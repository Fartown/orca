# 移动端上传任意文件 需求澄清

## 1. 背景与目标

移动端的「附件」只能传图片：终端输入栏点按打开相册、长按打开文件选择，但文件选择被限定为 `image/*`；聊天输入框只有相册。ZIP、PDF、日志、文本等文件在系统文件选择器里是灰的，无法选中。

根因是这条链路一开始就是按「粘贴一张图片」做的：选择器只放行图片，上传走主机的剪贴板图片接口（不带文件名和类型，上限约 18 MiB，主机先把整个文件放内存），主机一律存成 `orca-paste-…png`，再作为图片路径交给 agent。

目标：在手机上能把任意类型的文件传到**工作区所在的那台机器**上，并交给当前终端或 agent 使用；图片的现有体验保持不变。

## 2. 用户场景

- 用户在手机上看着一个 Claude Code / Codex 会话，想让 agent 分析一份 PDF 报告、一个日志压缩包或一份需求文档，直接从手机的「文件」App 选中发过去。
- 用户在手机上操作一个普通终端，想把手机里的一个文件放到工作区所在机器上，拿到路径后自己执行命令处理（如 `unzip`）。
- 工作区可能在运行 Orca 的电脑本机，也可能在电脑通过 SSH 连接的另一台机器上；文件都要落在工作区所在的机器上，agent 才读得到。

## 3. 范围

### In Scope

- 终端会话输入栏和聊天输入框的附件入口：点按弹出「照片 / 文件」选择。
- 文件选择放开为任意类型，保留原文件名。
- 文件写入工作区所在机器的临时目录，单文件上限 100 MiB，主机边收边写盘。
- 上传后把文件交给终端或 agent：终端插入路径，聊天输入框插入文件引用。
- 新旧版本混用时的兼容：新手机配旧电脑端、旧手机配新电脑端、网页版会话页配旧手机壳。
- 上传失败、中断、超限、主机未连接时的可感知提示与残留清理。

### Out of Scope

- 把文件长期放进工作区指定目录（移动端文件面板「上传到此目录」）。用户 2026-10-06 选择只做临时目录。
- 从主机下载文件到手机。
- 在手机上预览非图片文件内容。
- 改变图片的上传方式和交给 agent 的方式。
- 修复现有图片上传在「SSH 主机上的文件夹工作区」写错机器的问题（调研发现，属上游现有缺陷，单独跟进）。
- 桌面端行为。

### 来源与结论分类

- 原始事实：
  - 移动端文件选择限定为图片：`mobile/src/session/mobile-image-source-picker.ts` 的 `mediaTypes: ['images']` 与 `type: 'image/*'`（代码调研）。
  - 主机把移动端上传一律存成 `.png`：`src/main/window/clipboard-image-temp-file.ts`（代码调研）。
  - 网页版会话页的手机壳文件选择已是 `*/*`，但页面把选中项全部当图片上传，非图片会被存成 `.png`（代码调研，未上真机）。
  - 客户端与主机独立升级，新增字段不能被新一端强制要求；未知方法在旧主机上被拒绝（`AGENTS.md`、`docs/reference/remote-wire-compatibility.md`）。
- 用户已确认结论（2026-10-06）：
  - 存放位置：主机临时目录，保留原文件名，只用于交给 agent / 终端，不进工作区、不出现在 git status。
  - 入口：点按附件按钮弹出「照片 / 文件」，终端和聊天输入框一致。
  - 单文件上限提高到 100 MiB，主机边收边写盘。
  - 在当前目录切分支开发，不另开工作区。
- 推断（待确认）：
  - 终端一次附一个文件、聊天输入框可多选，沿用现有图片的行为。

## 5. 需求点

### REQ-001 附件入口支持选择任意类型文件

- 当前状态：已实现；云真机两轮（原生与网页版会话页）验证入口菜单、选择器、长按通过（TC-001、TC-002、TC-003）
- 描述：终端会话输入栏与聊天输入框的附件按钮，点按后弹出「照片 / 文件」两项；选「文件」打开系统文件选择器，任意类型均可选中。
- 业务规则：
  1. 「照片」保持现有相册行为与图片上传方式不变。
  2. 「文件」不限制类型；选中图片文件时仍按图片处理（与现在一致），非图片按文件处理。
  3. 上传进行中按钮不可再次触发，并显示发送中状态。
- 验收标准：
  1. 本地工作区与 SSH 工作区的会话中，终端输入栏和聊天输入框点按附件按钮都弹出「照片 / 文件」。
  2. 在 iOS「文件」与 Android 文件选择器中，ZIP、PDF、TXT 可被选中。
  3. 选「照片」的流程与改动前一致。

### REQ-002 文件写到工作区所在机器的临时目录并保留原文件名

- 当前状态：已实现；2026-10-06 真实 App 本机与 SSH 验证通过（TC-004、TC-005、TC-007、TC-016）
- 描述：上传的文件写到工作区所在机器上的 Orca 上传临时目录；文件名保留手机上的原名，同名文件互不覆盖。
- 业务规则：
  1. 「工作区所在机器」由电脑端按工作区判定，与该工作区终端的运行位置一致：本地工作区写在运行 Orca 的电脑上；SSH 工作区写在远程机器上；git worktree 与文件夹工作区都适用。
  2. 文件不写进工作区目录，不出现在 `git status`。SSH 主机上放在远端用户家目录的 Orca 目录里，不放共享的 `/tmp`，避免同一台服务器上的其他账号读到（D-006）。
  3. 原文件名中对目标机器不安全的字符被替换；无法取得原文件名时按类型生成一个带正确扩展名的名字。
  4. 远程机器未连接时上传直接失败并提示，不自动重连、不重试。
- 验收标准：
  1. 本地工作区：上传 `report.pdf` 后，电脑上出现内容逐字节一致的 `…/report.pdf`。
  2. SSH 工作区：上传后文件出现在远程机器的临时目录，电脑本机没有该文件。
  3. 连续上传两个同名文件，两者都存在、内容各自正确。
  4. 上传后工作区 `git status` 无变化。
  5. SSH 断开时上传，提示远程主机未连接，电脑端不发起重连。

### REQ-003 上传后把文件交给终端或 agent

- 当前状态：已实现；终端交付真实 App 本机与 SSH 通过（TC-008），Claude Code 读取 PDF 与聊天交付云真机通过（TC-009、TC-010）
- 描述：终端会话中，上传完成后在终端当前输入位置插入文件路径，不自动回车；聊天输入框中，插入加引号的绝对路径，用户可继续编辑后发送。
- 业务规则：
  1. 终端插入的路径按目标机器的 shell 规则转义，后跟一个空格，用户接着输入不会粘连。
  2. 聊天输入框中非图片文件不作为图片附件发送，只以加引号的路径文本出现在消息里；不用 `@路径`、也不以 `/` 开头，避免终端 agent 的文件提及或斜杠命令菜单吞掉发送（D-007）。
  3. 图片（无论来自「照片」还是「文件」）保持现有交给 agent 的方式。
- 验收标准：
  1. 在 Claude Code 终端会话上传 PDF 并发送「总结这个文件」，agent 读取到该文件。
  2. 在普通 shell 终端上传 ZIP，插入的路径可直接用于 `unzip -l`。
  3. 聊天输入框上传 TXT，输入框出现该文件的路径，发送后消息直接提交，agent 能读到文件内容。

### REQ-004 单文件上限 100 MiB，过程可感知

- 当前状态：已实现；真实 App 验证 90 MiB、超限、取消清理（TC-011、TC-012、TC-013），网页版会话页 60 MiB 与原名云真机通过（TC-018）
- 描述：单个文件最大 100 MiB；超过上限在上传前就提示；上传中显示发送状态；失败给出可读原因。
- 业务规则：
  1. 电脑端边收边写盘，不把整个文件放进内存。
  2. 手机端按块读取文件，不把整个文件读进内存。
  3. 失败或中断（用户离开页面、连接断开、主机拒绝）时，主机上已写入的部分文件被删除。
- 验收标准：
  1. 上传约 90 MiB 文件成功，内容一致。
  2. 选择大于 100 MiB 的文件，立即提示超出上限，不发起上传。
  3. 上传中途断网，提示失败；主机上不残留未完成的文件。

### REQ-005 新旧版本混用时行为明确

- 当前状态：已实现，自动化覆盖（TC-014、TC-015）
- 描述：手机 App、网页版会话页与电脑端独立升级，任意组合下都不能把非图片当图片存，也不能静默失败。
- 业务规则：
  1. 新手机配不支持文件上传的旧电脑端：图片照旧；选非图片文件时提示「电脑端 Orca 需要更新」。
  2. 旧手机配新电脑端：行为与改动前一致。
  3. 网页版会话页配不支持大文件的旧手机壳：超过手机壳能力的文件提示更新 App，其余照常。
- 验收标准：
  1. 用不含本功能的电脑端版本配新手机，上传 PDF 得到更新提示，主机上不出现 `.png` 文件。
  2. 用不含本功能的手机 App 配新电脑端，图片上传正常。

### REQ-006 上传的临时文件会被清理

- 当前状态：已实现；取消清理真实 App 验证通过（TC-013），保留期清扫自动化覆盖（TC-017）；保留期 7 天已确认
- 描述：失败或中断的上传残留立即清理；成功上传的文件在保留期过后由 Orca 自动清理，本地与远程机器都适用。
- 业务规则：
  1. 保留期内文件可被 agent 反复读取。
  2. 清理只针对 Orca 自己创建的上传目录，不碰其他文件。
  3. 保留期 7 天（2026-10-06 用户确认）。
- 验收标准：
  1. 超过保留期的上传目录在下一次上传时被清理。
  2. 清理不影响保留期内的文件与非 Orca 文件。

## 7. 业务规则

- 文件归属：上传文件、上传临时目录、清理动作都在**工作区所在的机器**上；手机只负责选择和发送，电脑端负责判定目标机器并转发。
- 远程主机：只在该主机处于已连接状态时写入；不自动重连、不重试、不轮询。
- 兼容：新能力只在电脑端明确支持时启用；旧电脑端的拒绝要被识别成「需要更新」，不能落回图片通道。
