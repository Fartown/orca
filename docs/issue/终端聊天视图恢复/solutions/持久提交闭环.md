# 终端 Chat 持久提交方案

之前由 renderer 分开调度 clear/body/Enter，内存 pending 与持久草稿之间没有可靠交接。现在先 prepare：桌面 main 用已有 durable-file-write 保存原文、附件与固定身份，fsync 后才允许清除未变的草稿；dispatch 先持久标记 attempted，再调用执行端现有 durable terminal.send。

执行端沿原队列逐段结算清理、图片、正文、一次 Enter；每段核对原 incarnation 与 provider session。完整清理复用 AGENT_TUI_CLEAR_INPUT_MAX 并检查当前主机 draft。Enter 前读取执行主机上当前 provider transcript 的文件字节末尾 afterByteOffset，添加 optional receipt 内容，不增加 stream opcode。renderer 只提交真实 user 行的 id、文件字节顺序、正文与图片数量；main 在串行持久更新内读取最新 outbox，按 session、文件字节边界及正文/精确图片数统一分配。重叠同文使用完整一对一匹配；无法证明所有争用关系时保留未知，不复用一条用户行。confirmed messageId 留最小 tombstone，直到没有未确认请求能争用才回收。时间戳仅诊断，不依赖客户端/主机时钟同步。receipt 同时保存执行端 transcript 路径、文件身份及原 byte cursor 的边界 fingerprint；main 删除前通过原 requestShow 的可选核验参数让执行主机读取同一 caller 的原 ledger proof，验证文件仍连续。文件替换、截断和边界重写时保留原文。

| 资源                                                  | 所有机器                                 |
| ----------------------------------------------------- | ---------------------------------------- |
| native-chat-outbox/submissions.json                   | 桌面客户端 userData，0600；目录 0700     |
| mutation ledger、原 PTY、Codex HOME、图片、transcript | 执行主机，本地或 managed/paired SSH host |
| 模型 fixture 127.0.0.1 与配置                         | Codex 所在执行主机；只用于隔离验收       |
| 共享连接 verdict、配对身份、客户端 SSH tunnel         | 客户端连接层；feature 不自行探活或重连   |

同一个请求经过 dispatching 后永不自动再次发送；恢复只读 requestShow。初始主机 runtime incarnation fence 保持；重启后的只读查询核对原 installationId 和 pairingRevision，读取新进程的旧 ledger。身份不明则保持未确认。

terminal.chat-composer.v1 仅在 durable SQLite 可用时发布。能力不足、legacy relay、无可验证 provider session、不可读的清理/转录边界都保留输入并拒绝/未确认；不得降级为假成功或给原会话新建进程。回退客户端不会改远端已存数据，旧客户端忽略可选 receipt 字段；没有新 stream opcode。此变更不重启当前用户 App 或主机服务。

当前 provider 身份复用 exact worker selector 和 observation incarnation fence；如果首个真实 hook 早于 PTY 注册，必须用该 hook 原始 launchToken 的 SHA256 匹配当前 live dispatch authority，且 pane/incarnation 一致。恢复快照不当作新的身份观察，不能把旧 row 回填给新进程。
