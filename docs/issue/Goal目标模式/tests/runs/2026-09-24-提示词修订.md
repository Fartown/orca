## 过程中的失败与处理

- 第一次运行作废（脚本）：Orca 终端里的 HOME 是真实主目录，Claude 包装脚本拒绝运行；等待就绪的判断把命令回显当成了 agent 的回复。改为显式设 HOME，并读 agent 自己的会话记录判断就绪。
- 真机发现产品问题：Claude 一轮结束后在输入框显示暗色建议「继续第二步」，终端读取的 `draft` 非空而屏幕上输入框为空，驱动连续 3 次以「输入框里有草稿」为由不发续跑。上游有意把建议算进草稿（`terminal-composer-draft.test.ts` 有断言）。按用户裁决去掉草稿检查（TC-381）；消息改按 agent 提示词投递，整段一次粘贴，上游注释写明分块写入时 Claude 的输入框会丢开头。
- 摘要判错一次：codex 口令用例的首轮消息，记录里 555 字、发出的是 495 字、开头一致，被判为「没有完整送达」。那次的会话记录没有留档，多出的是什么、原文是否完整在内都未能查明，后续运行未再出现。核对规则同时改为：记录里包含发出的全文就算完整送达，多出的字数照实标给守卫。
