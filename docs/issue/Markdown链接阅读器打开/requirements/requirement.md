# Markdown链接阅读器打开

## 背景与范围

事实来源：[Issue #154](https://github.com/Fartown/orca/issues/154)，以及用户 2026-11-24 的选择：「md 链接带行号时仍用阅读器打开，只是不跳行」。

智能体引用文件时几乎都带行号（`docs/guide.md:12`、`docs/guide.md#L12`）。上游的规则是：点开带行号的 Markdown 链接时，先强制把标签切到源码，再跳到那一行，因为阅读模式（Rich）没有按行定位的能力。结果是点开的 md 基本都是源码。

本需求只改「点击链接」这一类入口：终端、聊天视图、机器人条目，以及 Markdown 文档里的链接，电脑端和手机端都改。以下入口保持原样：快速打开里手动输入的 `:行号`、检查注解、Notes、手机驱动的定位请求，这些都是明确要求跳行的操作。打开位置（在来源旁边分屏，上游 #32907）不在本需求范围内。

## 需求与验收

### REQ-1541 带行号的链接不改变 Markdown 标签的模式

当前状态：已实现。

本地：点击带行号的 Markdown 文件链接时，不把标签切到源码。新打开的标签按用户设置的默认模式显示（默认是阅读模式）；已打开的标签保持当前模式。SSH：文件在 SSH 主机上时，规则相同；模式只是客户端渲染状态，不读写主机上的任何东西。

### REQ-1542 只有源码模式才跳行

当前状态：已实现。

本地：标签当前就是源码模式（之前手动切过，或者用户把默认模式设成了源码）时，照旧跳到链接指定的那一行。阅读模式下不跳行，也不留下待执行的跳行。SSH：与本地相同，跳行只是客户端编辑器的动作。

### REQ-1543 明确的跳行入口不变

当前状态：已实现。

快速打开输入 `:行号`、检查注解、Notes 和手机驱动的定位请求，仍然切到源码并跳行。本地和 SSH 相同。

### REQ-1544 手机端预览先显示阅读模式

当前状态：已实现。

手机端从带行号的链接打开 Markdown 文件时，先显示阅读模式。用户切到源码时，仍然定位到该行。连接本机 Orca 和连接 SSH 工作区的 Orca 行为相同；文件内容仍由原执行主机提供。

## 机器归属

- 阅读模式和源码模式是客户端渲染状态，存在客户端的 store 里。默认模式是客户端的 `markdownDefaultViewMode` 设置。
- 文件、文件读取和 stat 都在原执行主机上进行（本地文件在本机，SSH 文件在 SSH 主机），沿用现有的 RPC。
- 没有新增配置、服务、端口、环境变量或定时器。
