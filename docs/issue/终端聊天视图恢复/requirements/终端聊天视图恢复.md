# 终端聊天视图恢复

用户要求修好 Fartown 安装包中无法发现或使用 Chat View 的问题，并完成合入与安装验证。

### REQ-1801 已有终端可双向切换视图

优先级：P0。当前状态：实现中。

支持原生聊天视图的终端标签，右键菜单提供「切到聊天视图 / Switch to Chat View」（与终端头部、窗格右键同名，见 [终端头部切到聊天视图 REQ-2](../../终端头部切到聊天视图/requirements/requirement.md)；上游的 Continue in Chat UI 在中文里已改指「在新聊天中接管」）；聊天视图提供 Continue with Terminal Agent。两者调用已有同标签切换入口，保留终端 ID、进程和 provider session。普通 shell、不支持的 agent、缺少切换回调的标签不显示此项。切换不创建标签、不启动或恢复 provider 会话、不发送用户消息。

### REQ-1802 本地和 SSH 行为一致

优先级：P0。当前状态：实现中。

本地文件夹和 Git 工作树、SSH 执行主机均沿用已有能力判断、会话路由和 transcript 读取。执行主机拥有 transcript 与终端进程，客户端仅切换展示；不增加 RPC、端口、设置、文件副本或重试。旧主机维持其已有能力判断。快捷键标签复用跨平台绑定，移动端的原生聊天入口保持已有行为。

### REQ-1803 历史会话可读且只读校验

优先级：P0。当前状态：实现中。

对用户指定旧标签核对 Orca 的 provider session 元数据；如缺失，只用已核实的会话标识及已有绑定入口修复元数据。读取并显示已有 transcript，前后校验文件未改动；不 resume 旧 provider、不发送消息、不关闭原终端。此项是既有配置的修复验收，优先复用现有接口。

### REQ-1804 已有终端聊天视图允许原恢复层自愈

优先级：P0。当前状态：已实现。关联：[Issue #112](https://github.com/Fartown/orca/issues/112)。

- 本地场景：已有本地文件夹或 Git 工作树的终端切到聊天后，若原恢复层收到有效的连接/渲染故障信号，当前仍可见、仍由该终端支撑的聊天窗格可重建视图并重新附着原终端，无须先切回终端展示。不把 `viewMode: chat` 等同于 provider 所有权已交接。
- SSH 场景：工作区、transcript 和终端进程归 SSH 执行主机，客户端只决定视图是否允许恢复。沿用主机原有绑定与连接层结论，不以客户端失联推断主机进程退出；恢复不新增独立连接、轮询、重试定时器、RPC 或流帧。本地与 SSH 均不因视图恢复发送用户消息或启动第二个 provider。
- 保护：只有当前已注册的具体终端实例能放行；隐藏、已卸载、跨 tab、无真实终端聊天覆盖层以及已交接给独立会话的旧实例仍拒绝。等待本地 liveness 期间如果视图或实例变化，提交恢复前再次确认。原代际、冷却、恢复预算与已结算失败规则保持生效。
- 移动端与旧主机：不改变主机执行和移动端会话所有权，不依赖新增主机能力；变化仅为桌面客户端对自身终端视图恢复的准入。

### REQ-1805 终端聊天消息必须反映实际投递结果

优先级：P0。当前状态：已实现。关联：[Issue #119](https://github.com/Fartown/orca/issues/119)。

本地和 SSH/配对的 Codex 普通消息均沿用原 verified PTY 写入并请求已有严格写入确认，不允许 false 回退成无确认发送：正文确认前不调度 Enter；明确拒绝时保留原文字并显示未发送，回执丢失时按原 pending hold 显示投递未确认，不能自动重发或把后一次不同消息算作前一次成功。真实 transcript 对账到达后撤下对应 pending 气泡。终端、provider 和 transcript 归执行主机；客户端只持有气泡与发送回执，不增加主机读、重连器、定时轮询或协议。文件夹与 Git 工作区使用相同 pane/PTY 身份；移动端保留自身已有确认发送路径，独立 native chat 和命令发送不改。

### REQ-1806 恢复后 Activity 提醒与真实内容一致

优先级：P0。当前状态：实现中。关联：[Issue #118](https://github.com/Fartown/orca/issues/118)。

- 恢复未确认的 waiting/blocked 行没有新的主机证据时，不作为当前等待输入、不生成新的当前事件或未读计数；已有真实历史事件沿原时间戳和已读记录保留。新的有效主机证据到达后沿现有新鲜度规则恢复当前状态。
- 点击该行时，如果同一已存在终端标签仍处于聊天视图、恢复未确认、缺少已核实 provider 绑定且目标 pane 仍有原 PTY，则显示该标签原终端窗格。paired split 中 tab 顶层 PTY 可为 null，按目标 leaf 的绑定判断，不借用 sibling 的 PTY。保留 tab、pane、PTY，不启动或推断 provider 会话，不自动重连。已绑定且有新鲜证据的聊天行沿用原行为。
- 本地、SSH 执行端与 paired runtime 均由执行主机拥有 PTY、transcript 和会话证据，客户端只根据已同步的状态决定展示；不新增 RPC、端口、环境变量、轮询或重试。失联不等于进程结束；该行的执行状态只使用 live / unverifiable / exited 判定。移动端不改变。
