### D-015 调度会话即总管：分配、管理、感知

- 日期：2026-11-05
- 背景：
  - 用户要求在本 PR 上先做一个用于分配、管理任务与会话、能感知的总管（super agent），想好任务、会话怎么给它提供接口，任务和会话复用已有的。
  - super agent 功能的设计已有，在分支 `claude/gifted-dijkstra-9oipaq` 的 `docs/issue/超级智能体/`。其中「总管第一版接口方案」提议把本方案的调度会话升格为总管，用户选择直接并入本 PR。
  - 核实了三处代码事实：
    - 调度会话按用户设置可能走结构化聊天（`nativeChatPreferenceFor`），而 Claude 的结构化聊天经 Claude Agent SDK，不能用 claude.ai 订阅；
    - `NativeChatView` 接受终端标签；
    - `ORCA_AGENT_SESSION_ID` 只注入结构化会话。
- 最终决定：用户同意并入本 PR；方案按 super agent 设计的推荐项写入。各项细节在用户审阅本 PR 时确认。
  - 调度会话即总管，常驻、唯一；Claude 以终端启动；对话按面板映射。
  - 总管的写入一律走提案，提案项扩为 `start` / `subtask` / `append` / `stop` / `link` / `record`；`stop` 永远要确认。
  - 感知：盯着的任务、收件箱、空闲时唤醒。语义照编排的指针投递，但不依赖编排。
  - 「只问」遇到要读代码的问题，提只读调查任务。
  - 新增 CLI：`task needs-you`、`task inbox`、`task watch/unwatch`、`task list --all-hosts`、`task show --events`。
- 原因：
  - 本方案让任务成为记录：任务就是总管的账本，提案就是审批，回写进展就是回执；复用这些，总管只需补收件箱与唤醒。
  - 唤醒不另起编排 Run，因为本工作流不经编排。
- 影响范围：REQ-030 增补、新增 REQ-031；产品方案 §6.4、§16；技术方案 M3、M13、§5.4、§5.5、§6.3（验证 7～11）、§8；切片 3c。

#### 备选项

- 调度会话升格为总管，建在本方案的任务记录与提案上（采纳并入）
- super agent 另起内核与事项表，与本方案并行

### D-014 速览就是对话的小边框模式；不要「完成标准」

- 日期：2026-11-02
- 背景：用户看了原型第三轮后问两件事：速览为什么不能回答，不就是对话的一个小边框模式吗；完成标准这东西能固化吗，每个任务都好定义吗。
  - 速览不能回答，是沿用了 D-007 的旧规则：REQ-015 的回复框是一条单独的「发一句话」通道，终端里的提问多是菜单，发文字会发错。但速览已经改成把真实终端或聊天挂进来，它就是会话本身，限制没有必要。
  - 完成标准：任务分三类，只有可验证的交付能事先定标准，而且开工时往往定不准；探索类只能是「给出结论」；零碎事写标准比做还费劲。先提了「可选、智能体提议、项目模板、验收不依赖标准」的折中，用户回复「我觉得不如没有」。
- 最终决定：用户回复「都改」，随后改口不要完成标准。
  - 速览就是对话的小边框模式：一个浮层两档宽度（速览约 420px、加宽约主区 2/3）加全屏，窄态也完整可操作；浮层里没有单独的回复框，不受「只有做完一轮能回复」的限制；首页「需要你」行的「回复」就是打开速览并聚焦输入；手机抽屉里挂真实会话视图。
  - 不要「完成标准」：REQ-021 取消（勾选、证据、智能体提议、项目模板、CLI、与 Goal 打通都不做）；REQ-004 的字段去掉，升级时已有条目追加到描述末尾；概览、新建任务、待验收卡里都没有它；验收看结果：合入位置、改动和 PR、智能体的自检结论、在哪验收。
- 原因：浮层挂的是会话本身，输入走会话自己的通道，再限制就是人为设门槛；完成标准对大多数任务定不出来，强求就是填表。
- 影响范围：REQ-004、REQ-009、REQ-010、REQ-015、REQ-019、REQ-021、REQ-024、REQ-026、REQ-027、REQ-028；方案 §4、§5.2、§5.3、§5.4、§8、§9、§13、§15；切片 3c、3d；原型第四轮（修改说明 BRIEF-4 在本机，不进仓库；第 2 节作废，改为整体去掉完成标准）。

#### 备选项

- 完成标准可选、智能体提议、项目模板、验收不依赖标准（折中，用户没要）
- 不要完成标准（采纳）
- 速览只读、加宽才能操作（第三轮原型）
- 速览窄态也完整可操作（采纳）

### D-013 看会话改成右侧浮层三级，概览页减信息

- 日期：2026-11-02
- 背景：用户看了原型第二轮的 ORC-38 概览后提出两点：「打开完整会话」能不能在右侧弹浮层，点全屏才开独立标签；这页信息太多，要说清每块从哪来、有什么意义、哪些有价值。逐块核对：工作区在头部和右栏重复；同一个会话在标签、侧栏树、等你卡、会话列表出现四次；「验收」按钮在进行中也显示；动态里是系统流水；右栏属性很少看；原型里混进一批给评审看的注释（含需求编号）。
- 最终决定：用户回复「改」。
  - 看会话是同一个右侧浮层的三级：速览（窄，只看最近内容，回复只对做完一轮）→ 展开（宽，完整可操作）→ 全屏（切到会话标签，标签顶部可收回侧边）。同一个终端或聊天实例只换宽度，不重新挂载。手机仍是两级。
  - 概览只剩四块：头部（标题、属性 chips、工作区一行、一个按状态变的主按钮、「…」菜单）；「现在」卡（验收条、在等你什么、最新进展、会话行，空的部分不显示）；描述、完成标准、子任务（有才显示）；动态（系统事件折叠成「系统记录 N」）。右栏取消；界面里不出现需求编号和机制说明。
- 原因：任务是主体，会话浮在它上面；概览要先回答「现在要我干什么、做到哪了、标准是什么、怎么进去」，其余信息要么重复、要么很少看。
- 影响范围：REQ-005、REQ-012、REQ-024、REQ-026、REQ-028；方案 §5.3、§5.4、§5.6、§15；原型第三轮（修改说明 BRIEF-3 在本机，不进仓库）。

#### 备选项

- 速览抽屉加独立标签两级（第二轮原型）
- 同一浮层三级，完整会话也浮在任务上（采纳）
