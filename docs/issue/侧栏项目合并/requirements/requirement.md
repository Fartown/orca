# 侧栏同名归类：需求与边界

**在原侧栏分组结果上，把显示名称相同的项目放到一起。原来的同仓库分组继续生效；只改归类，按钮、菜单、设置入口、操作回调及业务归属保持原样。**

## 1. 用户已确认的要求

来源为本次对话及“项目设置 → 身份 → 显示名称”截图：

- “同 repo 合并”：保留原本已有的仓库分组，不重写身份识别，也不取消原来需要分开的例外。
- “重名的话我希望合并，不希望合并我改名字就行了”：使用已有显示名称，不维护另一份成员名单。
- “原本逻辑不要改动太多”“不要改变了其他归属逻辑”：文件、工作目录、项目/工作区 ID、终端与业务范围保持原样。
- “不就改下归类逻辑吗”“为什么要改 ui”：不新增目录选择器，不改按钮或菜单层级，不增加合并设置页。

Agent 之前增加的原生项目绑定、成员配置、目录选择交互和折叠偏好继承，均不作为本期需求。当前结论见 [D-007](../journal.md#d-007-仅修改侧栏归类撤回所有操作-ui-改动)。

## 2. 用户看到的变化

目录是某台电脑上实际存文件的文件夹。侧栏项目头是界面对工作区的归类，本次只改变这一层。

此前读到的三个目录名称分别为本机 `workspace`、mini `workspace`、dbox `workspaces`。它们是历史配置读回，不代表本轮重新读取了在线状态。新规则下前两个归在同一头下；将 dbox 的已有显示名称也改成 `workspace`，它就加入。改成 `workspace-dbox` 后，它离开同名归类。三个实际路径、原工作区和会话继续保留。

Movo 等原本按同仓库合在一起的项目，继续按原逻辑显示。改名只解除名称带来的归类，不用来拆散原仓库关系。

## 3. 范围

| 本期处理                               | 必须保持原样                                       |
| -------------------------------------- | -------------------------------------------------- |
| 按已有显示名称组合原侧栏区块           | 仓库身份推导、原生 Project/setup 与工作区归属      |
| 桌面和手机使用同一显示归类结果         | 文件、路径、执行主机、终端、会话及原业务 ID        |
| 渲染、折叠、导航和定位使用一致的显示键 | 原按钮、菜单、弹窗、设置页、新建/移除流程及回调    |
| 原仓库分组和已有显示容器边界继续生效   | 手工 ProjectGroup、按主机查看、归档/置顶及过滤范围 |

不新增配置字段、分组数据库、后台服务、网络请求、RPC 协议、成员管理、折叠状态迁移或批量操作。不扩展任务、AI Vault、快捷命令、自动化、Git 或运行偏好的归属范围。
