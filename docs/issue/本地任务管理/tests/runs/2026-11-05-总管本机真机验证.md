# 总管（调度会话）本机真机验证（2026-11-05）

- 对应：需求 REQ-022、REQ-030、REQ-031；技术方案 [§6.3](../../solutions/任务为主的工作流技术方案.md) 开工前验证 7～11。
- 构建：本分支的 e2e 构建（`electron-vite build --mode e2e`），CLI 用 `tsc` 输出到 `out/cli`。
- 方式：Playwright 驱动隐藏窗口的隔离实例（Xvfb，独立 userData）。智能体是 `agentCmdOverrides` 指向的假 `claude`（Node 脚本），它记下参数、工作目录、`ORCA_*` 环境变量和收到的每一行输入。总管的命令用它窗格的 `ORCA_PANE_KEY` 调用编译好的 CLI；唤醒指针到达后，假智能体在自己的终端里真的执行一次 `orca task inbox --json`。代理状态通过 Orca 的 hook 端口发 Claude 的 `UserPromptSubmit` 和 `Stop`。用户操作都走界面。
- 证据（本机目录，不进仓库）：`.docs/本地任务管理-ui-validation/2026-11-05/`。`README.md` 是逐条结果，`evidence/` 是截图和运行记录，`scripts/dispatcher.spec.ts` 是驱动脚本。

## 结果

| 项                                   | 结论           | 说明                                                                                                   |
| ------------------------------------ | -------------- | ------------------------------------------------------------------------------------------------------ |
| 打开总管                             | 通过           | 在浮动工作区开出终端，`ORCA_WORKTREE_ID` 是浮动工作区，并带 `ORCA_PANE_KEY`；登记成功                  |
| 提交提案                             | 通过           | `orca task propose --body-file` 成功，提案卡出现在「需要你」视图                                       |
| 确认并执行                           | 通过           | 建出 SHOP-1、挂上 master 工作区、在后台开会话；提示「Done 1 of 1」，你留在原视图                       |
| 第一句指令带任务说明                 | 通过           | 带编号、描述，以及 `orca task show`、`orca task guide` 的说明                                          |
| 收件箱                               | 通过           | 写明「item 1 done (started SHOP-1)」，并列出状态变化和新会话                                           |
| 回写进展                             | 通过           | `orca task progress --needs-you` 成功；收件箱、列表行标记、详情顶部的进展卡都显示出来                  |
| 唤醒                                 | 通过           | 总管做完一轮后，指针以粘贴加回车写进它的终端；同一份没处理的收件箱不再唤醒                             |
| 唤醒开关                             | 通过           | 关闭期间不唤醒；重新打开后补发一次                                                                     |
| 关掉总管再打开                       | 通过           | 沿用原对话，盯着的任务仍在                                                                             |
| 验证 7（终端作为总管）               | 部分           | 用假智能体验证终端启动和登记；真的 Claude 在隔离环境里没有登录，未验证；对话页按方案的退路直接显示终端 |
| 验证 8（浮动工作区里调 `orca task`） | 通过（本机库） | Orca 把自己的 CLI 目录放在 PATH 最前，不用开启 orchestration；`--host` 读写 orcad 主机的库没做         |
| 验证 9（写指针与打字冲突）           | 部分           | 写指针通过；光标在总管终端里时不写，这一条只有单元测试覆盖，因为隐藏窗口拿不到系统焦点                 |
| 验证 10（跨库收件箱）                | 未做           | 按方案的退路：收件箱只覆盖桌面库                                                                       |
| 验证 11（未知提案项整份拒绝）        | 代码确认       | 参数校验用按 `kind` 区分的联合类型，未知 `kind` 整份拒绝；未在真机上测                                 |
| SSH 场景                             | 未做           | 本容器原本没有 sshd；装上后，添加专用密钥和启动 root sshd 被会话的权限检查拦下                         |
