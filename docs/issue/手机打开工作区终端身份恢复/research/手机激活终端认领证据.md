## 当前技术链路

1. 手机 `worktree.activate` 在 `src/main/runtime/workspaces/workspace-activation.ts` 通知桌面后台 wake；`src/renderer/src/lib/wake-sleeping-agents-in-background.ts` 进入 PTY gate，不导航。
2. `src/main/runtime/pty-recorded-surface-topology.ts` 可将窗口图丢失 pane claim 的仍 live PTY 列为 orphaned。`src/renderer/src/lib/worktree-agent-live-surface-adoption.ts` 的 `bindToRecordedSurface` 要求 renderer 已有旧 tab；缺 tab 时 fallback 以随机 tabId `createTab(initialPtyId)`。
3. 已挂载窗格的 deferred 连接在 `src/renderer/src/components/terminal-pane/pty-connection/deferred-session-reattach-choice.ts`、`deferred-session-reattach-connect.ts` 发普通数字 `sessionId`。`src/main/providers/local-pty-spawn.ts` 过滤此数字后会新建 shell。
4. `src/main/runtime/runtime-terminal-orphan-adoption-plan.ts` 有 exact-persisted replay；现有顺序使它在 revision/tombstone 检查之前返回。`src/main/runtime/terminal-surface-close.ts`、`src/shared/closed-terminal-tab-tombstones.ts` 有关闭记录。主进程已有 stable pane 严格认领，见[复核审计](../../../../.docs/mobile-empty-terminals-investigation/2026-10-24/evidence/repair-proposal-audit.md)。
5. 窗口会话在 main 保存并维护 hostPrivate 的 `terminalTopologyRevisionByRepoId`；本机/SSH 的 set/patch 可重基 terminal membership，同 ID 的普通窗口保存通常可接受，renderer 单方面写新成员会被裁掉直到 host binding 可证实。关闭路径有 durable retirement。此为[收敛静态审计](../../../../.docs/mobile-terminal-surface-recovery-ui-validation/2026-10-24/evidence/convergence-audit.md)所证源码行为；durable 认领提交与 renderer 投影之间、unified-only patch，以及恢复后新建/关闭/split 和 patch/set/unload/重启尚未运行验证（V12）。
6. [Claude 第二轮只读评审](../../../../.docs/mobile-terminal-surface-recovery-ui-validation/2026-10-24/evidence/claude-review-2.md)确认 `deferred-session-reattach-connect.ts` 的 catch 除 owner unverified/changed 外会清绑定并 `startFreshInstead()`；`reattach-result-handler.ts` 对无 PTY id 会 cold resume，对成功接回但无 snapshot/replay/coldRestore 且有睡眠退役证据也可能断开原 PTY 再 resume。main 的 `attemptStablePaneAttach` 只将 SessionNotFound 作为已观察退出，其他错误可能原样传播。故成功路径的零新 shell 对照不能证明错误分支安全。v3 将两处 renderer 接缝列为确定修改，并提出单次内存标记、人工 retry 严格分类和 live 无回放保留原 PID；这些仍是待实现方案，不是修复结果。

[Claude 第三轮定向复核](../../../../.docs/mobile-terminal-surface-recovery-ui-validation/2026-10-24/evidence/claude-review-3.md)对已送审 v3 给出 **APPROVE，仅设计层面**：P0=0、P1=0、P2=1。非阻断 P2-7 指出首次接回中 remount/新 generation 可能丢掉严格分类；主方案随后补同 executionHost/worktree/tab/leaf/ptyId/incarnation 的 attempt 转交，旧 transport 回调不得清继任者。评审只复核第二轮 P1-6/P2-5/P2-6 和 v2→v3 差异，未运行测试，也未复核补写的 P2-7 实现效果；V01～V12 与全部产品行为仍待实施后验证。

## 上游 `79b87c4f7c` 三组本机对照

[原调查 README 的上游对照实测](../../../../.docs/mobile-empty-terminals-investigation/2026-10-24/README.md)及其 `evidence/upstream-79b87c4f7c/` 记录同一已访问 folder workspace、进程内 PTY、手机打开三次的三组结果：发布构建关闭 `ORCA_LAYOUT_OWNER` 时新增 3 个空 shell，原 PTY 仍为桌面不可见孤儿；打开暗开关的构建新增 0 个，后台创建后原 tab 立即出现在桌面标签栏且未成孤儿；发布构建叠加 `stopgap-experiment.patch` 单文件补丁新增 0 个，恢复原 tab/leaf，`pty:spawn` 对原 sessionId 返回 `isReattach:true`。暗开关方案的即时桌面呈现行为与现行 REQ-002 的后台不即时 reveal 规则不一致，不能直接视为需求验收。单文件补丁只覆盖宿主有 recorded pane、本地缺 tab、无关闭记录的兜底；无记录 orphan、关闭竞态等边界未由这组三次激活证明。

调查的 SSH 路由结论来自代码核查：现行 fork/上游 SSH workspace 由远端 orcad 承载并带 `runtimeEnvironmentId`，`resolveActivationPtyListScope` 返回空，手机 wake 不进入本次认领入口；旧 relay 遗留会话可能仍走 `ssh:` 路由。该路径**未在 SSH 实测**。本轮仅阅读既有证据，没有重新运行上述三组对照，也没有执行 SSH、真机或产品测试；旧方案的 SSH 覆盖假设须在新稿中重新核对。

## 单文件止血方向的调用方反证（只读）

- 上游 `stopgap-experiment.patch` 仅在 `owner.recorded`、本地缺原 tab、renderer 关闭记录未命中时尝试 `bindLivePtyToExactSurface`；失败后仍落入原随机 `createTab(initialPtyId)`。三次零新增 shell 只覆盖命中的本机路径，不能证明无 recorded、关闭或冲突时安全。拟议的 Fork 策略可收缩为 owned 路径中的原身份止血、目标一个上游接缝；“单文件方向”不等于现在已证明全部产品改动只需一个文件。
- 在 `src/renderer/src/lib/worktree-agent-live-surface-adoption.ts:181-255`，即使未来把无 recorded、关闭或冲突的 PTY 列入 `declinedPtyIds` 并令 `surfaced=false`，也只阻止该函数自身 mint。`src/renderer/src/lib/worktree-agent-activation-gate.ts:211-262` 仅对 declined 打警告；若没有其他 surfaced、resume、structured 或 blocked 结果，返回 `empty`。现有 `worktree-agent-activation-gate.test.ts:538-563` 已断言宿主不可读或 owner 冲突时 gate 返回 `empty`。
- 显式激活通过 `src/renderer/src/lib/worktree-activation.ts:125-149,240-267` 与 `worktree-activation-gated-empty-reseed.ts:24-56` 消费 `empty`，再经 `worktree-initial-terminal-seeding.ts:44-70,205-216,271-284` 可能 `createTab(pendingActivationSpawn)`；启动 watcher 也在 `src/renderer/src/components/use-terminal-watcher-effects.ts:220-262` 的 `empty` 分支创建初始 tab。是否实际 spawn 仍受当时 active workspace、host authority、可渲染标签及其他 guard 影响，不能把每次 decline 都说成必然新增进程。
- 手机后台 wake 在 `src/renderer/src/lib/wake-sleeping-agents-in-background.ts:215-219` 以 fire-and-forget 调 gate，本调用方不消费 `empty` 来 seed；但同文件 `:171-203` 在 gate 前就派发 wake 与背景 mount，gate 的 `:233-262` 在条件成立时也可调用 resume。因此 adoption 的 decline 不能单独保证后台路径无第二 writer。
- 关闭记录的 renderer 镜像不是原子权威判断。`bindLivePtyToExactSurface` 可先调用 `createTab`（`worktree-agent-live-surface-adoption.ts:41-79`），该调用即时写 `tabsByWorktree`、`unifiedTabsByWorktree` 和 group（`src/renderer/src/store/terminals/terminal-tab-creation.ts:229-271`）；main 的 `assertPaneStillExists` / `ptyBindingIsRefused` 在后续 stable attach、spawn 或持久化阶段核对（`src/main/ipc/pty/pane/pane-spawn-operation.ts:41-64`、`src/main/persistence/loading-store/pty-binding-refusals.ts:66-109`、`src/main/ipc/pty/ipc/spawn-execute.ts:40-67`）。所以即使原 pane 被 main 拒绝，也不能据此保证 UI 标签不曾短暂复活；若 gate 的 `empty` 分支另建随机 tab，原 tab 的 tombstone 也不一定能阻止这个新身份的 spawn。

上述调用方反证表明，“统一 decline”也不能单独保证整个激活链不 seed；它当时仍是待验设计建议，不是通过的修复。新证据已推翻非目标统一 decline，见下一节。

## Claude 代码 review 的 daemon 反例与剩余风险

[真实代码 review](../../../../.docs/mobile-terminal-surface-recovery-ui-validation/2026-10-24/evidence/claude-code-review.md)结论 REQUEST_CHANGES（0 P0、1 P1、3 P2）。评审人在上游 `79b87c4f7c` 发布版用 daemon PTY 实测旧随机标签 fallback：带原 sessionId 的 `pty:spawn` 返回 `isReattach:true`，新 PTY 数为 0，原输出标记可见。因此原先“无 recorded/冲突等全部 decline”会使 daemon 的 live 终端不再可见；这一派生建议应撤回。该实验只证明**旧上游 daemon 路径**的行为，尚不是当前修订代码的端到端验收。

评审要求只新增“宿主有 recorded pane、桌面完全缺原 tab”时按原身份恢复，`bindToRecordedSurface` 原路径先行；无 recorded、原 leaf 不在布局、被占用、跨工作区、精确恢复失败仍保留上游随机 fallback。对本机纯数字 PTY，这些非目标情形仍可能留下旧空 shell，不能把当前止血称为全局不增生。`worktree-agent-activation-gate.test.ts` 原有三种随机 mint 契约也须保留，仅缺原 tab 的用例改为精确身份预期。

P2 风险：别的客户端关闭桌面从未显示的 tab 时，renderer 关闭镜像可能晚于 main 关闭提交；策略可能先造出一个连不上的“幽灵”标签，需验证最终 main 成员关系与 tombstone，不能仅看新进程数。另 `adoptHostOwnedSurface` 的 `materializedTabIds` 只覆盖同一轮 sweep，新旧两轮分别发现同 tab 的两个 leaf 时，后轮可能走旧随机 fallback；当前修复不声称跨轮 split 完整恢复。本轮仅整理评审与源码，不重跑 daemon、本机或 SSH 实验。

新稿至少须验证上述 daemon fallback、other-client close-never-shown、跨轮多 leaf、各调用方最终 pane/spawn，以及完整 SSH runtime 与遗留 relay 路径。默认复用现有 RPC/IPC、不顺带扩成通用 unknown 错误修复；若边界实证失败，再按失败点增加最小接缝，而非回到已撤回的 10 文件方案。

## 最终窄版代码复核与运行事实（2026-10-25）

[Claude 最终防御复核](../../../../.docs/mobile-terminal-surface-recovery-ui-validation/2026-10-24/evidence/claude-code-review-final.md)对 `code-review-manifest-final.json` 的四个源码文件哈希一致快照维持 **APPROVE：0 P0、0 P1**。新增 `isValidHostTerminalTabId(recorded.tabId)` 后，不合法 web surface id 先被拒绝，交由上游一次随机 fallback；真实 store 回归先红后绿，最终 59/59 定向单测通过由实现代理报告，评审人未重跑。剩余 P2-4 为本机 numeric 同 tab 多 leaf 的第二个 leaf 可能沿旧 fallback 重复增生，当前修复未覆盖。

隔离 SSH 通过 root `127.0.0.1:2222`、独立短 `/private/tmp` HOME 与 managed orcad，在 `evidence/ssh-runtime/steps.json` 对 Git worktree 和 folder repo 各完成三次 mobile E2EE executionHost `worktree.activate`：回复均 `activated:true`，远端原 PTY/incarnation 不变、远端和电脑本机新 PTY 都为 0。独立 `folder:<id>` 可 `terminal.create` 原远端终端，但三次 activate 都返回 `selector_not_found`，手机按既有 best-effort 成功/跳过合同处理；远端身份未变与无新 PTY 只证明**安全跳过**，不证明该恢复分支通过。初次长 HOME 引起的 Unix socket `EINVAL` 是夹具问题，短路径重跑成功；遗留 relay 真机、mixed peer、SSH UI 映射仍未验。以上执行结论以[Journal 的 TC 粒度](../journal.md)为准，不将局部 slice 升级为全部 REQ 已实现。

## 主机、状态与待验证

本机文件、PTY 和进程在本机；直连 SSH 的文件、PTY、relay 在 SSH 机，布局/关闭记录在电脑 main 的 `ssh:<target>` 分区；配对 runtime 的权威 session 在远端 runtime。窗口是投影。folder workspace 不应以 Git 路径推断 owner。执行主机的活性结论须区分 `live`、`unverifiable`、`exited`；主机失联只能标为 `unverifiable`，不可推断 `exited` 或读取该主机。现有代码事实及文件索引见[源码审查](../../../../.docs/mobile-empty-terminals-investigation/2026-10-24/evidence/source-review.md)。SSH、配对 runtime、独立 `folder:<id>`、关闭竞态、正向 exited 恢复与旧 peer 缺字段尚待运行验证。
