# 终端 Chat 持久提交闭环

关联 [Issue #121](https://github.com/Fartown/orca/issues/121)。REQ-1805 的严格写入结算仅修正了拒绝与部分未知状态，不能证明 Codex 接收；本轮补齐完整发送闭环。

### REQ-1807 输入与目标在发送前持久交接

优先级：P0。当前状态：已实现。

桌面 Codex 普通 PTY Chat 的文字、图片路径、固定 requestId、原 pane、执行主机、PTY incarnation、provider session 必须在清草稿前完成持久保存。存储失败不得发送或清草稿。等待持久交接期间新增文字/附件不得清掉。切视图、renderer/app 重启后保留未确认原文；未确认记录不能被缓存上限、同文重发、分页或 Stop 删除。不改独立 structured chat、斜杠命令与其他 agent。

### REQ-1808 执行主机持有一次完整提交

优先级：P0。当前状态：已实现。

复用 terminal.send 的 durable ledger 与原串行队列，clear、图片、正文、Enter 都由执行主机操作，并检查同一 PTY/incarnation/provider session。每段等待已有 transport settlement；拒绝或未知不继续后缀，不回退 raw write，不自动补发正文或 Enter。客户端 renderer 消失不能取消已开始的主机提交。host accepted 不等于 Codex 消费。

### REQ-1809 正文证据与同请求恢复

优先级：P0。当前状态：已实现。

初始显示发送中；20 秒仍无对应 Codex 用户消息则显示投递未确认。执行主机在 Enter 前读取真实 provider transcript 边界，receipt 保存文件字节边界（时间戳仅诊断）；客户端只认同 session、该边界后的对应正文/图片用户行，main 根据最新持久状态原子对账，一条用户行只能确认一个请求。旧 working、旧同文、loading 空读、分页滑出和失败记录均不能充当送达证据。字节游标只在原文件内容连续时有效：执行主机保存文件身份和边界 fingerprint，每次确认前由原 ledger proof 核验；文件替换/截断/边界重写不得确认。

丢回执/重启后只在共享连接层认为 host 在 contact 时查询原 requestId；不由 feature 探活、重连、轮询或重新 terminal.send。absent/pending/unknown 不授权补发；同一 profile 的主机进程重启可查原 ledger，重新配对或主机身份改变则保留未知，不重定向。

### REQ-1810 本地与 SSH 兼容验收

优先级：P0。当前状态：已实现。

本地文件夹、Git worktree 与通过 SSH 连接的 managed/paired 执行主机均验收真实 App 和真实 Codex。桌面 outbox 在客户端 userData；远端 ledger、PTY、Codex HOME、图片及 transcript 在执行主机；模型 fixture 的 127.0.0.1 属于运行 Codex 的机器，客户端隧道另记。不得操作用户旧终端或服务。

新增能力 terminal.chat-composer.v1 在发送前协商；旧主机、无 SQLite 或只支持原始输入的 legacy SSH relay 保留草稿并明确拒绝可靠 Chat 提交，不迁移原 PTY、不新建 shell。旧客户端与移动端原有协议保持兼容；无此桌面能力的终端 Chat 入口不得冒充持久提交。
