# 同仓库与同显示名称归并方案入口

当前有效方案为[项目归并最小改动方案：同仓库沿用，同显示名称补充归并](项目分组最小改动方案-10-23.md)。用户指定使用项目设置里的“显示名称”：重名合并，不希望合并时改名，并授权“改吧”。源码实现与隔离应用验证已完成；用户安装版本和在线名称未在本轮修改。

- 同 repo：现有仓库身份规则自动归并，Movo 沿原逻辑，不新增匹配规则。
- 同显示名称：在原有结果上组合侧栏区块，使用已有名称；不新增人工分组 ID、成员名单或专用合并设置。
- 改名：复用现有设置入口，解除同名产生的展示归并；同仓库自动关系及原有例外保留。
- 其他归属：Repo、原生 Project/setup、工作区引用、文件、终端、Git、账号、任务、AI Vault、快捷命令和运行偏好继续按原逻辑处理。

新稿第 1–3 节解释当前为何不合并、三个目录具体改名效果和归并优先级；第 4 节列清受影响与不变逻辑；第 5–7 节说明既有保存 owner、最小接缝、Local/SSH/移动端兼容和验证范围。

历史 REQ-601、REQ-602、REQ-603、REQ-604 属于人工成员名单原型，记录在[历史需求](../requirements/侧栏项目合并.md)，已由当前 REQ-611、REQ-612、REQ-613、REQ-614、REQ-615 替代；它们不要求重新启用旧设置或继续部署旧包。

上游事实见[现状调研](../research/项目目录工作区与属性归属现状.md)，范围见[当前需求](../requirements/requirement.md)，决策见[Journal D-005](../journal.md#d-005-复用显示名称归并改名解除同名归并)，验证见[当前 Test Run](../tests/runs/2026-10-23-同显示名称项目归并.md)。[上一版原生归属稿](原生项目归属方案-10-23.md)标记 superseded；其中业务引用迁移不再实施。此前人工成员名单也是已撤回建议，旧原型测试不能作为当前名称规则的验收证据。
