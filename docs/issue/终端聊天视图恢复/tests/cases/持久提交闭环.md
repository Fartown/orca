# 持久提交闭环

- TC-1816（REQ-1807）：保存成功前不清草稿、不发消息；文件损坏/磁盘失败保留输入；重开 store 和 renderer/app 后仍有相同 id、文字、附件、主机。
- TC-1817（REQ-1807）：prepare 等待期间编辑文字或替换/新增附件，完成交接后仅清除未变的提交内容。
- TC-1818（REQ-1808）：本地和 SSH 执行端 clear/image/body 的拒绝、unknown/丢 ACK 均不继续后缀；无 raw fallback，无自动第二个 Enter。
- TC-1819（REQ-1808）：正文接受后 renderer 卸载不取消首次 Enter；PTY incarnation/provider session 改变则拒绝原操作，不重定向。
- TC-1820（REQ-1809）：仅 host accepted、旧 working、loading 空消息、旧同文、分页边界不在窗口、没有主机边界均不得确认。20 秒后展示未确认并保留原文；同 session 的 inode 替换、truncate 和边界重写即使提供同文大 offset 也不得清除原件。
- TC-1821（REQ-1809）：失败同文与不同附件重发不能互相冒领；同文并发一条 user row 只确认一条请求；confirmed messageId 经过重挂后不能再次分配；renderer 缺失并发记录时仍由 main 最新状态裁决，争用一行的两个请求都保留未知。
- TC-1822（REQ-1809）：实际提交后丢回执，使用原 ID requestShow；pending/absent 保持未知，不能新发送；offline 不读主机，仅 contact edge 查询，renderer/app 重启同样适用。
- TC-1823（REQ-1810）：真实 Codex + Responses fixture，Chat DOM 发送唯一正文，模型请求与真实 JSONL 一致且仅一次，pending 对账消失；原 PTY/providerSession 保持。
- TC-1824（REQ-1810）：SSH 独立执行主机重复正例与断线恢复；记录客户端与主机的 HOME、配置、ledger、文件及各 loopback 端口；不读写用户原会话。
- TC-1825（REQ-1810）：旧能力/无 SQLite/legacy SSH 保留草稿并诚实拒绝；不影响其他 agent、命令、structured chat、移动客户端旧协议。
