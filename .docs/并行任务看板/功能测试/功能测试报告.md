## 4. 完整 16 步 packaged App 旅程

命令：

```bash
SKIP_BUILD=1 \
ORCA_E2E_PACKAGED_EXECUTABLE='/tmp/orca-issues-reuse-package.OYRu8W/mac-arm64/Orca.app/Contents/MacOS/Orca' \
pnpm exec playwright test tests/e2e/issues-journey.spec.ts \
  --config tests/playwright.config.ts \
  --project electron-headless --workers=1 --reporter=line
```

最终结果：`1 passed (3.6m)`。

该旅程覆盖本地/外部 Issue、三级层级、Issue 新建会话、Folder Workspace Hook 物化、原生行复用、
bind/rebind/unbind、detached 持久化、AI Vault 原生 Resume、Continue in New Session、重启、profile 隔离、
degraded/unavailable、main 原生 Project transfer、authority tree 分区，以及 Activity/Dashboard 不接入。

这次真实回归先后暴露并区分了三类问题：

1. 产品缺陷：Issue 外层 capture 使用 microtask 清 route，会先卸载内部 Workspace row，使其 bubble
   activation 丢失。产品代码改为 `setTimeout(0)` 后，Step 6 实际聚焦通过。
2. 过期测试：Step 14 仍断言已撤回的 `issue_project_move_blocked`；实际 App 正确返回 main 原生
   `transferred`。测试改为验证 Issue 不介入 Project transfer。
3. 过期定位器：历史行曾查找 main 从未提供的 `data-ai-vault-session-id`；改为通过原生 Search sessions
   和 `ai-vault-session-metadata` 定位，没有要求产品新增 DOM seam。
