# 渠道分流与单一状态源

在 SettingsAppUpdateSection 仅增加渠道接缝，integration Android 挂 owned IntegrationSettingsUpdateSection；官方渠道沿用既有组件。提取关于页现有按钮标签、busy、动作到 owned useIntegrationUpdateAction，两个入口共享 mobileUpdates.store 和动作，不创建第二个控制器。外层复用 ListRow、SettingsSection/SettingsNote 与既有本地化键，保留版本行，状态直接来自控制器。

直接隐藏外层入口会保留用户绕路；重新接上游会违反签名与更新渠道约束；重写更新器会产生第二套请求/安装状态。因此采用既有控制器复用。

风险集中在渠道分流、hook 订阅和安装动作：用真实 controller+受控 native I/O 的组件回归覆盖 integration 与官方渠道、下载返回、去重、权限/继续安装和真实错误；用 RN Web 真实组件的手机 viewport 隐藏渲染采证。原生 APK 安装不作为浏览器组件测试的通过项。所有文件/校验/安装属于手机，更新服务属于既有 GitHub fork 发布；SSH 配对主机不参与更新。
