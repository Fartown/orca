# 工作区恢复占位收敛

## 背景与目标

用户截图中出现三组 Unknown；只读采样及真实会话字段回放证实，历史选择字段复活工作区，随后项目目录刷新移除了 repo 却留下工作区。用户明确要求按 fork 流程修复。

## 范围

In Scope：客户端会话恢复与成功目录刷新后的占位收敛。Out of Scope：磁盘、Git worktree、进程删除，原生项目归属、同名分组合并、连接重试和协议变更。

## 需求与验收

### REQ-2001 历史选择不复活工作区

当前状态：已实现。

本地：没有实际标签、文件、浏览器内容或可恢复会话的历史选择/排序记录不生成额外工作区。SSH：远端会话的历史选择同样不能单独创建占位；真实终端及主机归属继续保留。

### REQ-2002 成功目录刷新收敛占位

当前状态：已实现。

本地：保持本机已登记工作区。SSH：只针对已取得联系并成功返回的对应主机目录收敛恢复占位，失败、失联、过期响应不能作为删除证据；相同 repo/worktree ID 在其他主机的记录保留。

### REQ-2003 保留可恢复内容

当前状态：已实现。

本地：打开文件、草稿、真实标签、浏览器内容和可恢复 agent 保留。SSH：远端项目不再登记但仍有可恢复内容时保留带名称的客户端恢复容器及原 host 归属；内容不会被重新登记到远端或转移到本机。

## 已确认结论与来源

来源为本次用户截图、只读诊断及用户“按fork流程修复一下”的授权。维持原业务归属和既有兼容性是仓库约束。

## 未决问题

无阻止本轮实现的未决产品问题。数据保留优先于清理；本轮不自动删除用户会话内容。
