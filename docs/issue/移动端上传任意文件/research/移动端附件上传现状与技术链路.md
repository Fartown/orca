# 移动端附件上传现状与技术链路

只写当前事实、约束与改动触点，不给方案。代码位置以 2026-10-06 的 `fork/integration`（`9e353deab4`）为准。

## 1. 会话页有两种形态

移动端会话页在生产环境有两种渲染方式，两条路都要覆盖：

| 形态 | 何时出现 | 代码 | 选择器 |
| --- | --- | --- | --- |
| 网页版会话页 | 手机壳支持路由要求的全部桥接接口时（当前 App 的默认情况） | 页面由**电脑端**下发（`config/scripts/mobile-web-page-routes.mjs` 中 `/h/[hostId]/session/[worktreeId]`），运行在手机壳的 WebView 里 | `mobile/src/platform/media-picker.web.ts` → 桥接接口 `native.media.pick/read/release` → 手机壳 `mobile/src/platform/native-media-device.ts` |
| 原生会话页 | 手机壳缺少必需接口时回退 | 手机 App 自带的 JS | `mobile/src/platform/media-picker.ts` → `mobile/src/session/mobile-image-source-picker.ts` |

网页版会话页与电脑端永远同版本；可能错开版本的是**手机壳与页面**（桥接接口）和**手机与电脑端**（RPC）。页面通过 `client.getShellSession()?.grants.native` 得知手机壳授予了哪些接口（`mobile/src/mobile-web-shell/bridge/use-native-verbs.ts:169`）；路由可把接口列在 `optionalGrants`，缺失时页面仍以网页形态渲染。

Android 手机壳的 WebView 没有覆写 `onShowFileChooser`（`mobile/modules/orca-mobile-web-shell/android/.../MobileWebShellView.kt:262`），网页里的 `<input type=file>` 在 Android 上无效。

## 2. 入口与选择器

- 终端输入栏：`mobile/src/session/MobileTerminalInputActions.tsx:48-57`，点按 `onAttachImage`（相册），长按 `onAttachFile`（文件）；`MobileSessionCommandDock.tsx:289-290, 357-358` 分别传 `'library'` / `'files'`。图标 `ImagePlus`，无障碍标签 "Attach a photo"。
- 聊天输入框：`mobile/src/session/MobileNativeChatOverlay.tsx:117` 只接了 `'library'`；`MobileNativeChatComposer.tsx:278` 按钮标签 "Attach image"。
- 原生选择器：相册 `mediaTypes: ['images']`（`mobile-image-source-picker.ts:88`），文件 `type: 'image/*'`（`:114`）。读出的结果只有 `{ base64, uri }`，没有文件名、类型、大小（`mobile/src/platform/media-picker-contract.ts:15-23`）。
- 手机壳选择器：文件 `type: '*/*'`（`native-media-device.ts:96`），返回项含 `mime`、`byteLength`，**不含文件名**（`mobile/src/mobile-web-shell/bridge/bridge-media-verbs.ts` 的 `mediaItemSchema`，strict）。页面 `media-picker.web.ts:32-34` 丢弃 `mime`，把每一项当图片上传。
- 手机壳暂存上限 `MEDIA_STAGED_MAX_BYTES` = 约 18 MiB（`mobile/src/mobile-web-shell/media-handle-registry.ts:201`），协议里偏移量上限也写死为该值（`bridge-media-verbs.ts` 的 `byteOffsetSchema`），最多 8 个句柄。

## 3. 上传与主机落盘

- 手机：`mobile/src/session/mobile-clipboard-image.ts` 把整段 base64 按 512 KiB 字符切块，调 `clipboard.startImageUpload / appendImageUploadChunk / commitImageUpload`；旧主机回退单帧 `clipboard.saveImageAsTempFile`（≤256 KiB）。
- 主机：`src/main/runtime/rpc/methods/clipboard.ts` 把所有分块字符串留在内存，commit 时整体解码（`clipboard-image-upload-decoding.ts`），最多 8 个并发，槽位 TTL 5 分钟，按移动端 clientId 绑定归属。
- 落盘：`src/main/window/clipboard-image-temp-file.ts:30` 文件名固定 `orca-paste-{时间戳}-{uuid}.png`。带 `connectionId` 时经 `requireSshFilesystemProvider` 写到 SSH 主机 `getTempDir()`（relay `fs.tempDir`，即远程用户的系统临时目录；旧 relay 回退 `/tmp`），否则写电脑本机临时目录。
- 参数 schema 用 `z.object`（`src/shared/rpc-contract/clipboard-params.ts`），未知字段被静默丢弃。

## 4. 目标机器判定

- 手机端的 `connectionId` 来自 `use-mobile-session-accessory-selection.ts:190-200`：`repo.list` 后按 `repoId` 取 `connectionId`。文件夹工作区（id 形如 `folder:…`）匹配不到 repo，结果为 null，被当成本机（上游现有缺陷，影响图片上传）。
- 主机端已有按工作区判定的公开方法 `runtime.showTerminalWorkspaceLaunchScope(worktree)`（`src/main/runtime/orca-runtime-list-managed-worktrees.ts:140`）：覆盖 git worktree、文件夹工作区与浮动终端，返回 `connectionId`，与终端 PTY 启动使用同一套判定；上游 `agent-launch` RPC 已在用。附带一次推送目标物化（`triggerTerminalSpawnPushTargetMaterialization`，远端已存在时为空操作，不等待）。
- 文件资源管理器的写入走 `resolveRuntimeFileTarget`（protected），对 `runtime:` 托管工作区抛错。
- SSH 文件接口（`src/main/providers/filesystem-provider-contract.ts`）有 `getTempDir / createDir / createDirNoClobber / writeFileBase64Chunk(append) / rename / deletePath(recursive) / readDir / stat`。relay 的 `fs.*` 处理没有路径白名单（`src/relay/fs-handler.ts:82-120`）。SSH 断开时 `requireSshFilesystemProvider` 直接抛错。

## 5. 交给 agent 的方式

- 手机终端：上传后用 `nativeChatTerminalWrite`（`terminal.send`，`enter: false`）写入 bracketed paste 包裹的 `formatAgentImagePath(agent, path)`（`src/shared/agent-image-paste.ts`）。
- 手机聊天：图片成为输入框里的「待发图片」；提交时
  - 结构化会话把路径作为 `image-ref` 附件发送，Claude 适配器按扩展名读文件，只接受 `.gif .jpeg .jpg .png .webp`，其余直接报错（`src/main/claude/claude-structured-dispatch-content.ts:113-151`）；
  - 终端型会话先清空输入行，再逐个粘贴图片路径，最后发正文（`mobile-native-chat-image-send.ts`）。
- 桌面对照：
  - 终端拖入非图片：输入 `shellEscapePath(path, 目标 shell) + ' '`，不包 bracketed paste（`src/renderer/src/components/terminal-pane/terminal-drop-path-writer.ts`，转义函数在 `pane-helpers.ts:69`）。
  - 聊天拖入或选择非图片：在草稿里插入 `@路径`（`formatNativeChatFileReference`），图片进待发区。

## 6. 体积、内存与临时文件

- 现上限：base64 24 MiB，原始约 18 MiB（`src/shared/clipboard-image.ts:1-4`）。
- 主机最坏内存：每个上传约 24 MB 字符串加 18 MB Buffer，8 个并发约 340 MB。
- 原生选择器读文件已经是分块读（`expo-file-system` 的 `File.open().readBytes`，256 KiB 一块），但结果累积成整段 base64 再上传。
- `orca-paste-*` 临时文件在本机和远程都没有任何清理。可复用的本机清扫：`src/main/window/owned-temp-staging-root.ts`（按用户的私有根目录 + 按 mtime 过期清扫子目录）。远程没有现成清扫器。

## 7. 版本兼容约束

- 手机端白名单在分发前检查：旧主机对未知方法回 `forbidden`，更旧的回 `method_not_found`（`src/main/runtime/runtime-rpc/runtime-rpc-websocket-dispatch.ts`）。手机端已有统一判定 `isMobileMethodUnavailableError`（`mobile/src/files/file-list-fallback.ts:21-30`）。
- 桥接协议 strict 解析：给现有 `native.media.*` 的返回项加字段，会让旧页面解析失败；新能力需要新接口名并放进 `optionalGrants`。
- `src/main/runtime/mobile-rpc-allowlist.test.ts` 扫描 `mobile/src` 里的 `method: '…'` 字面量，要求每个都在白名单里且已注册。
- `mobile/src/session/mobile-session-route-parity.test.ts` 固定了会话路由文件的 hook 数、字符串数、JSX 数与摘要，改这些文件需要重新固定。
