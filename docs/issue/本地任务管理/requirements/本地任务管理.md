# 本地任务管理

## 1. 背景与目标

现在的 Orca 以项目和会话为中心：用户先选仓库、开工作区、开会话，「要做的事」散落在各个会话的对话里，没有地方统一记录、拆分和跟踪。原来 fork 里的「Issues 看板与会话」不好用，已于 2026-10-23 撤回（`revert(issues-board)`），这一版重新做。

**目标**：在 Orca 里加一个以任务为中心的本地任务管理。需求在这里记录、拆分、跟踪；开始做时，一键在 Orca 里开工作区和会话。之后写代码、看 diff、提 PR，都用 Orca 原有的功能，任务这边只负责把它们挂在一起、显示进展，并在会话需要人时告诉你。

**原则**（2026-11-02 修订：原第 2 条「只做连接，不做流程」改为下面的 2～5 条，D-1 同步修订，见 D-011、D-012）：

1. 任务优先：任务是入口和记录，对话是手段。从任务进入工作区和会话；从派活、新建任务或任务里开的会话自动属于任务；工作区和会话也能看到自己属于哪个任务。直接在工作区里开的会话，只在任务模式侧栏的「未关联任务的会话」组里能记成任务（REQ-011、REQ-026）。
2. 人说了才开工：Orca 不因为状态变化、定时或主机恢复联系自动开会话。派活一定来自用户的一句话、一次点击，或用户确认过的调度提案（REQ-029、REQ-030）。
3. 动作都留痕：派活、开会话、回写、状态变化、验收，都在任务时间线上留一条记录，写明来源（你、手机、对话、智能体、规则）。
4. 进度只写明确的内容：摘要来自智能体主动回写；没有回写时显示它每轮结束时的最后一句话；让模型读会话生成摘要是用户点了才做的可选操作（REQ-022）。任务这边仍然不判断「做完没有」「做得对不对」，状态由用户决定，只保留两条可以关掉的自动规则（REQ-013）。
5. 完成由人定：智能体最多把任务推进到「待验收」；「完成」只能在桌面或手机界面上点，来自 CLI 的写入不能进入已完成类别（REQ-019、REQ-024）。
6. Orca 已有的不重做：diff、批注、提交、PR、Checks、智能体状态、通知、新建工作区弹窗、聊天视图、终端视图，都直接用现有的。不轮询、不重试、不排队：主机不在联系时派活和读取都不可用并写明原因，恢复联系后只重读一次。
7. 只记录明确的关联：工作区和会话只在两种时候挂到任务上，一是从任务里开（含派活），二是用户手动关联。不推断，不追踪会话身份。
8. 任务库和 Orca 的项目一样，是每台 Orca 自己的资源：项目在哪台 Orca 上，它的任务就存在哪台；其他客户端走现有的远程连接读写，主机不在联系范围内时不读它（D-008）。

产品方案与设计稿的讨论过程见 `.docs/本地任务管理调研/`（本机目录，不进仓库），主稿是 2026-10-24 目录下的 `产品方案-v4.md`，设计稿是同目录下的 `prototype-v4/`。以任务为主的工作流（REQ-026～REQ-030 和 REQ-020～REQ-025 的修订）见 `interaction/任务为主的工作流产品方案.md`，评审见 `interaction/任务为主的工作流方案评审.md`，交互原型在 `interaction/prototype-task-first/`，技术方案见 `solutions/任务为主的工作流技术方案.md`。

## 2. 用户场景

用户在商城项目（仓库 shop，前端在 `web/`，后端在 `api/`）里记录需求 SHOP-12「订单导出支持 CSV」，拆出两个子任务：SHOP-13 后端、SHOP-14 前端。在 SHOP-12 上点「开始做」，在 SSH 主机 minizc 上建出工作区 `shop-12-order-export`；再分别在 SHOP-13、SHOP-14 上「开会话」，Claude 做后端、Codex 做前端，两个会话在同一个工作区里同时运行。

之后用户不用盯着两个终端：任务列表上能看到两个会话的状态点；Codex 提问时，「需要你」里出现一条「等你回答」，用户点开会话回答；Claude 一轮做完，「需要你」里出现「做完一轮，你还没看」，用户在桌面或手机上直接给下一句指令。PR 合并后 SHOP-12 移到「待验收」，用户在商城后台试过导出后点「通过」。

以任务为主的工作流（2026-11-02 起）：用户打开 Orca 先看到任务首页，顶部是派活输入框。输入「@orca/docs-typo 把 README 里过期的链接都修一下」，Orca 建出 ORC-42、关联 docs-typo、用默认智能体开会话，输入框下出现「已派活」卡，10 秒内可以撤销。Claude 每轮结束时用 `orca task progress` 回写一条「做了什么、结论、下一步」，任务卡上的「最新进展」跟着更新；用户不进会话也知道做到哪了，想细看就打开速览抽屉。输入「@orca/perf-startup 顺便看看首屏渲染」时，perf-startup 属于 ORC-39，它的 Claude 刚做完一轮，这句话直接发给它当下一句，不另建任务。没有 @ 的请求「看看 orca 里哪些工作区的 PR 还没合，各开一个任务跟进」交给调度会话，它只读查完后给一张提案卡，用户确认后由 Orca 建任务、开会话。

## 3. 范围

### In Scope

- 任务管理：项目、编号、可自定义的状态、任务、子任务、优先级、标签、评论与动态、列表、看板、详情、筛选、键盘操作、Cmd+J。
- 开始做：新建或关联工作区；在工作区里开会话，任务内容作为 prompt。
- 显示进展：任务上显示工作区、会话、PR 的现有状态，点击跳过去。
- 需要你：挂在任务上的会话等批准、等回答、被卡住，或做完一轮还没看时，进入「需要你」。
- 以任务为中心的导航：侧栏可以按任务分组；工作区卡片和会话头部显示所属任务。
- 以任务为主的工作流（2026-11-02，REQ-026～REQ-030）：任务首页与任务模式侧栏、任务视图；派活输入框与 @ 提及、直接派活与调度会话；会话速览；智能体回写进展（REQ-022）；待验收、通过与打回（REQ-024）。
- 手机端与桌面功能对齐。

### Out of Scope

- PR 的创建与合并流程、提交、占用锁与排队、执行者预设、编排。验收（通过、打回）和智能体回写约定从 2026-11-02 起在范围内（REQ-022、REQ-024），但仍不替用户判断「做完没有」。
- 一个任务涉及多个仓库、任务专用目录。前后端在同一个仓库里由用户在工程上约束，任务功能不加锁。
- 任何新的主机侧能力（执行主机上不新增 RPC、文件、端口或服务）。
- 截止日期与提醒、保存视图、任务模板、从外部 issue 导入、任务依赖、在智能体仪表盘和 AI Vault 上显示任务编号。这些以后再说，本版不预先设计。

## 4. 对象与关系

```mermaid
flowchart TB
    P["项目 商城 SHOP（仓库 shop，前缀 SHOP，状态集）"]
    T["任务 SHOP-12 订单导出支持 CSV"]
    S1["子任务 SHOP-13 后端：导出接口"]
    S2["子任务 SHOP-14 前端：导出按钮"]
    W["工作区 shop-12-order-export（shop 仓库的工作树，在 minizc 上）"]
    C1["会话：Claude（后端）"]
    C2["会话：Codex（前端）"]
    PR["PR #231（Orca 现有的 PR 状态）"]
    P --> T
    T --> S1
    T --> S2
    T -->|"开始做时新建或关联"| W
    S1 -->|"在父任务工作区里开"| C1
    S2 -->|"在父任务工作区里开"| C2
    C1 -.->|"属于"| W
    C2 -.->|"属于"| W
    W -.->|"Orca 现有"| PR
```

| 对象     | 规则                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 项目     | 关联 0 到多个 Orca 仓库（侧栏里的仓库），一个仓库也可以被多个项目关联（D-008）                             |
| 任务     | 属于一个项目；层级不限，不能挂到自己或自己的下级下面（D-008）                                              |
| 工作区   | 每个任务最多关联一个工作区，一个工作区最多属于一个任务；没有自己工作区的任务，沿用最近一层上级任务的工作区 |
| 会话     | 工作区里的一个智能体标签，终端视图和聊天视图都算；任务和子任务都可以开会话，一个任务可以有多个会话         |
| 进展记录 | 动态的一种：智能体回写、轮次结束的最后一句话、Orca 生成的摘要；任务卡和详情顶部单独突出显示（REQ-022）     |
| 对话     | 通用对话只是入口，不是任务；由它派出的任务，时间线第一条记「由对话派出」，能跳回那段对话（REQ-030）        |

### 任务怎么展示（2026-10-30 定）

- 任务的主要信息是**标题**。凡是展示任务的地方，主文字都是标题；编号（如 `SHOP-12`）是辅助信息，用更小、更浅的字作为前缀或后缀，不能替代标题。
- 空间只够放一样时放标题，标题过长就截断，编号放进悬停提示。适用的地方包括：
  - 侧栏工作区卡片的任务标签；
  - 会话页头的任务 chip；
  - 侧栏「按任务分组」的组头；
  - 手机会话页任务条。
- 弹窗标题和提示里用标题指代任务，例如「删除『订单导出支持 CSV』？」，而不是「删除 SHOP-12？」。
- 编号只用在这些地方：
  - 搜索和跳转：Cmd+J 按编号直达，结果的主文字仍是标题；
  - 引用：分支名、prompt；
  - 列表、看板、子任务列表里，作为对齐用的小号灰色列；
  - 详情页顶部的位置标识，此时标题就在下方。

## 5. 需求点

以下「SSH 场景」指客户端是用户的桌面 Orca，工作区、会话和 PR 所在的执行主机是 SSH 主机；配对服务器与 SSH 主机遵守同样的规则。会话事实只用 `live`（在运行）、`unverifiable`（无法确认）、`exited`（已结束）三个词。

### REQ-001 项目与仓库

- 目标级别：P0；当前状态：部分实现（2026-10-26 切片 1：一个项目对应一个仓库的版本已实现并验证，见 TC-001；2026-10-28 改为项目可关联 0 到多个仓库（D-008），已随 PR #71 实现，真机证据在本机 `.docs/local-tasks-ui-validation/2026-10-28/codex-d008-verify/`，测试用例文档尚未补对应条目）。
- 描述：项目是任务的容器，字段有名称、前缀、状态集、两条自动规则的开关，以及关联的仓库（0 到多个 Orca 仓库，其中一个是默认仓库）。
  - 没有仓库的项目只做任务管理，比如调研、运营、写文档。
  - 多个仓库的项目用于前后端分仓等跨仓的情况；一个仓库也可以被多个项目关联。
  - 第一次进入任务页时，按用户已有的仓库推荐生成项目（每个仓库一个，用户确认后才创建）；也可以随时新建一个空项目，之后再关联仓库。
  - 在「设置 → 本地任务」分区里，可以改项目的名称、前缀、状态、规则开关和关联的仓库；「设置 → 任务来源」的本地任务卡片里，「管理项目与状态」也跳到这里。手机建项目时同样可以一次勾选多个仓库（2026-10-30）。
- 本机场景：本机仓库可以关联到项目。
- SSH 场景：SSH 主机上的仓库同样可以关联；项目只记录仓库在 Orca 里的标识。项目存在拥有它的那台 Orca 上（REQ-018）：桌面上的项目在 SSH 主机断开时照常显示和编辑；SSH 主机上的项目在断开时显示为未连接，不读也不写，恢复联系后再读。
- 验收标准：建一个没有仓库的项目，能建任务、改状态；建一个关联前端、后端两个仓库的项目，「开始做」时两个仓库都能选；推荐列表包含本机仓库和 SSH 仓库。

### REQ-002 编号与前缀

- 目标级别：P0；当前状态：已实现（2026-10-26 单测与真机验证通过，见 TC-002、TC-031、TC-033）。
- 描述：编号按项目递增（SHOP-1、SHOP-2……）。任务的身份是不可变的 ID，编号只用于显示和搜索。前缀可以改，改后旧前缀保留为这个项目的别名，旧编号仍能搜索和跳转；旧前缀不能再被其他项目使用。删掉的编号不复用。原项目删除后，只要仍有存活任务使用该前缀的历史编号，其他项目的新建或改前缀仍不能占用它。
- 本机场景与 SSH 场景：编号和前缀在拥有这个项目的那台 Orca 上分配（REQ-018）；不同主机上的任务库各自编号，前缀互不占用。有多台主机的任务时，编号旁显示主机名，例如「dbox · SHOP-12」。
- 验收标准：SHOP 改成 MALL 后，搜索 SHOP-12 能打开 MALL-12；新项目不能使用前缀 SHOP。

### REQ-003 状态类别与自定义状态

- 目标级别：P0；当前状态：已实现（2026-10-26 单测与真机验证通过，见 TC-003）。
- 描述：状态有 6 个固定类别：待规划、未开始、进行中、评审、已完成、已取消。新项目默认 6 个状态，每个类别一个：待规划、待办、进行中、评审中、已完成、已取消。用户可以在类别里新增、改名、改颜色、排序（例如在进行中类别里加「联调中」）；状态不能换类别；每个类别至少保留一个状态。「评审」只是一个类别，不附带任何流程。看板的列就是项目的状态；跨项目查看时按类别出列。
- 本机场景与 SSH 场景：一致，与执行主机无关。
- 验收标准：加了「联调中」后，看板多出这一列；删除一个仍有任务的状态时，要求先把这些任务移到另一个状态。

### REQ-004 任务与子任务

- 目标级别：P0；当前状态：部分实现（2026-10-26 两层版本已实现并验证，见 TC-004、TC-005、TC-006、TC-027、TC-030；2026-10-28 改为层级不限（D-008），已随 PR #71 实现，整棵子树防环，测试用例文档尚未补对应条目）。
- 描述：
  - 字段：标题、描述、状态、优先级（无、紧急、高、中、低）、标签、父任务。「完成标准」字段于 2026-11-02 取消（D-014）：界面不再显示和编辑，升级时把已有的条目追加到描述末尾，库里的列只读保留一个版本再删。
  - 层级不限：任何任务都可以有子任务。不能把任务挂到它自己或它的下级下面。列表按树缩进显示并可折叠，看板卡片和详情显示「上级 › 任务」路径。
  - 新建任务对话框带「继续创建」；在子任务输入框里粘贴多行文本，可以一次建多个子任务。手机多行创建会将表单中的状态、优先级、标签应用到这些子任务；部分保存失败时明确保留未完成状态，重试不重复创建。
  - 删除任务只删任务记录，关联的工作区和会话都不动。删除带下级的任务时，所有下级一起删除，确认框写明总数。
  - 移到别的项目时，整棵子树一起移，各自拿到新项目的编号，旧编号仍能打开。已关联工作区的任务也能移，工作区关联保留。
  - 下级完成不会带动上级，上级的状态由用户决定。
- 本机场景与 SSH 场景：一致。删除任务时不碰执行主机，主机不在线也能删。
- 验收标准：删除 SHOP-12 后，工作区 `shop-12-order-export` 和其中的会话仍在，工作区卡片不再显示任务编号。

### REQ-009 开始做

- 目标级别：P0；当前状态：部分实现（2026-10-27：开始做、无智能体创建与完成后关联已接入；本机与 SSH 的空终端真实界面回归通过；真实智能体启动未验收，见 TC-101、TC-110）。

  - 2026-11-02 起，新建任务的流程见 REQ-027：第一屏选「新建工作区」就直接接本弹窗。
  - 2026-10-30 起，本地任务接入新建工作区的「创建自」，和 GitHub、Linear 等来源同一套交互：

    - 「创建自」新增「本地」页签（和上游页签一样只写一个词），排在「智能」之后，按标题或编号搜索；「智能」页签的结果里不混入本地任务。

    - 关联仍记在任务库，不写进上游的「已链接的工作」，原因是旧版本会拒收或丢弃不认识的提供方。
    - 暂缓：从本地任务创建的工作区，在上游的创建统计里来源记为 `unknown`。改它要在上游的统计口径里加值，不由 fork 改。

- 本机场景：在本机仓库建工作树并关联。
- SSH 场景：运行位置选 SSH 主机时，工作树建在 SSH 主机上，用 Orca 现有的创建流程，不新增主机能力。主机未连接时「开始做」不可用，并说明「minizc 未连接」这类原因；不替用户重连。
- 验收标准：本机和 SSH 各开始做一次，工作区卡片显示正确的主机和分支；SSH 主机断开时按钮置灰并显示原因。

  2. 工作区关联的 PR 合并后，关联这个工作区的任务移到项目设置里选定的状态：「待验收」（默认；评审类别下新增的默认状态，老项目也补上）、已完成类别的第一个状态，或不动（2026-11-01 定，见 REQ-024）；它的上级不自动完成。规则当前的判定显示在任务详情和待验收卡上，例如「PR #231 合并后按项目设置进入待验收」「项目关掉了这条规则」。

- 本机场景：本机工作区的 PR 合并后触发规则 2。
- SSH 场景：SSH 工作区的 PR 状态由 Orca 现有的 PR 读取提供；主机不在联系范围内时不读，恢复联系后读到「已合并」再触发，不补发、不重复触发。
- 验收标准：PR 合并后任务自动完成；关掉规则 2 后不再自动完成。

### REQ-014 需要你：判定

- 目标级别：P0；当前状态：部分实现（2026-10-27：桌面判定版本已接入；2026-10-28 改为由拥有会话的主机判定（D-008），已随 PR #71 实现，SSH 真机证据在本机 `.docs/local-tasks-ui-validation/2026-10-30/ui-final/ssh/`，测试用例文档尚未补对应条目）。
- 描述：判定在拥有会话（也就是拥有这个任务库）的那台 Orca 上做，桌面、手机、局域网网页版看到的是同一份结果。完全使用 Orca 现有的智能体状态（hooks 优先，其次是终端里的 OSC 7501），不自己猜测。只看挂在任务上的会话。规则只有 4 条：

  | 类型               | 判定                                                                                                  | 何时自动消失                                           |
  | ------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
  | 等你批准           | 状态为等待，原因是权限申请                                                                            | agent 回到工作中                                       |
  | 等你回答           | 状态为等待，原因是提问，或 agent 没报原因；结构化聊天会话需要人处理时也归为这一类（这类会话不报原因） | 用户回答后 agent 继续                                  |
  | 被卡住             | 状态为阻塞，比如要登录、额度用完                                                                      | agent 恢复工作                                         |
  | 做完一轮，你还没看 | 状态为完成，并且这一轮还没人看过                                                                      | 用户在任意一端打开会话看过、标记已看，或给了下一句指令 |

  不进「需要你」的：正在工作的会话；已完成且看过的会话；主机断线的会话（显示「无法确认」）；Orca 刚重启、还没收到新状态的会话；没有挂在任务上的会话（仍由智能体仪表盘和现有通知负责）；没有集成状态上报的智能体（会话行显示「状态未知」）。

  「完成」只表示 agent 的这一轮结束了，不代表任务做完了：条目只写「Claude 停下了，最后一句：……」，任务状态不因此改变。每条显示任务标题和编号、类型、智能体和它的最后一句话、时间；同一个任务下的多条合并成一行。入口有左侧栏「任务」按钮上的数字、任务页的「需要你」视图、手机首页的任务卡片；系统通知沿用 Orca 现有的智能体通知设置，不新增开关。

  「任务在等你」（2026-11-01 定，修订 D-3）：除了上面按会话状态判定的 4 类，另有按任务字段判定的两类，在视图和首页里单独分组显示，叫「任务在等你」，和「会话在等你」区分：待验收（任务处于「待验收」状态，REQ-024）、等你决定（REQ-023）。条目正文优先用智能体回写里的「需要你什么」，没有才用最后一句话（REQ-022）。

  「需要你」与智能体仪表盘的「需要你」同名，口径不同（2026-10-30 定，不改名）：这里只看挂在任务上的会话，仪表盘看全部会话；挂在任务上的会话会在两边同时出现，这是预期的。在这里标记已看（E）只移出本地列表，不会清掉 Orca 的未读和仪表盘里的条目；反过来，在会话里看过会清掉这里的「做完一轮，你还没看」。

- 本机场景：4 条规则都能触发，也都按上表自动消失。
- SSH 场景：判定用的状态由执行主机上报，与本机一致；主机断开时条目不再算「需要你」，改为在会话行显示「无法确认」；恢复联系后按真实状态重新判定。拿不到等待原因的主机，一律显示「等你回答」。
- 验收标准：本机和 SSH 下 4 条规则各触发一次，条目出现并按规则消失；Aider 这类没有集成的智能体不进「需要你」。

### REQ-015 需要你：操作

- 目标级别：P0；当前状态：部分实现（2026-10-27：桌面暂存队列版本已接入；2026-10-28 改为照 Orca 现有会话发消息一次发送、失败退回文字（D-008），已随 PR #71 实现，暂存表已在库版本 4 删除，测试用例文档尚未补对应条目）。
- 描述：每条可以：
  - 打开会话。
  - 回复：和 Orca 现有的给会话发消息一样，直接发进会话，发一次，显示送达状态（已送达、已发出未确认，或失败原因）；发不出去时文字退回回复框，不排队、不自动重发。只有「做完一轮，你还没看」能回复（给下一句指令，终端和聊天视图都可以）。其余只提供「打开会话」：
    - 等你批准：Orca 在智能体等权限确认时会拒绝写入，批准要在会话里点；
    - 等你回答：终端里的提问几乎都是选项菜单或对话框，Orca 在这时同样拒绝写入；用一段文字提问时智能体已经结束这一轮，会归到「做完一轮，你还没看」；结构化聊天会话拿不到原因，可能其实是批准请求；
    - 被卡住：登录、额度这类问题要在会话里解决。
  - 标记已看（E）：只把条目移出列表，不改变任何事实；同一个会话下次进入需要你的状态时会重新出现。
  - 暂缓（H）：1 小时、今晚、明天、下周，或自定义时间；到时间后条目回到列表（如果仍满足判定）。
  - 2026-11-02 补：这条「只有做完一轮能回复」只管一次性发送一句话的通道（首页「需要你」行、手机回复抽屉、打回、派活到空闲会话）。会话速览浮层（REQ-028）挂的是会话本身，输入走会话自己的通道，不受这条限制（D-014）。验收打回（REQ-024）把原因发给做完一轮的会话，没有时一键开新会话；直接派活到有做完一轮会话的工作区时，正文也按这条规则发给它（REQ-029）。
- 本机场景：回复后显示送达状态。
- SSH 场景：主机在联系范围内时与本机一致。主机未连接时与 Orca 现有的会话输入框一样：桌面回复框上方提示主机离线或重连中，发送失败时文字保留；手机回复框禁用并显示「重连中」。不暂存、不在恢复联系后自动发出。
- 验收标准：桌面和手机上各回复一次，看到送达；SSH 断开时回复，文字保留在回复框，恢复联系后可以再发。

### REQ-018 数据归属与跨机器

- 目标级别：P0；当前状态：部分实现（2026-10-26「只存桌面」版本已实现并验证，见 TC-013～TC-016、TC-025、TC-038；2026-10-28 改为任务库是每台 Orca 自己的资源（D-008），已随 PR #71 实现：桌面、`orca serve`、orcad 各开自己的库，SSH 真机证据在本机 `.docs/local-tasks-ui-validation/2026-10-30/ui-final/ssh/`，测试用例文档尚未补对应条目）。
- 描述：任务库和 Orca 的项目一样，是每台 Orca 自己的资源：桌面 Orca 存它自己项目的任务，配对服务器（`orca serve`）和 SSH 主机上托管的 orcad 服务器存它们自己项目的任务，每个 profile 一份。任务与工作区、会话的关联存在拥有任务的那台主机上。客户端（另一台桌面、局域网网页版、手机）用 Orca 现有的远程连接读写，和管理那台主机的项目、会话一样；只在主机在联系时读，不重连、不轮询。同一个 Orca 项目在多台主机上各有一份时，任务也各存各的，不合并、不同步（D-008）。
- 同一次写入在 24 小时回执窗口内使用同一操作号、同一方法与参数重试时不重复执行；窗口内发生超过 1000 次其他写入、桌面重启后也保持去重。不同方法/参数或损坏回执明确失败且不重做；写入时按时间清理旧回执（D-006）。
- 本机场景：任务数据和工作区都在本机。
- SSH 场景：SSH 主机上托管的 orcad 服务器拥有该主机上项目的任务库，数据文件在 SSH 主机的 Orca profile 目录里；桌面经现有连接读写，主机不在线时这台主机的任务显示为「未连接」，不读、不重连；恢复联系后重新读取。
  - 直连 SSH（经 relay，主机上没有 orcad）的项目，任务存在发起连接的桌面库里（2026-10-30 补记）。两台桌面经 relay 连同一台主机时，各存一份，互不可见；要共享，需改用 orcad 托管。
  - 2026-11-02 补：直连 SSH 工作区里的智能体回写进展（REQ-022）经 relay 写回桌面的库，桌面关着或断线时写入失败，智能体按任务说明把摘要写到文件继续干活，不重试。新增的 RPC、CLI 和事件类型按能力位 `local-tasks.v2` 探测；旧版本桌面和手机收到不认识的事件类型要忽略而不是报错，列为切片 3a 的开工前验证。
- 验收标准：桌面项目的任务只在桌面的库里；SSH 主机上 orcad 托管项目的任务只在 SSH 主机的库里，桌面和手机都能看到并编辑；SSH 断开时这些任务显示未连接，恢复后自动对上；两台桌面连同一台 orcad 托管的 SSH 主机时，看到的是同一份 SSH 主机任务。

### REQ-019 与 Orca 其他功能的衔接

- 目标级别：P2；当前状态：部分实现（2026-10-30 已接入，单元测试覆盖，真实界面未逐项验收）。
- 描述：本地任务像上游工作项一样，参与 Orca 的其他功能。
  - **PR 描述**：AI 生成 PR 描述时，带上工作区所属任务的标题和描述，作为不可信的上下文，不当作 issue 引用。只在执行主机上读它自己的任务库，不跨机器。直连 SSH 的 PR 生成上游本来就不支持，这里也不支持。
  - **工作区清理**：「工单来源」维度新增「本地任务」；挂了任务的工作区不再算「完全空」。来源隐藏或没有项目时不提供这个筛选项。
  - **CLI**：新增 `orca task` 命令组，包括 `list`、`show REF`、`current`（当前工作区所属的任务）、`comment REF 内容`、`status REF 状态名`。
    - 输出以标题为主；写入带操作号，改状态时带版本号，防止覆盖别人刚做的修改。
    - 主机没有任务库时，提示升级那台主机上的 Orca。
    - 2026-11-02 起新增（切片 3a～3c）：`create 标题 --parent REF`、`link REF --worktree 选择器`、`progress REF --file 文件`（REQ-022）、`update REF --title 标题`、`dispatch propose --file 提案文件`（REQ-030）。多行正文一律从文件读，参数里内联的多行文本会被 shell 转义弄坏，Windows PowerShell 还会把中文变成问号。
    - 来自 CLI 的写入不能进入已完成类别：`status REF 某个已完成类别的状态` 被拒绝，并写明「完成要在界面上点」（原则 5）。现在的实现接受它，要改。
    - `current` 先按会话关联找任务（终端里带 Orca 的会话标识时），找不到再按工作区；现在只按工作区找，在子任务的会话里会返回父任务。
    - 报错写给智能体看：状态被人改过时说明是谁、改成了什么，并要求这一轮不再改状态、改为留评论；状态名不对时列出这个项目可用的状态（借鉴 Multica）。
- 本机场景与 SSH 场景：PR 描述和 CLI 都由拥有任务库的那台 Orca 执行；配对服务器和 orcad 主机上的工作区，读它们自己的库。
- 验收标准：
  - 挂了任务的工作区生成 PR 描述时，能看到任务内容；
  - 清理弹窗能按「本地任务」筛选；
  - 在工作区终端里运行 `orca task current`，能看到所属任务。

### 从提出到验收：工作流迭代（2026-10-30 提出，2026-11-01 用户确认）

背景：用户反馈「从提出一个 issue 到完成，整条动线不流畅」，决策见 journal D-009。这次开发本身就暴露了几个断点：

- 反馈散落在聊天和截图里，没有逐条记录；
- 范围只在聊天里定，后来说「做完了」时对不上账；
- 进展用户看不到；
- 「完成」的标准只在执行方心里；
- 合入以后，用户的 App 里还看不到；
- 没有「用户验收」这一步；
- 中途发现的新问题没有记下来。

下面 REQ-020～REQ-025 补齐这条动线。2026-11-01 用户回复「都按建议」确认；2026-11-02 按方案评审修订了 REQ-022、REQ-024，并新增 REQ-026～REQ-030；同日用户定不要「完成标准」，REQ-021 取消（D-014）。分期见 §7 切片 3a～3d；代码等原型评审后再动。

```mermaid
flowchart LR
  A["提出（REQ-020）"] --> B["澄清：把描述写清（REQ-020）"]
  B --> C["拆解与定范围（REQ-023）"]
  C --> D["开始做（REQ-009）"]
  D --> E["执行与回写进展（REQ-022）"]
```

### REQ-022 执行中回写进展与最新进展

- 目标级别：P0；当前状态：未实现（2026-10-30 提出，2026-11-01 确认，2026-11-02 按方案评审修订，切片 3a；「生成摘要」排在 3d）。
- 描述：
  - **任务说明**：从任务发起的每个会话（开始做、开会话、派活、「+」），第一句指令末尾附一段任务说明，用户可以在设置里关掉；说明做成 skill 按需加载。内容：
    - 任务编号，以及「需要最新内容时运行 `orca task show 编号`」；指令里的标题和描述只是开工那一刻的快照；
    - 由对话派出的任务，开工后用 `orca task update --title` 改一个不超过 30 字的短标题；
    - 每一轮结束时用 `orca task progress 编号 --file 摘要文件` 写一条结果，分三段：做了什么、结论或产出、下一步或需要你什么；中途进展不用写，终端里说的话用户看不到（借鉴 Multica：每轮只发一条结果）；
    - 卡住时写明原因，然后结束这一轮；
    - 回写失败（主机不在联系，例如直连 SSH 的桌面关了）就把摘要写到工作区里的文件，继续干活，不重试、不等待；
    - 状态真的变化了才写；只回答问题时不改状态；交付最多到「待验收」，「完成」由人在界面上点；
    - 发现这次不处理的问题，用 `orca task create --parent 编号` 记下（REQ-025）。
  - **最新进展**：任务卡、任务模式的悬停卡和详情顶部显示「最新进展」，按优先级取值：
    1. 最近一条智能体回写的进展，写明来自哪个会话、什么时间，以及「需要你什么」；
    2. 没有回写时，取「轮次结束」记录：拥有会话的主机在会话状态变成「做完一轮」时，把 hook 上报的最后一句话落进任务库，每个会话只保留最近一条，卡上标注「最后一句话」。现在这句话只在主机内存里，重启、离线后就没了，所以要落库；
    3. 都没有时只显示会话状态，比如「工作中 · 12 分钟」；
    4. 父任务没有自己的进展时，取子孙里最近一条，并标明来自哪个子任务（REQ-012）。
  - **生成摘要**（切片 3d）：详情进展卡上的按钮，用户点了才生成，复用 Orca 生成 commit 信息和 PR 描述的那条管线，读这个任务下的会话记录，结果是一条来源为「Orca 生成」的进展。默认不自动生成。
  - 只显示智能体写的和它自己的最后一句话，不从会话内容推断（原则 4）。
- 本机场景与 SSH 场景：回写走 `orca task`，由拥有任务库的那台 Orca 执行，与 REQ-019 一致；直连 SSH 的回写经 relay 回桌面，桌面不在时失败并按上面的规则处理（REQ-018）；轮次结束记录由拥有会话的主机写入自己的库。
- 验收标准：开始做后，智能体每轮结束在任务上留下一条三段式进展，桌面和手机的任务卡都显示它；关掉回写的智能体做完一轮后，卡上显示标注为「最后一句话」的轮次结束记录，重启 Orca 后仍在；直连 SSH 的桌面关闭期间，智能体把摘要写进文件且没有重试。

- 目标级别：P0；当前状态：未实现（2026-10-30 提出，2026-11-01 确认，2026-11-02 按方案评审修订，切片 3c）。

  - 「需要你」里的待验收条目有「速览」和「去验收」：速览打开写了最新进展的那个会话（2026-11-03 补）。

    - 规则当前的判定，例如「PR #231 合并后按项目设置进入待验收」。

    - 「通过」：移到已完成类别的第一个状态，时间线记「你点了通过」；
    - 「打回」：回到进行中类别的第一个状态，必须写原因。原因记成评论；有「做完一轮」的会话时作为下一句指令发过去（多个都发，REQ-015 的回复规则）；没有能回复的会话时，一键用打回原因加任务说明开一个新会话（REQ-010），不只是提示。
  - 规则 2 只由桌面窗口读到 PR 状态时执行（REQ-013）：只用手机的用户要等桌面打开，待验收卡上写明。

- 验收标准：PR 合并后，任务出现在「需要你 → 任务在等你 → 待验收」；打回后做完一轮的会话收到原因、任务回到进行中；没有可回复会话时打回开出一个新会话，第一句就是原因。

### REQ-026 任务首页与任务模式

- 目标级别：P0；当前状态：未实现（2026-11-02 提出，方案已评审，切片 3a）。
- 描述：
  - **任务首页**：桌面默认打开任务页的「本地」来源。实现上沿用上游「恢复上次视图」，只加一个设置「启动时打开任务页」，默认开，关掉回到上游行为。首页自上而下：派活输入框（REQ-029）、「需要你」（会话在等你、任务在等你两组，REQ-014）、按状态分组的任务卡（沿用列表和看板）。任务卡以标题、状态、会话状态点、最新进展（REQ-012、REQ-022）为主，工作区和主机是次要信息，主机不在联系时写「未连接」。
  - **任务模式**：侧栏「项目」那一行加一个「按任务显示」图标按钮，放在铃铛前面；点了标题变「任务」、按钮高亮，再点切回；选择记在本功能的偏好里，不碰上游只在内存的侧栏视图状态。任务模式下「搜索、任务、自动化、手机端」入口保留，「项目」区换成任务树：
    - 树的内容是任务页那一列原样搬过来：需要你、全部、进行中、待规划、已完成、已取消，以及「项目」下的全部项目和各个项目；每行可展开；选中某行就是筛选，主区按它显示，左右始终一致。
    - 展开视图或项目看到任务，「需要你」下的任务带原因；展开任务看到它的会话（状态点加一句话），子任务嵌在父任务下；每深一层缩进 20px 并有竖向引导线；工作区不作为树的一层，只出现在悬停卡和详情的工作区卡里。

    - 主机未连接时任务标「未连接」，它下面的会话置灰。
    - 树用上游侧栏的虚拟列表行渲染，不另写滚动。
  - **任务视图**（任务模式下选中任务）：任务是主体，会话从属。
    - 标签栏：「概览」固定第一，然后是这个任务和它子任务的会话各一个标签（子任务的标签带子任务标题），最后是「+」（REQ-010）。
    - 点任务（树或列表）一律打开「概览」，不自动跳到会话标签；有会话在等你时，「现在」卡先显示「在等你什么」，带「速览」。
    - 点侧栏里的会话：打开所属任务的概览，并打开这个会话的速览浮层（REQ-028）；浮层里「展开」是完整会话，「全屏」才切到它的标签。
  - **概览的内容**（2026-11-02 用户看原型后定：只回答「现在要我干什么、做到哪了、标准是什么、怎么进去」，其余减掉）：
    - 头部：标题；属性 chips 一行（状态可点改；优先级、标签、上级任务设了才显示）；工作区一行（名称、主机、改动统计、PR，没有的项不显示，点开有「打开工作区」「查看更改」，没有工作区时写「还没有工作区」）；一个主按钮按状态变（没有工作区 → 开始做；有工作区 → 开会话；待验收 → 验收；已完成或已取消 → 没有）；「…」菜单：设为目标（聊天型置灰并写原因）、取消任务、删除、复制链接、改标题。右栏取消，创建和更新时间放到动态底部。
    - 「现在」卡：唯一一张卡。待验收的验收条在最上面（REQ-024）；在等你什么（有才显示，带速览）；最新进展（有才显示；「全部进展 N」只在有记录时显示，「生成摘要」只在有会话内容时显示）；每个会话一行（智能体、终端或聊天、所属子任务、状态、一句话、速览）。没有会话也没有进展时只有一行「还没有会话」。
    - 描述、子任务：有内容才显示，为空时只有「添加」小链接。没有「完成标准」块（D-014）。
    - 动态：按 REQ-005 的 2026-11-02 规则，系统事件折叠。
    - 界面里不出现需求编号和机制说明。
    - 关闭会话标签就是关闭会话，和工作区模式一样；两种模式下是同一个标签，一边关了另一边也没了。
    - 会话所在主机未连接时标签置灰，悬停写明原因。
    - 实现：任务视图是任务工作区的标签表面，标签栏按任务过滤，再加「概览」伪标签；不另造任务标签集合，终端不重新挂载（上游标签必须属于工作区）。任务没有工作区时只有「概览」，头部按钮是「开始做」。
  - 任务模式下任务首页没有二级导航列，派活输入框、列表、看板占满宽度。
  - 本地任务来源在设置里隐藏时，任务模式按钮、首页设置、派活输入框都不出现（REQ-008）；「按任务分组」的去留见 REQ-016。
- 本机场景与 SSH 场景：树和任务视图读各台主机自己的库（REQ-018）；SSH 工作区的会话标签和速览与本机一样；主机不在联系时置灰并写明原因，不重试，恢复联系后只重读一次。
- 验收标准：切到任务模式后点「需要你」，主区只剩等你的任务；展开 ORC-41 看到它的会话，点会话打开概览加速览浮层，点「全屏」切到标签；关闭标签后工作区模式里它也没了；切回工作区模式与改动前一致。

### REQ-027 新建任务一次流程

- 目标级别：P0；当前状态：未实现（2026-11-02 提出，切片 3a）。
- 描述：一次流程、两屏，不重做上游的新建工作区弹窗。
  - **第一屏**：标题（必填）、描述、状态等属性（没有完成标准，D-014），加「在哪做」三选一：
    - 已有工作区：当场选（可搜索，列出所有在联系的主机），下面出现「开工」段：智能体（默认你的默认智能体，可以选「先不开」）、第一句指令（默认「按任务说明开始」）、发送方式（默认直接发送）；主按钮「创建并开工」，建好任务、关联工作区、开会话，停在任务视图；
    - 新建工作区：主按钮「创建，下一步新建工作区」；
    - 稍后再定：主按钮「创建」。
  - **第二屏**（选新建工作区时）：Orca 现有的新建工作区弹窗，「创建自」预选这个任务（REQ-009），智能体和第一句指令在那里填；发送方式按设置「从任务发起的会话」执行，弹窗里不加选项。创建完成后关联并停在任务视图；创建失败或取消时任务保留、不关联。
  - 从「记成任务…」进入时，标题和工作区预填（REQ-011）。
- 本机场景与 SSH 场景：第二屏的运行位置可以选 SSH 主机，与 REQ-009 一致；主机未连接时「已有工作区」里它的工作区置灰并写原因。
- 验收标准：建一个任务并选新建工作区，两屏走完后任务视图里有工作区卡和一个会话；选稍后再定时任务视图只有「概览」和「开始做」。

### REQ-028 会话速览

- 目标级别：P0；当前状态：未实现（2026-11-02 提出，切片 3a）。
- 描述：速览就是对话的小边框模式（2026-11-02 用户定，D-014）：同一个会话挂在右侧浮层里，窄一点，什么都能做。首页列表、任务概览、任务模式侧栏都从这里看会话；任务模式里点会话先开速览，不直接切标签；只有明确要全屏才变成独立标签（D-012、D-013）。
  - 桌面是一个浮层两档宽度，加全屏；同一个终端或聊天实例只换宽度，不重新挂载：
    - 速览：点会话、点「速览」、侧栏树点会话进入；窄，约 420px；主区往左让开、在剩余宽度里重新排版，任务内容（含验收条和「通过」「打回」）不被遮住，验收时可以一边看会话一边点通过（2026-11-03 补）；真实终端或聊天挂进来，**完整可操作**：终端有输入行（打字、方向键选菜单、批准），聊天有完整 composer（选项按钮、输入）；「停止」；头部有「加宽」「全屏」「关闭」。
    - 加宽：速览里点「加宽」；宽，约主区三分之二，盖在任务上；同一个实例，只是更宽；头部「收窄」「全屏」「关闭」。
    - 全屏：任一级点「全屏」；任务模式下切到任务视图里这个会话的标签，工作区模式下跳到工作区的那个标签；标签顶部一条「收回侧边」回到浮层。
  - 浮层里没有单独的回复框，也不受 REQ-015「只有做完一轮能回复」的限制：那条说的是一次性发送一句话的通道，浮层里挂的是会话本身，输入走会话自己的通道。首页「需要你」行的「回复」就是打开速览并把光标放进输入；待验收行也有「速览」（REQ-024）。
  - 任务有不止一个会话时（含子任务的），浮层头部会话名旁有下拉，可以在这些会话之间切换；只有一个会话时不显示（2026-11-03 补）。
  - 聊天型会话复用结构化会话视图；终端型会话把真实终端挂进浮层（Activity 页 portal 终端的做法），不是文本快照，颜色和滚动都在。显示状态与「在等你什么」。窄态下终端按浮层宽度重排，和拖分屏一样。
  - 手机是底部抽屉，里面挂真实的会话视图，半屏就能回答；上拉到全屏就是会话页。
  - 读取规则：浮层打开且主机在联系时才读，有推送跟随推送；主机不在联系时显示上次读到的内容并写「未连接」，不重试。
- 本机场景与 SSH 场景：一致；SSH 主机断开时浮层保留旧内容并写明，不发读请求，恢复联系后只重读一次；输入走会话原有的通道，主机不在联系时和标签页里一样不可输入。
- 验收标准：从首页「需要你」速览 ORC-38，在窄态里直接选 Codex 的选项并送达；速览工作中的终端会话能打字；全屏后标签顶部能收回侧边；SSH 断开时浮层写「未连接」且没有读请求。

### REQ-029 派活输入框、@ 提及与直接派活

- 目标级别：P0；当前状态：未实现（2026-11-02 提出，切片 3b）。
- 描述：
  - **输入框**：在任务首页顶部（手机在本地任务页顶部，REQ-017），占位「要做什么？@ 一个工作区或仓库，说一句话」，回车派活；右侧「展开对话」进入通用对话（REQ-030）；「派活 | 只问」两段开关，默认派活。Cmd+J 加「派活…」动作（REQ-007）。
  - **@ 提及**：候选按类型分组：工作区、仓库、任务、主机；来自所有在联系的主机，不在联系的置灰并写原因；选中成 chip，chip 存确定的 id，不是文字。含义：
    - @工作区：在这里派活；
    - @仓库：为这个任务新建工作区再派活（名称来自编号和标题，复用「开始做」）；文件夹项目只能选已有的文件夹工作区；
    - @任务：在它下面建子任务，会话开在它的工作区；它没有工作区时先走开始做；
    - @主机：不是派活目标，选中后候选只剩这台主机的仓库和工作区，输入框旁出现可去掉的筛选标签。
  - **只问**：不建任务，把 chip 里的工作区作为上下文交给调度会话（REQ-030）只读回答。
  - **直接派活**（提及了明确的工作区或仓库，Orca 直接执行，不经过额外的模型）：
    - 项目归属：工作区所在仓库只挂在一个项目下就用它；挂在多个项目下用最近派过活的那个，卡上可改；没有项目时卡片先出「为仓库 X 建一个项目？」，确认后建项目再派（与 REQ-001 的推荐一致）。
    - 工作区不属于任务：建任务（标题取正文第一句、截 60 字，原句进描述；Orca 不另起模型调用起名，由智能体按任务说明改短标题），关联工作区，用默认智能体开会话，第一句指令是正文加任务说明（REQ-022）。
    - 工作区属于任务 T：T 下有「做完一轮」的会话时，把这句话发给它当下一句指令，不建任务，T 的时间线记「由对话追加指令」，卡上给「改为建子任务另开会话」；没有空闲会话（都在工作中、等你批准、等你回答、被卡住，或没有会话）时在 T 下建子任务、另开会话，卡上写明同一工作区里还有会话在工作。
    - 多个工作区：建父任务，每个工作区一个子任务，各开会话；工作区要在同一台任务库上，否则走调度会话。
    - 已派活卡：任务、会话、速览、10 秒撤销。撤销停会话、删任务；新建的工作区保留并提示可删；已改的文件不回滚，卡上写明；编号不复用（REQ-002）；要在拥有库的那台 Orca 删任务、在执行主机停会话，主机不在联系时写明「没有撤销」，不排队。
  - 主机不在联系时派活按钮置灰并写明原因；不排队、不重试。
- 本机场景与 SSH 场景：目标主机由 chip 决定，任务写进拥有工作区的那台 Orca 的库（直连 SSH 是桌面的库，REQ-018），会话在那台主机上启动；SSH 主机断开时它的候选置灰。
- 验收标准：「@orca/docs-typo 把 README 里过期的链接修一下」建出任务并开会话，10 秒内撤销后任务消失、会话停止；「@orca/perf-startup 顺便看看首屏渲染」发给了做完一轮的 Claude，没有新任务；没有项目的仓库派活时先建项目；「只问」不留任务。

### REQ-030 调度会话、提案与对话历史

- 目标级别：P1；当前状态：未实现（2026-11-02 提出，切片 3c）。
- 描述：
  - 没有提及在哪做、或要拆解、比较、查找的请求，交给调度会话：桌面 Orca 浮动伪工作区里的一个普通智能体会话，用默认智能体，附「调度说明」skill：理解请求、提方案、用 orca CLI 只读查询，不自己干活。
  - 要新建的东西（任务、工作区、会话）先用 `orca dispatch propose --file 提案文件` 提交结构化提案，对话里渲染成提案卡（每项可改、可去掉）；用户确认后由 Orca 直接建任务、关联、开会话，不再经过调度会话，也不多一轮模型调用；设置里可改成「直接执行」。不让智能体输出约定格式的文字再解析。
  - 调度会话只在桌面有；手机经配对桌面；局域网网页客户端没有（上游不允许在浮动工作区里开会话），只能直接派活。
  - 对话历史按天分组，每段对话能看到它派出的任务卡；由对话派出的任务，时间线第一条「由对话派出」能跳回那段对话；只聊天没派活的对话不留任务。上游没有会话级元数据，「这段对话派出了哪些任务」存在本功能的库里。派出到别的库（orcad 主机、配对服务器）时，任务在那台库里，对话在桌面，对方库里只带对话 id。
- 本机场景与 SSH 场景：调度会话跑在桌面；派活到 SSH 主机或配对服务器时用 CLI 的 `--host`、`--environment` 指定目标，任务写进拥有工作区的那台 Orca 的库。
- 验收标准：「看看 orca 里哪些工作区的 PR 还没合，各开一个任务跟进」得到提案卡，去掉一项后确认，剩下的各建一个任务并开会话；对话历史里能回到这段对话；「只问」得到回答且没有任务。

## 6. 边界情况

| 情况                         | 处理                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| 关联的工作区被删除           | 任务上显示「工作区已删除」，可以重新开始做                                                    |
| 会话关闭了                   | 会话行显示「已结束」，可以再开一个                                                            |
| Orca 重启后找不到记录的会话  | 显示「找不到这个会话」，提供「打开工作区」                                                    |
| 删除任务                     | 只删任务记录，工作区和会话都不动                                                              |
| 一个工作区想关联第二个任务   | 不允许，提示它已属于哪个任务（写任务标题）                                                    |
| 任务移到别的项目             | 整棵子树一起移，工作区关联保留，旧编号仍能打开（REQ-004）                                     |
| 项目对应的仓库从 Orca 里移除 | 项目和任务保留，「开始做」不可用并提示仓库已移除                                              |
| 执行主机断开                 | 任务照常管理；会话和 PR 显示「无法确认」；「开始做」「开会话」不可用                          |
| 派活到正在工作的工作区       | 建子任务另开会话，卡上写明同一工作区里还有会话在工作；有做完一轮的会话时改为发给它（REQ-029） |
| 派活的仓库没有项目           | 卡片先出「为仓库 X 建一个项目？」，确认后再派（REQ-029）                                      |
| 撤销派活                     | 停会话、删任务，工作区保留，已改文件不回滚，编号不复用；主机不在联系时写明没有撤销            |
| 取消或删除有在跑会话的任务   | 确认框里给「同时停止 N 个会话」勾选，默认不勾（REQ-004）                                      |
| 直连 SSH 的桌面关闭          | 智能体回写失败，写文件继续、不重试；手机看不到这台桌面库里的任务，提示写明（REQ-018）         |

## 8. 待确认问题

以下是本稿的默认做法和理由，用户确认或修改后再定稿。

1. 文件夹项目的「开始做」：只关联已有的文件夹工作区，不新建（已写进 REQ-009）。文件夹没有分支和 PR；替用户新建目录等于做「任务目录」，本版不做。
