# 终端对话转聊天退出判定

## 1. 背景与目标

终端里跑着 Codex 或 Claude 时，用户可以把同一段对话转到聊天界面继续（窗格标题栏的「在聊天界面中继续」，或 Session History 的「在新聊天中恢复」）。为防止两个进程同时写同一段对话，执行主机会先核查终端里已经没有能写这段对话的程序：shell 回到前台，且一个任务都不剩（前台、后台、挂起都算）。这个核查来自上游 #29242（2026-10-19）。

2026-10-23 用户在 Movo 工作区反馈「一直报错，切不了 chat view」，提示是「Orca can't confirm Codex has exited in its terminal…」。复现结论：macOS 上 Orca 通过 `/usr/bin/login` 包装启动每个终端（TCC 隐私授权归属），终端的根进程是 `login`，shell 是它的子进程；核查直接要求根进程是 shell，拿到 `login` 就永远不通过。所以 **Codex 退出后照样被拒绝**，只有关掉整个终端才行。e2e 测试统一关掉了这层包装（`ORCA_DISABLE_MACOS_LOGIN_SHELL=1`），所以测试一直没发现。

目标：agent 真正退出后，能在聊天界面继续同一段对话；agent 还在运行或终端里还有任务时，保护照旧。

## 2. 用户场景

用户在 macOS 的 Orca 里开终端运行 Codex，聊了几轮后想换到聊天界面。Codex 运行中点切换，Orca 提示先停掉终端里的程序；用户退出 Codex，shell 回到提示符，再从 Session History 选「在新聊天中恢复」，聊天界面打开并载入原对话。

## 3. 范围

### In Scope

- 执行主机核查本机终端是否「只剩 shell」时，穿过 macOS `login` 包装找到真正的 shell 再检查。
- 回归测试：login 包装下 agent 运行中拒绝、退出后放行、login 下多出其他子进程时拒绝。

### Out of Scope

- 「Codex 运行中点按钮却一定失败」的交互问题（例如点按钮时代为退出 agent）：属于新交互，需单独设计。
- 远程主机和 SSH 工作区支持转聊天：上游只对本机执行的终端会话提供这个动作，本需求不改变。
- `src/main/runtime/run-terminal-shell-alone.ts` 中写法相近的另一处检查：它先走 provider 的前台确认，用户可见影响未证实，不在本次范围。

## 4. 需求点

### REQ-1 agent 退出后可以转到聊天界面

- 目标级别：P0；当前状态：已实现（2026-10-23 单测与本机真机验证通过，见 TC-1、TC-2、TC-3）。
- 描述：终端经 macOS `login` 包装启动，agent 已退出、shell 在前台且没有任何任务时，从窗格按钮或 Session History 转到聊天界面不得被拒绝，聊天打开后载入原对话。核查在运行这个终端的机器上执行。
- 本机终端：按上述规则放行。
- SSH 工作区与远程主机终端：客户端不提供这个动作，行为与修复前相同（见 REQ-3）。

### REQ-2 保护不放松

- 目标级别：P0；当前状态：已实现（2026-10-23 单测与上游回归套件通过，见 TC-1、TC-3、TC-5）。
- 描述：agent 仍在运行，或 shell 下还有任何任务（前台、后台、挂起），或 `login` 下除 shell 外还有其他子进程时，仍然拒绝。终端根进程本身就是 shell 的情况（Linux、关闭包装的 macOS）规则不变；Windows 走单独的分支，不受影响。
- 本机终端：如上。
- SSH 工作区与远程主机终端：不涉及（见 REQ-3）。

### REQ-3 SSH 工作区与远程主机行为不变

- 目标级别：P1；当前状态：已实现（2026-10-23 隔离 SSH 真机修复前后对照一致，见 TC-4）。
- 描述：SSH 工作区（由远端 orcad 执行）和配对远程主机上的终端会话，窗格上不出现「在聊天界面中继续」，Session History 不出现「在新聊天中恢复」，修复前后一致。修复只改变执行主机检查自己本机终端的方式，不改任何客户端与主机之间的协议。
