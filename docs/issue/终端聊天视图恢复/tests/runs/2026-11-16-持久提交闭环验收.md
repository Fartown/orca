# REQ-1807～1810 / TC-1816～1825

## 结论与证据链

普通 Codex PTY Chat 由桌面 main fsync 原文及固定目标后交接，执行主机复用 durable terminal.send 整体提交，真实 user 转录对账后才撤下待确认。回执丢失时保持原文；renderer/App 重启及 SSH 主机服务重启后查询同一 request ID，没有第二次 terminal.send。文件身份与原字节边界 fingerprint 不连续时禁止确认。

真实 Codex 为 0.167.0-alpha.4.1，模型响应使用执行主机上的独立 Responses SSE fixture。没有手写 JSONL、伪造 providerSession 或手工 setAgentStatus；由生产启动链与生产 hook 建立会话，再读回模型请求、真实 Codex JSONL、outbox 和 DOM。模型 fixture 不代表外部模型服务可用性或严格数学 exactly-once。

## 资源所有权与范围

客户端 outbox 属客户端临时 profile。Mini 的 PTY、Codex HOME、图片、transcript、mutation ledger 属 `/tmp/orca-durable-host-HbuJNZ/` 独立执行主机目录；测试模型在 Mini 127.0.0.1:53814，Orcad 在 Mini 127.0.0.1:53897，客户端 127.0.0.1:53897 是单独 SSH local-forward。服务重启只操作本轮独立 PID/profile。SSH 验证覆盖经 SSH 隧道访问 managed/paired runtime，legacy raw relay 明确拒绝新可靠提交并保留草稿，不新建或迁移用户终端。

客户端、主机和旧移动端混合版本通过可选能力、参数和 receipt 内容兼容；没有新 stream opcode。无 SQLite/旧能力不进入新发送。服务重启后若没有当前 providerSession 强证明，不能用历史恢复行冒充 live 身份；此时保留输入并拒绝新提交。已经执行的原请求仍可通过 ledger 与转录对账。本轮不声称新增了无 providerSession 终端的首次会话创建能力。
