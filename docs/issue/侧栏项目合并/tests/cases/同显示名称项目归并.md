# 同显示名称项目归并测试规格

来源：[当前需求](../../requirements/requirement.md)与[最小改动方案](../../solutions/项目分组最小改动方案-10-23.md)。实际执行记录单独放在 tests/runs，不在本文保存执行状态。

| 功能               | 关联需求                  | 测试点                                                 | 用例   |
| ------------------ | ------------------------- | ------------------------------------------------------ | ------ |
| 同名加入与改名分开 | REQ-611、REQ-612          | 三主机普通目录、名称精确比较、名称与路径区分           | TC-611 |
| 原仓库规则         | REQ-614                   | 同仓库不同名、不同 provider 同名、原独立 checkout 例外 | TC-612 |

## TC-611 同名加入与改名分开

- 优先级/类型：P0，逻辑与真实 DOM。
- 前置：本机、mini、dbox 各有一个独立普通目录项目和工作区；本机/mini 显示名称为 workspace，dbox 为 workspaces，记录原路径和标识。
- 操作：按项目显示；把 dbox 显示名称改为 workspace，再改为 workspace-dbox；另检查首尾空白、大小写和空名。
- 预期：开始为两项，本机与 mini 共一项；改为同名后同一头下三个原工作区；改为不同名后只分开 dbox。仅去首尾空白，大小写不同不合并，空名不触发新归并。路径和工作区名称分别保留。

## TC-612 保留原仓库规则

- 优先级/类型：P0，逻辑及 Local/SSH DOM。
- 前置：同仓库的两个主机目录显示名称不同；另准备不同 provider 同名项目及同一执行面的两个独立 checkout。
- 操作：查看项目区块与原项目身份。
- 预期：同仓库按原规则合并，即使不同名也不因改名拆开；不同原生仓库同名可组合展示，原身份保留；原先需要区分的同执行面 checkout 不被同名规则强行合并。其他副本别名不触发传递串组。

## TC-613 原生身份与业务归属保留

- 优先级/类型：P0，结构与副作用检查。
- 前置：记录 Repo、原生 Project/setup、工作区及原归属索引，准备同名目录。
- 操作：计算名称组合、加入、改名拆分，并读取原对象。
- 预期：纯展示计算不改任何输入；native projectId、路径、repo/worktree/instance ID 不变，原 ownership index 保留。文件、Git、任务、AI Vault、快捷命令等不接收展示键；无人工成员名单或新归属 RPC 写入。

## TC-614 明确菜单目标并保留终端

- 优先级/类型：P0，真实 Electron/IPC/RPC。
- 前置：同名组包含本机和远端目录，选中远端工作区并建立终端，记录原 PTY/实例；目录的已知 upstream 状态为 null。
- 操作：从合并头打开操作，选择带远端路径的目录，进入既有设置并编辑显示名称。
- 预期：目录选择明确显示电脑和路径；原有设置/新建/删除等操作以选定原目录为目标，不默认作用于所有成员。owner 回读仅 displayName 改变；原工作区与终端身份保留，终端仍连接、可写。

## TC-615 排序、折叠与导航

- 优先级/类型：P0，逻辑与 DOM。
- 前置：准备同名区块、原手动顺序和折叠键。
- 操作：计算新列表；折叠/展开合并头；检查原区块全部折叠时的继承、展开后的键清理；检查显示顺序和工作区分组键。
- 预期：合并头沿原手动 anchor 排序；原过滤与工作区身份保留。折叠与展开只控制显示；展开可清理导致继承折叠的源键，不反复自动折叠。渲染、快捷键列表和 reveal 使用同一名称区块键；真实原项目归属索引不改。

## TC-616 移动端共享归并

- 优先级/类型：P0，移动列表模型。
- 前置：手机收到含原项目/目录的 catalog，三主机各有独立同名普通目录。
- 操作：生成列表并变更其中一个显示名称。
- 预期：同名区块合一，原排序下的三个工作区身份保留；改名后对应区块分开；原 catalog 和工作区输入不变。旧端仍能使用原字段和原 ID。

## TC-617 SSH、原执行目标与名称持久化

- 优先级/类型：P0，隔离应用与真实 SSH 传输。
- 前置：当前客户端和独立 owner，通过已认证 SSH 转发连接；两边有普通目录与同仓库 Git 目录。
- 操作：加载归并列表，选择远端工作区，编辑远端目录名称，owner 回读并重载客户端。
- 预期：普通目录按同名归并；同仓库 Git 的不同显示名称保持原自动归并；选中远端时执行 host 不变。名称在 owner 及重载后保留；原路径、工作区项目 ID/实例保留；名称功能不发起额外直连 SSH。测试授权公钥与临时环境能精确清理。
