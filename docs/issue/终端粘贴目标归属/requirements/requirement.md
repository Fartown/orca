# 终端粘贴目标归属

状态：ready。外部来源：[Fartown/orca#137](https://github.com/Fartown/orca/issues/137)。

## 背景与用户场景

用户在 macOS 按 ⌘V 粘贴时频繁看到焦点变化错误，已明确确认入口。受控实测：同一终端内 helper 节点替换会误取消；后续成功仍保留旧红条。受控结果不能证明用户截图当次发生了节点替换。

## 范围

In Scope：快捷键/paste-event/应用菜单共享的异步粘贴归属和该操作的错误恢复。本地与 SSH，git worktree 与 folder workspace。Out of Scope：改 agent CLI、自动重发、抢系统焦点、宿主连接重试或恢复策略。

### REQ-001 快捷键使用实际聚焦终端

- 当前状态：已实现。
- 按实际 xterm 焦点确定 pane；读取剪贴板前固定该 pane、transport、PTY 与初始焦点归属。
- 同一目标内部 helper 节点替换和短暂 blur 应保持可粘贴；真实移到其它输入目标或目标绑定变化仍取消，不能向新 PTY 改投。

### REQ-002 错误归属与恢复

- 当前状态：已实现。
- 区分焦点变化、目标变化与失去连接；后续成功只清理同 pane 的粘贴错误，保留其它 pane 和无关终端错误。
- 失败必须向剪贴板协调器返回拒绝，不能被其视作成功。

### REQ-003 执行宿主与兼容

- 当前状态：已实现。
- 客户端拥有 DOM、剪贴板读取和归属快照；执行宿主拥有 PTY、工作区与实际 stdin 接收文件。SSH 测试的 127.0.0.1:2222 属于客户端机器上的隔离 sshd 服务，工作区文件经 SSH 在宿主端访问。
- 本地和 SSH 实际接收内容须恰好一次；测试 App 的环境变量、profile、服务端口和所有证据须隔离，不影响用户会话。
- 不改 RPC/stream，不新增能力要求；兼容独立更新的客户端/宿主，复用跨平台快捷键与已有移动端粘贴路径。

## 验收标准与已确认结论

REQ-001～003 对应上述可判断行为；单测检查异步前后的目标身份及拒绝，真实 App 检查实际 stdin 与窗口未显示。本轮没有新增交互设计事实源。
