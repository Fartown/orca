## 4. 失败记录与覆盖边界

- 最初 E2E 把改名分开后的原来源折叠状态误期望为展开；修正规格为读取原键，实际点击原头展开。
- 一次夹具只通过 setState 写入来源折叠键，被异步 UI 偏好读回覆盖。夹具改为先用原 window.api.ui.set 保存来源键，再加载列表；未修改产品的折叠实现。
- 额外 terminal.read 断言只读到旧提示符，实际客户端截图和终端缓冲区已包含执行输出；这些失败日志保留为 minimal-integrated-{final,input,pane}-e2e。该 RPC 读回差异的原因未定，本轮未修改终端实现；最终以原客户端输入链和实际渲染缓冲区读回唯一执行结果为准，不把 connected/writable 标志单独当作输入成功证据。
- pnpm 自更新生成的两份锁文件增量已核对并恢复；架构门禁初次因此失败，最终在无依赖变化的工作树上重跑。没有放宽门禁。

三主机画面使用 catalog 夹具，不连接用户 mini/dbox；真实 SSH 场景使用独立 owner 和本机 root sshd 的 127.0.0.1:2222 转发。客户端和 owner 各有隔离 HOME/profile，目录、端口、配置和服务属于夹具；名称归类本身不读取主机或发网络请求，不部署 .orca-remote。

`minimal-final-verified-e2e-ssh-cleanup.json` 确认认证成功、退出 0、authorized_keys 原字节精确恢复、测试公钥移除。原生手机 UI、新 SSH 服务安装、异机网络故障和所有旧端二进制组合未实测；无 wire/schema 变化。用户正在使用的 App、在线名称、目录与会话未修改。
