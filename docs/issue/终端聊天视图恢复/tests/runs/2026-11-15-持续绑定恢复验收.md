# REQ-1804 / TC-1805～1808

客户端源码基线为 Fartown/fork/integration `bcacdce2c34daa8d91690b15bc2e46dddaa56358`；旧版对照为真实安装包 `1.4.214-preview.81`。全部 Electron 窗口隐藏、不聚焦，HOME/userData 隔离。原用户窗口与 mini 服务未重启。

## 原因与对照

旧版 `requestTerminalPaneRecovery` 在任一 tab 索引为 chat 时无条件返回 false。它沿用了 structured native chat 的 provider 交接保护，但 fork 恢复的同终端 Chat View 仍依赖 PTY，因而正常恢复也被拦截。4 项新增回归在改动前失败。

真实配对主机对照：仅断开隔离客户端的 viewer，主机进程保留。输入框持续禁用 12 秒，聊天模式调用真正的恢复函数返回 false；切到终端后调用相同请求返回 true 并恢复。单独切终端等待 6 秒未自动恢复，不能把这个对照写成“切换本身即恢复”。故障注入证明恢复准入缺陷，不证明历史截图第一次丢绑定的触发。

## 修复版真实界面

| 链路                      | 故障和恢复入口                                   | 结果                                                    |
| ------------------------- | ------------------------------------------------ | ------------------------------------------------------- |
| 本地 Git 工作区           | detach 该 viewer 后调用真实恢复函数，未 kill PTY | chat 保持，原 PTY 重新附着，DOM contenteditable=true    |
| mini 配对                 | disconnect 该 remote viewer 后调用真实恢复函数   | chat 保持，原 handle、PTY、incarnation 保持，DOM 可编辑 |
| 经真实 SSH 访问 mini 服务 | 同上，唯一配对 endpoint 经 SSH 转发              | chat 保持，原终端身份保持，DOM 可编辑                   |

每轮均先采到 noPty 提示及 contenteditable=false，再在恢复后连续等待 12 秒确认。使用 CDP 检查真实 bundle 作用域调用现有恢复函数，不替换该函数、不模拟主机成功响应；测试不发送输入。该验证证明准入和重挂链路，未声称覆盖所有生产信号的自动触发。

## 主机归属与限制

- 本地 fixture、transcript、PTY 在客户端机器的临时目录和隔离实例；不读取或写入用户原终端。
- SSH 客户端转发端口是客户端 `127.0.0.1:46768`，目标是 mini 的 `127.0.0.1:6768`；经 mini 现有 SSH 服务建立隧道。工作区、transcript、provider 和原终端归 mini。
- 只在隔离 profile 将 endpoint 指向转发口，沿用配对身份，未更改用户配置、主机服务和协议。关闭验证隧道不影响用户连接。
- 文档预设的本机 root sshd 实测不存在；已有 2222 是用户级 sshd，sudo -n 需要密码，Docker 不可用。因此使用真实 mini SSH 隧道，不把它说成原生 SSH relay 自动部署验收。
- 新准入为纯客户端逻辑，沿用原主机连接层，不增加主机读取、轮询或重试器；旧 peer 和移动端无需升级协议。folder workspace 由同一恢复准入单测覆盖。
- 测试修正过配置 schema、fetchRepos 参数和真实 worktree ID 的激活方式，属于验收 fixture 问题，未为此修改产品代码。
