# 手机打开工作区终端身份恢复 需求澄清

## 1. 背景与目标

用户报告手机打开工作区后，电脑端反复增加空终端。调查在源码基线 `cd5b6fca` 上将 18 条现场事件关联到两个仍存活的原 PTY；隔离实例在已访问的本机 folder repo 中复现三次打开新增三个 shell。目标是手机打开工作区时保留原终端的标签、窗格与进程身份，避免重复生成空终端。[事实摘要](../research/手机激活终端认领证据.md)记录证据及限制。

## 2. 用户场景

用户在电脑上已有工作区和终端，手机打开该工作区；电脑窗口投影可能暂时缺少该终端。再次在手机打开同一工作区、从其他窗口查看或恢复远程连接时，应继续使用原终端。场景包含本机、直连 SSH、配对 runtime、Git worktree 与 folder workspace。

## 3. 范围

### In Scope

- 手机打开工作区触发的后台 live PTY 认领和桌面投影恢复。
- 原终端已关闭、归属冲突、执行主机失联、PTY 退出或身份变化时的安全结果。
- 本机与 SSH 执行主机、Git 与 folder 工作区、旧 peer 兼容边界。

### Out of Scope

- 自动删除历史产生的空终端。
- 重写普通新终端创建或已确认退出后的常规 cold restore。
- 新增产品 UI 或改变手机打开工作区时电脑端的导航、焦点行为。

### 来源与结论分类

- **用户要求**：解决手机打开工作区使电脑端反复增加空终端，保留原终端会话。
- **代码与运行事实**：现场关联 18 条新增标签；受控已访问 folder 场景三次打开增加三个 shell；只恢复原 tab/leaf 身份的对照三次均未新增 shell，PTY/PID/incarnation 保持一致。
- **Agent 拟议策略，待方案评审与实施验证**：由执行主机权威检查关闭及归属，恢复 canonical surface，沿用 stable pane 严格认领，并封住此次自动 live 认领失败时的新建回退。此策略不是已确认业务规则，SSH 和自然手机操作尚未验收。

## 5. 需求点

以下均为目标行为，**当前状态：未全量实现、待验收**。此前 10 处接缝技术方案的设计批准已撤回；[临时修复方案](../solutions/手机工作区原终端身份恢复方案.md)只新增有效 recorded、桌面缺原 tab、单 leaf 的身份恢复分支，其他情形保留上游兜底。该窄版已通过代码 review，并有局部本机/SSH 运行证据；多 leaf numeric、任意 unknown、所有关闭微竞态、遗留 relay 和 mixed peer 仍待处理或验证。不得把局部 slice 写成 REQ-001～005 全部已实现。

### REQ-001 手机激活不增生新 shell

- 当前状态：待实现。
- 描述：手机打开已有工作区、遇到仍 live 的原终端时，重复激活不得为同一原终端增生空 shell；恢复合法原标签可以一次性增加窗口模型中的标签。
- 业务规则：窗口图缺标签不能单独作为创建全新终端身份的理由；后台创建不立即在电脑端 reveal 标签，后台唤醒不抢电脑导航或焦点。
- 本地验收：已访问与未访问的 Git/folder 工作区连续三次及并发重复激活，同一原终端新增 shell 为 0、恢复后的原 surface 不重复；不同后台挂载状态结果一致。
- SSH 验收：直连 SSH Git/folder 工作区重复上述激活，SSH 机与电脑本机均无增生 shell，原 surface 只恢复一次，不改变桌面导航或焦点。

### REQ-002 原会话身份、内容与布局连续

- 当前状态：待实现。
- 描述：认领仍 live 的原终端时，保留原 tab/leaf、PTY/incarnation、PID、会话内容和 canonical 布局；不扰动健康 sibling、选中状态或原 Sleeping done 记录。
- 业务规则：后台创建保留不即时桌面 reveal 的语义；后续 wake 或用户显示时才以原身份投影。这是一段原会话的连续投影，不是新进程或新 `--resume` 会话；split 多 leaf 均按原成员关系恢复。恢复后新建、关闭、split 及窗口会话保存仍须保持 canonical 成员关系。
- 本地验收：数字本地 PTY、daemon provider、未访问/landing、split 多 leaf 场景中，原 tab/leaf/PTY/incarnation/PID 不变；静止内容和后续输出可见，健康 sibling 与选中状态不变；恢复后新建/关闭/split，经过 patch/set、unload 和重启仍收敛。
- SSH 验收：SSH Git/folder 中原远端 PTY/incarnation/PID、tab/leaf、布局及可见内容连续；电脑本机不生成对应替代进程，配对 runtime 镜像不成为第二 writer。

### REQ-003 关闭意图与并发冲突不复活

- 当前状态：待实现。
- 描述：原 tab/pane 已关闭、正在关闭、被别的窗口认领，或同数字 ID 换 incarnation 时，不复活或错误认领原 surface，也不覆盖赢家。执行主机正向确认 PTY 已退出时可交回原有恢复路径。
- 业务规则：关闭/归属检查应覆盖持久化绑定 replay；窗口图缺失不等于用户主动关闭。拒绝和写盘/回执不确定时保留健康布局。
- 本地验收：关闭记录、admission 中途关闭、抢占、ID 复用、写盘失败/回执丢失及重复同 claim 下，没有复活、错误归属或替代 shell；正向确认退出且 surface 仍有效时进入原有恢复；重试后可幂等收敛。
- SSH 验收：SSH 对应 host 分区重复上述竞态，关闭记录与执行主机当前身份均由正确 owner 裁决；本机镜像不能覆盖远端赢家，失联不作为退出证据。

### REQ-004 执行主机权威与失联边界

- 当前状态：待实现。
- 描述：只由原执行主机核定 PTY 活性与认领；断连时不读取该主机、不把失联视为退出、不回退到电脑本机创建终端，联通恢复后依据新状态重新判定。
- 业务规则：活性结果仅用 `live` / `unverifiable` / `exited`；功能不自行重连、重试或对失联 host 轮询。电脑窗口是投影，不因数字 PTY ID 相同跨主机认领。
- 本地验收：本机 provider 暂不可验证时不新建 shell；恢复可验证后按当前 PID/incarnation 判断，不复用过期快照。
- SSH 验收：SSH 断开时无远端读取或功能自发重试、无电脑本机 fallback；共享连接层报告 connected 后重新判定。配对 runtime 的权威进程和 session 保持在远端。

### REQ-005 工作区类型与混合版本覆盖

- 当前状态：待实现。
- 描述：同一认领行为覆盖 Git worktree、folder repo、独立 `folder:<id>` 工作区，并在客户端与执行主机独立更新、旧 relay/runtime 缺必要能力时安全降级。
- 业务规则：不得由 Git 路径、工作区名称或缺失字段推断执行归属或允许认领；旧 `worktree.activate` 仍可调用，旧 peer 不能证明严格认领时拒绝自动恢复。
- 本地验收：本机 Git/folder 两类入口保留原身份；新旧组件混用且缺必要字段时无误认领、无隐式新建，普通旧激活协议仍可工作。
- SSH 验收：SSH Git、SSH folder repo、独立 folder workspace 均在 SSH 机保有文件/进程/PTY/relay，在电脑 main 的 `ssh:<target>` 分区使用正确布局与关闭记录；新旧客户端/宿主/relay 组合缺能力时安全拒绝、不发未知 opcode、不产生本机 shell。各机器的 `127.0.0.1`、环境和服务归各自机器。

### REQ-006 本次原身份恢复分支不引入第二 writer

- 当前状态：待实现。
- 描述：仅在此次 `adoptLiveWorkspacePtySurfaces` 新增的“宿主有 recorded pane、桌面缺原 tab”分支中，以原 tab/leaf 接回同一 live PTY，不因该分支另启 writer。无 recorded、原 leaf 不在布局、归属冲突、跨工作区或精确恢复失败等非目标情形保留上游 fallback 合同。
- 业务规则：保留上游 fallback 对 daemon PTY 的可用接回；不能把非目标情形全部改成 `declinedPtyIds`/`surfaced=false`。本机纯数字 PTY 在不可恢复情形下仍可能沿旧 fallback 留下空 shell，这是已知残留，不能隐瞒或写成全局 no-fresh。显式桌面 `empty` seed 和手机后台 wake 的调用方区别仍须验证；普通 connect 的 unknown/无 ID/cold resume 异常另列后续。
- 本地验收：有有效 recorded pane 且桌面缺原 tab 时恢复原 tab/leaf、PTY/PID 不变、新 writer 增量 0；无 recorded、冲突、原 leaf 缺失或跨工作区时，daemon 保持上游随机标签接回同一 PTY 的能力，旧 gate 测试契约不被删改；本机 numeric fallback 的可能残留单独记录，不误判为新分支成功。
- SSH 验收：先证实现行 runtime/orcad 工作区是否绕过本 gate；对实际进入 gate 的遗留直连 relay 路径验证有效 recorded 的原身份接回，同时核对非目标 fallback 保持旧行为及执行主机分区正确。

## 7. 业务规则

- 不以窗口图缺失推断用户主动关闭；关闭意图和执行归属需权威核对。
- 活性判定用 `live` / `unverifiable` / `exited`；无法联系执行主机时不读该主机。
- 手机后台打开工作区不抢电脑导航和焦点；本轮不新增 UI。
- 后台创建不立即在电脑 reveal 终端标签；后续 wake 或用户显示时投影原 tab/leaf，不创建替代身份。
- 本次止血新增的原身份分支只接回同一 live PTY；无 recorded、冲突等非目标路径保留上游 fallback。此限制不代表全部异常下均不 fresh；原有 numeric 空 shell 残留需另行处理。
- 具体事务、tombstone TTL、RPC 字段和失败回退属于技术方案，不能从受控对照推出已完成。

## 9. 已确认结论

- 已进入临时修复测试阶段；目前只对有效 recorded、桌面缺原 tab、单 leaf 的窄版路径取得代码 review 与局部运行证据，全部 REQ 的宏观完成状态仍待覆盖矩阵收敛。
- 无 UI 新增或交互事实源，设计稿 `not-required`；正式 Test Case 单独登记，执行结果另存证据。
- 调查支持本机受控场景的身份缺口，不代表完整生产修复已验证。
