## 过程中的失败与处理

- 本机前三次运行失败都在脚本：非 e2e 构建不暴露 store；生成稿直接成为文档后，脚本等的「采用」按钮不出现；目标详情已自动打开，脚本还去点列表行。产品断言在第三次运行已全部通过，第四次为完整重跑。
- 真机发现一处产品问题并修复：给守卫的「历史会话」原先指向 `~/.codex/sessions`，而 Orca 终端里的 codex 用托管目录。改为优先从执行 agent 的对话记录路径推出它的会话目录，第四次运行起生效。
- 首次 SSH 运行一条断言写宽（把本机 Orca 自己的 `codex app-server` 当成守卫调用），修正后重跑；那次收尾漏掉了测试 relay，已按工作目录结束，脚本随后改为按 cwd 清理。

## 清理与边界

每次运行结束：测试 profile 删除，按工作目录结束落在其中的进程，`authorized_keys` 的哈希与运行前一致，`~/.orca-remote` 与真实 `~/.orca-goal` 未变。窗口始终隐藏、不聚焦，没有操作用户正在用的 Orca。

未在真机覆盖：Stop hook 丢失（TC-369）、结论生效前复核（TC-373）、预算顺序（TC-375），这三项由驱动端到端测试覆盖；D1 生成时不读 Orca 托管的 codex 会话目录（守卫能读，见上）；驱动被 SIGKILL 时正在跑的守卫子进程会跑完才退出，结论无人读取。
