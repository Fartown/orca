# 插件读取工作区远程仓库

## 背景

要给自建代码平台写 Orca 插件（在右侧面板里看当前工作区的 MR、diff、检查），插件得先知道「当前工作区对应平台上的哪个仓库」。插件接口目前只给分支名、显示名和终端：

- 本地工作区，插件 worker 还能自己在工作区路径上跑 `git remote`；
- SSH 工作区的文件在 SSH 主机上，插件 worker 跑在客户端，没有办法在那台机器上执行 git。插件接口也有意不开放远程执行，插件不应该自己去连主机。
- orcad 托管的 SSH 工作区（当前默认）连分支名和显示名都拿不到：插件宿主只问客户端主进程的 runtime，而这类工作区归 SSH 主机上的 orcad 管。

Orca 自己其实早就知道答案：每个仓库记录里都有它在所属主机上读到的远程地址（`gitRemoteIdentity`），Orca 窗口也列着每个主机上的工作区。本功能把这些已有的记录，按插件接口的规则交给插件。

## 需求

### REQ-2201 插件能拿到当前工作区的远程仓库

当前状态：已实现

`workspace.readContext` 的结果和 `workspace.changed` 事件的 `context` 增加可选字段 `remote: { name, url }`，即当前聚焦工作区所属仓库的远程名和地址。

- 本地场景：远程地址由 Orca 已有的仓库远程识别在本机读取并记录；插件宿主从客户端 Orca 的仓库记录里取。
- SSH 场景（orcad 托管，当前默认）：工作区、仓库记录和终端都归 SSH 主机上的 orcad 管，客户端主进程的 runtime 不认识这个工作区，改动前 `readContext` 一直是 `null`。现在插件宿主在本机 runtime 认不出聚焦工作区时，改问 Orca 窗口：窗口本来就列着这个工作区和它的仓库记录（含远程），插件因此拿到分支、显示名和 `remote`。`terminals` 为空——这些终端跑在 SSH 主机上，列出它们不在本需求内。
- 两种场景下本功能都不执行 git、不联网、不读写文件、不连主机；SSH 断开时不重连、不读取，窗口还列着这个工作区就照样给出。
- `agents.list`、`terminal.sendText` 的行为不变：聚焦 orcad 托管的 SSH 工作区时，它们和改动前一样看不到这个工作区。
- 验收：本地和 SSH 工作区聚焦时，`readContext` 与 `workspace.changed` 都带 `remote`，与仓库的 origin 一致；在本地和 SSH 工作区之间切换时，`workspace.changed` 依次给出各自的上下文。

### REQ-2202 工作区列表带上各自的远程仓库

当前状态：已实现

`workspace.list` 的每个 worktree 行增加同样的可选字段 `remote`，取自该行所属仓库的记录。项目组里的纯文件夹没有仓库记录，不带此字段。

- 本地场景：数据来自客户端 Orca 已有的仓库列表（`repo.list`），不新增任何远程读取。
- SSH 场景：`workspace.list` 只列客户端主进程 runtime 管的工作区，这是现有行为；orcad 托管的 SSH 工作区本来就不在列表里，所以也不会有它们的行。把 SSH 主机上的工作区并进列表涉及 `terminal.create`、`agent.launch` 等按行操作的路由，不在本需求内（2026-11-04 用户选定只补聚焦工作区）。插件要拿 SSH 工作区的远程，用 REQ-2201 的 `readContext` 或 `workspace.changed`。
- 验收：列表里每行带自己仓库的远程，互不串用；聚焦 SSH 工作区时列表内容与改动前相同。

### REQ-2203 不把凭据交给插件

当前状态：已实现

远程 URL 交出之前去掉凭据：任何协议都去掉 `user:password@`；HTTP(S) 的单独 `user@` 也去掉，这里常放访问令牌；`git@host:path`、`ssh://git@host/...` 的 `git@` 保留，它是 SSH 登录名，去掉地址就不能用了。去掉后为空或超过 2048 字符时不给此字段。

- 本地场景：脱敏在客户端插件宿主（Orca 主进程）里完成。
- SSH 场景：脱敏在客户端 Orca 窗口里完成，主进程只收去掉凭据后的地址，再按插件接口的形状校验；记录本身不变。
- 验收：远程为 `https://user:secret@…` 的仓库，插件收到的 URL 不含 `secret` 和 `user`。

### REQ-2204 对现有插件和旧版本兼容

当前状态：已实现

- 字段可选：Orca 不知道远程时不出现，而不是给 `null`。已有插件与已有断言看到的结果不变。
- 不新增方法，不改参数，不提升 host API 小版本号。插件判断「这个 Orca 是否提供」只需看字段是否存在；在旧版 Orca 上字段不存在，插件应按「未知」处理。
- 本地场景与 SSH 场景相同；没有窗口的无界面服务（headless serve）里，SSH 工作区的 `readContext` 仍为 `null`。
- 验收：现有插件相关测试不改动全部通过；生成的参考文档与插件类型声明只多出这个可选字段。
