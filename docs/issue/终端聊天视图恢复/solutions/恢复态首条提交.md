# 恢复态首条提交

恢复 PTY inventory 的 launchToken 为 null，持久 hook row 不保留 raw token；旧 provider row 不会凭空变成 live observation。不能把旧 hash 与同 pane 拼接成“原 launch 已认证”，也不能因缺 provider 证明而永久禁止原终端的一次用户输入。

执行权限仍来自当前用户选定的固定物理终端。抽出既有 restored authority 的完整字段比较，同时供旧兼容调用者校验和本功能使用；不改变原兼容调用者仍需 token/hydrated attestation 的规则。普通 live 提交继续走原严格 provider guard。只有 opt-in 且完整 restored physical receipt 匹配，才可返回未证实 provider 的提交计划；明确不同当前 session/旧 observed incarnation 继续拒绝。

在 Enter 前记录旧 session 的原文件 anchor，receipt 增加可选的 sessionUnverifiedAtSubmit/submitPtyId。已有 prompt receipt 的 processIncarnation 供后续核验。requestShow 的 verifyChatTranscript 读取原调用者 ledger；provisional 只有在同 PTY/incarnation、fresh 期望 provider、hook transition 和本次提交后的 turnStartedAt 成立后才进行文件连续性核验。provider 未证实、换 session/进程仍保持未知，不能让旧 transcript 升级证明。

身份解除只用于文件证明核验，最终仍由原文件边界后的实际正文一对一匹配确认。Stop 保留 turnStartedAt，不依赖 working 时隙；OSC/replay/身份行不能后证。completed ledger 的后证事实原地持久，查询只观察同一请求，不重放写入。

renderer 复用已有 store subscription，在相关 pane 的 turn/state 边沿到来时，对仍 provisional 的记录重做确认。事件来自执行主机，不对每个 tool updatedAt 发请求，不轮询、不为离线主机探活或重连。原文和 outbox 在客户端；物理 authority、hook、turnStartedAt、PTY、ledger、transcript 在执行主机；两个 loopback 仍按既有验收归属。

新客户端显式请求 reconcileRestoredSession；旧客户端不进入 provisional 行为。新增字段可选，旧 host 忽略 opt-in 后维持严格拒绝，数据不丢。移动端原路径不变。本轮不迁移用户会话，不退出用户 App；真实验证只使用独立 profile/进程。
