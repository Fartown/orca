## 2. 决策点记录

### D-001 文档上限独立于手机端读取

- 日期：2026-09-12。
- 背景：本地文档读取复用 512 KiB 手机端常量；直连 SSH 请求和共享读取器限制为 10 MiB。
- 备选项：放大所有文件读取与全局 RPC 预算；或只接入文档专用上限。
- 最终决定：本轮采用后者，20 MiB 按实际文件字节判断。
- 原因：用户请求扩大文档预览，不是改变普通读取与通信协议。
- 影响范围：REQ-401/402；普通读取与全局通信限额不变。

### D-002 实际预览入口的传输接线

- 日期：2026-09-12。
- 背景：追踪 HtmlDocPreview → grant → readDocPreviewFile 后确认 runtime 入口仍受单次预算限制；SSH 另有 16 MiB 单帧限制，底层文件测试通过不代表传输打通。
- 最终决定：SSH 复用现成 requestGitStreamable / 单一 responseStreams registry；runtime 在已有授权方法上增加可选 chunk，按 256 KiB 拉取，保留旧主机完整响应回退。
- 原因：这是当前预览入口支持 20 MiB 的必要实现，不是另建通用传输功能；不扩大其他读取或任何全局限额。
- 影响范围：REQ-401/402，客户端与执行端均升级后支持新上限；未安装或重启用户 App。

### D-003 验收纠正本地 UI 与宿主方法的入口混淆

- 日期：2026-09-12。
- 背景：此前 D-002 将专用预览组件的 runtime 路由概括为全部预览入口。真实 UI 验收重新检查 `file-preview.ts:getWorkspaceFilePreviewPlan`，确认纯本地 UI 使用已有 `file://` 浏览器标签，只有 SSH／配对使用专用 `orca-preview://`。
- 最终决定：保持原本本地预览能力，验收 20 MiB 正常显示；不为纯本地新增 20 MiB 上限。宿主内部 reader 的 20 MiB+1 拒绝测试保持，但不冒充本地 UI 证据。
- 原因：纠正 Agent 对当前实现的描述，不改变用户请求或引入新的本地限制。
- 影响范围：REQ-401 与 TC-401 描述已同步；生产代码没有因此变更。
