# 自动出包测试用例

| 功能 ID | 关联需求 | 功能点 | 是否测试 | 预期表现 | Test Case |
| --- | --- | --- | --- | --- | --- |
| F-401 | REQ-401 | 自动同源构建 | 是 | 三个平台包由相同提交产生 | TC-401 |
| F-402 | REQ-402 | 完整预发布 | 是 | 全部成功才公开，失败可查 | TC-402 |
| F-403 | REQ-403 | 内测签名 | 是 | macOS 未公证，APK 指纹稳定 | TC-403 |

## TC-401 自动构建与来源

- 关联需求：REQ-401；模块：工作流；优先级：P0；类型：单元、云构建。
- 前置条件：fork 工作流可用；测试数据：一个完整 Git SHA。
- 步骤：验证工作流触发器和依赖；提交构建分支 PR；合入 integration 后检查自动运行。
- 预期：macOS arm64、x64 与 Android 在身份任务后并行；checkout SHA 一致；产物非空；手动运行同样可构建。

## TC-402 发布完整性与范围

- 关联需求：REQ-402；模块：发布；优先级：P0；类型：单元、GitHub 集成。
- 前置条件：拥有 fork 仓库权限；测试数据：齐套、缺包、空包和上传失败输入。
- 步骤：执行发布反例测试；检查真实成功构建发布页和下载清单。
- 预期：PR 和其他仓库/分支不能发布；缺包不创建 release；上传失败停留 draft；齐套后转 prerelease；SHA、版本和校验和可追溯；已公开产物不覆盖。

## TC-403 签名与兼容边界

- 关联需求：REQ-403；模块：打包；优先级：P0；类型：单元、打包验签。
- 前置条件：macOS 和 Android 构建工具可用；测试数据：原签名、变化签名、无签名输出。
- 步骤：执行签名反例；对 DMG 中 App 验签并运行对应架构 Node 入口；对 APK 执行 apksigner verify。
- 预期：继承原打包资源与校验 hooks；macOS ad-hoc、未公证，不发布 updater 元数据；APK 唯一签名指纹匹配现有 Expo 模板；版本来自 app.json；发布说明明确不同签名不可覆盖。
