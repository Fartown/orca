# Goal 目标模式需求

本文的 `ready` 表示本地文档与当前源码的现状核对已完成，不表示功能已经验收、发布或在三平台运行通过。CLI、独立验收裁判、插件面板归属于本需求；关联 [技术说明](../solutions/Goal目标模式技术说明.md) 与 [测试用例](../tests/cases/Goal功能测试.md)。

## 需求目标与层级

用户为 Orca 中已有的交互式 agent 会话设定一个持久目标。看门狗在 agent 停下来后继续推动该目标，以独立证据核对完成声明，并让用户能够查明进展、验收结果和停止原因。用户保留查看会话、插话和主动停止的能力。

| 层级 | 目标 | 完成尺度 |
|---|---|---|
| 总目标 | 持续推进用户原始目标，并给出可核实的进度与停因 | 不能以一次模型“完成”回复或局部测试通过代替整个目标达成 |
| P0 基础闭环 | 工作区目标 → 已有会话续跑 → 认领 → 独立验收 → 完成/预算结束/等待用户 | 现有源码已形成主链路；具体运行验收仍需测试记录 |
| P1 可靠性与可用性 | 故障接回、终端改绑、证据落盘、参数配置、面板观测；减少错误停止 | 有实现，也有明确差距，见逐条需求 |
| P2 扩展与边界 | Windows/SSH/WSL 完整支持、完整运行代际标识等 | 当前不作为已完成能力宣传 |

## 用户流程

1. 用户在 Orca 打开工作区和 agent 会话，通过 CLI 指定目标、终端、验收及预算；或在 Goal 面板填表后复制生成的启动命令。
2. 驱动通过 Orca 公开 CLI 向该终端发送目标，等待本轮结束，收集文件变化并读取 agent 的完成/受阻认领。
3. 声称完成时执行验收；未通过则将具体失败反馈给下一轮。声称受阻达到阈值后等待用户，或先执行验收核实。
4. 用户通过 status/watch 或面板查看；可以 stop 保留记录、resume 接回，原终端关闭后可以 rebind。
5. 当前代码也可能因空转、反复验收失败或驱动重试耗尽终止；这些行为与最新目标的差距单独列出，不掩盖为“已实现自动恢复”。

## 需求清单

“已实现”仅指存在对应源码；“部分实现”表示代码不能满足完整目标；所有产品运行验收状态均为本次未执行。

### REQ-101

优先级：P0。

需求与验收：在已有交互式会话中持续推进完整目标。正常忙碌时等待，轮次结束后继续；用户切换工作区不应改变目标终端。

当前状态：已实现外部 CLI 驱动；终端判定依赖 hook/PTY，不能保证所有 TUI/agent 无误判。

### REQ-102

优先级：P0。

需求与验收：目标按工作区持久化，终端仅作为可更换的输入位置。同工作区不得并发运行两个驱动；关闭终端后仍能找到目标并接回。

当前状态：已实现工作区 key、锁、resume、rebind、旧 key 迁移；软链别名、PID 身份与完整运行代际仍有边界。

### REQ-103

优先级：P0。

需求与验收：完成/受阻声明只从指定认领文件读取，旧轮次或无效内容不应被采信。

当前状态：已实现格式、大小、mtime 检查；不是从终端扫字符串，也不是独立 agent 工具协议。

### REQ-104

优先级：P0。

需求与验收：配置验收时，完成必须有独立命令结果；失败反馈须保留可操作证据。未配置验收必须明确未经验证。

当前状态：已实现原地命令门禁与独立 claude/codex 裁判；异常分类、缓存范围仍有限制；判据质量仍需用户保证。

### REQ-105

优先级：P0。

需求与验收：提供轮数与累计时长预算，显式 0 表示不限；停止驱动期间不扣预算，验收耗时应计入。

当前状态：已实现默认 20 轮/180 分钟与 activeMs；验收不受剩余目标时长严格截断，预算结束不等于停止 agent 进程。

### REQ-106

优先级：P0。

需求与验收：识别 agent 正在等用户时暂停注入；连续受阻后通知用户，并可在用户回应后继续。

当前状态：已实现 hook needs-user 与认领 ask/verify；无 hook 时不能可靠识别权限对话框；停因分类见 REQ-113。

### REQ-107

优先级：P1。

需求与验收：瞬时终端/磁盘/取证故障不能静默丢失目标；需保留异常原因、认领与验收结果，并能恢复。

当前状态：已实现重试、取证降级、判词落盘、crash guard 与 resume；并非完整持久阶段机，故障边界需回归。

### REQ-108

优先级：P1。

需求与验收：每轮用独立文件证据展示改动；验证方式被修改时可见并交裁判判断，不以改测试本身推定作弊。

当前状态：已实现 git tree/HEAD、差异扫描与 gate diff；非 git 无该证据，普通 check 不自动解释 diff；未实现所有旧稿的硬门槛。

### REQ-109

优先级：P1。

需求与验收：面板展示目标、预算、当前轮次、等待/中断、验收与逐轮摘要；数据过期可辨，操作命令可复制。

当前状态：已实现 bundled 插件及镜像；面板不直接执行带参操作，当前选择全局活动目标而非按工作区过滤。

### REQ-110

优先级：P1。

需求与验收：支持长目标配置、多个 check、后台运行及可读错误；路径在后台 cwd 改变后仍正确。

当前状态：已实现 JSON/整行注释/目标数组、CLI 优先与路径绝对化；resume 与 judge 数值校验、配置字段仍有不一致。

### REQ-111

优先级：P2。

需求与验收：平台与远端支持边界准确：执行机器负责验收/证据/进程，不将断联当退出。

当前状态：Linux 命令名已适配；当前仅有本机执行链，无完整 Windows/SSH/WSL 实现或本次运行验证。

### REQ-112

优先级：P1。

需求与验收：删除“连续无文件变化即终止”的空转熔断；正常只读调研、铺环境等过程应继续，直到可靠停因或预算触发。

当前状态：未实现。2026-08-21 最新提案已有明确意图；当前仍使用 maxStallRounds=3 并生成 stalled。

### REQ-113

优先级：P1。

需求与验收：在无认领的停止点，只在有明确依据时区分等待权限、崩溃和普通停止，避免把续跑文本打进权限框。

当前状态：未实现最新提案的 obs.tail/明确签名判断；现有 hook/PTY 等待不等于这一能力已完成。

### REQ-114

优先级：P1。

需求与验收：门禁无法判定不计为 agent 失败；同一批验收项反复不能收敛时，将证据升级给用户。

当前状态：部分实现。inconclusive 已独立计数；普通 falseClaims 仍累计 3 次终止，没有“同批失败项→等待用户”。

### REQ-115

优先级：P1。

需求与验收：目标状态、驱动存活、agent 活动和验收有效性分别表达；记录删除/归档行为准确可预期。

当前状态：部分实现。driverError/driverAlive 独立展示；多处仍只探测 PID，forget 仅删目标 JSON，未形成完整 runId/侧车清理。

## 明确保留的产品取舍

当前采用外部驱动保持交互式会话，plugin worker 负责观测与命令入口。历史 v2 Stop hook、v3 headless 干活会话以及“全部循环放进 worker”均已被替代；保留其取舍依据，不作为并行需求继续维护。

验收默认在原工作区执行，不提供旧稿中的干净副本验收。默认首失败短路，`--check-all` 可全跑。裁判默认不强制只读沙箱；显式沙箱限制以实际 agent 支持为准。开工前 baseline 验收在原决策中已决定不做，不能重新列为必须实现。

本期没有 token/美元预算、验收测试集合采集、验收文件硬锁、自动安装额外 hook、独立 Goal daemon RPC、运行中编辑 objective 的完整入口。它们曾在历史稿出现，不能直接并入当前完成清单。

## 最新目标尚未达成的部分

REQ-112 来自最新“删除空转熔断”提案：三轮文件无变化不能可靠说明 agent 不在推进。该提案要求保留快照、changed、篡改扫描和验收缓存；保留 `stalled` 的历史显示兼容，仅停止产生新 stalled。本文记录这一既有目标，不代替代码实施。

REQ-113 是同一提案明确分开的第二阶段：只在能识别的权限/崩溃签名出现时改变普通 continuation；看不懂时维持现状。签名集合、具体误判率和真实验证还没有落地材料。

REQ-114 来自已标“完成”的旧待决清单，但源码仍不是其声明的最终行为。整理后保留为差距，不能因为标题上有勾选就判作完成。
