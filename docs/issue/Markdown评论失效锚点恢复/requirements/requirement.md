# Markdown评论失效锚点恢复

## 背景与范围

事实来源：[Issue #79](https://github.com/Fartown/orca/issues/79)、同版本 preview.68 复现和用户本轮完成修复、测试与合入的授权。评论计数存在但失效行号无法生成卡片。仅恢复 rich Markdown 评论可见性；不改写文件、不迁移或自动删除评论、不修改主机归属与通信协议。

## 需求与验收

### REQ-7901 恢复可匹配的原文位置

当前状态：已实现。

本地：旧行号失效而引文仍存在时，复用现有选中文本匹配定位评论。SSH：远端文件在客户端渲染时使用相同定位规则，评论始终属于原执行主机。

### REQ-7902 原文失效仍可访问评论

当前状态：已实现。

本地：引文移除、行号落在分隔行或超出范围时仍生成评论卡片，明确显示原文已变更，支持既有编辑与删除。SSH：远端评论同样保持可访问，编辑和删除通过既有主机路由持久化；计数与可访问评论一致。

### REQ-7903 保留内容与兼容性

当前状态：已实现。

本地：评论正文、引文、存储字段及其他评论不被自动改写，原正常定位、排序和尺寸测量保持。SSH：执行主机拥有文件与评论，客户端仅计算布局；未连接时遵循原连接层，不触发额外读取、轮询或重连。移动端继续使用已有独立评论入口，存储格式不变，允许新旧客户端与主机混用。

## 未决问题

无阻止本轮修复的问题。重新挂接原文的独立编辑功能不在本轮范围内。
