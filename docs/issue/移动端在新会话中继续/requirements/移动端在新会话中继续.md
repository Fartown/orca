# 移动端在新会话中继续

## 1. 背景与目标

桌面端已有「Continue in New Session（在新会话中继续）」：从一个 agent 会话的当前进度出发，新建一个 agent 会话，把源会话上下文作为首条 prompt 交给它，源会话保持不变。移动端目前没有这项能力，也没有任何相关代码或文案。

目标：让移动端用户对当前 agent 会话也能做同一件事，且优先复用执行主机（桌面端 / orcad）已经暴露给移动端的能力，不新增 RPC、不改 wire 协议。第一期只覆盖 claude 与 codex。

## 2. 用户场景

- 用户在手机上盯着一个 claude / codex 会话，任务做到一半想换个干净上下文接着做（或换另一个 agent 接着做），希望像桌面端一样一键新建会话并把上下文交接过去，而不必手动复制粘贴。
- 源会话可能仍在运行、也可能已经空闲；用户只要求新会话拿到「做到哪了」的交接，不要求把旧会话 resume 到新会话里。

## 3. 范围

### In Scope

- 移动端对 agent 类型为 claude 或 codex 的终端会话提供「在新会话中继续」入口（终端 tab 长按菜单）。
- 与桌面端相同的两种上下文模式：聚焦交接（默认）与完整会话记录。
- 新会话落在同一工作区，首条 prompt 与桌面端同构（同一套 prompt 构建逻辑），并自动提交。
- 只使用已对移动端开放的主机能力；不新增 RPC 方法、参数字段或流 opcode。
- 旧版本主机的兼容处理（入口按主机能力门控）。
- 三类失败的用户可感知反馈（会话未创建 / 会话已创建但上下文未送达 / 无可用上下文）。

### Out of Scope

- `stdin-after-start` 类 agent（aider、goose、amp、cline、kimi、claude-agent-teams 等）。
- Agent History 页不提供入口（2026-09-13 用户确认：只在终端 tab 长按菜单加，历史页不加任何入口）。
- 结构化聊天通道（`agentSession.create` → `send`）。
- 桌面端 Fork Session（新建 git worktree）与 Resume in Chat（接管同一 provider 会话）的移动端对位。
- 移动端 i18n 体系（移动端现状为内联英文文案，本需求沿用）。

### 来源与结论分类

- 原始事实：
  - 用户要求移动端具备与 PC 端相同的「基于当前会话新建一个对话」能力。
  - 桌面端该能力的实现形态（采集源上下文 → 拼交接 prompt → 新开会话并投递首条 prompt；prompt 明确要求不 resume 旧会话）——来自代码调研。
  - 仓库规则：客户端与主机独立升级，新增可选字段安全但不可被新客户端要求存在；新 opcode 必须协商；fork 侧新能力须先注册再实现——来自 `AGENTS.md` 与 `docs/reference/remote-wire-compatibility.md`。
- 用户已确认结论：
  - 第一期只支持 claude 和 codex（用户原话「支持 claude 和 codex 就行了」「先按 claude 和 codex 做」）。
  - 实现方向为「新增一个入口，其他能力全部复用 PC 端」，即复用执行主机已有能力，不重新实现一套。
  - 2026-09-13 方案评审：入口只放终端 tab 长按菜单，Agent History 页不加入口；两种上下文模式都提供、与 PC 一致；新会话创建后自动切换为当前 tab。
- 推断（待确认）：
  - 新会话的起始目录沿用源终端的启动目录。
  - 源会话没有 transcript 路径时入口不可用（移动端没有终端回滚缓冲的回退来源）。

## 5. 需求点

### REQ-001 从当前 claude / codex 终端会话新建续接会话

优先级：P0。当前状态：已验收（2026-09-13 云真机小米 15，mock host 与真 Orca 主机各一轮；入口、面板、两种模式 prompt 逐字一致、自动切 tab 全部通过；真主机上被拉起的新 agent 按 prompt 正确行事）。

- 描述：用户对一个 agent 类型为 claude 或 codex 的终端会话触发「在新会话中继续」后，移动端在同一工作区新建一个 agent 会话（agent 可选 claude 或 codex），并把源会话上下文作为首条 prompt 自动提交；源会话保持不变。
- 业务规则：
  - 新会话不 resume 源会话；prompt 内声明源 provider 会话是只读上下文（与桌面端相同文案）。
  - 首条 prompt 的构建逻辑与桌面端为同一实现（同一函数），输入字段来自移动端已能读到的会话数据（agent 类型、transcript 路径、最后一条助手消息、会话标题、启动目录）。
  - 只在源会话具备 transcript 路径时可用。
  - 提供与桌面端相同的两种上下文模式：聚焦交接（默认）、完整会话记录。
  - 新会话创建后自动切换为当前 tab（与桌面端一致）。
- 验收标准：
  1. 对一个 claude 或 codex 终端会话触发后，同一工作区出现一个新的 agent 终端 tab 并成为当前 tab，源 tab 不变。
  2. 新会话的首条 prompt 与桌面端对同一源会话、同一模式生成的 prompt 逐字一致；两种模式各验证一次。
  3. 首条 prompt 作为一条消息被提交（agent 侧只出现一条用户消息），新会话开始处理。
  4. 源会话 agent 类型不是 claude / codex，或没有 transcript 路径时，入口不可用并有说明。

### REQ-002 只复用已开放给移动端的主机能力

优先级：P0。当前状态：已验收（真机抓到的 RPC 仅 session.tabs.createTerminal / terminal.wait / terminal.send，均在移动端白名单内）。

- 描述：实现只使用移动端 RPC 白名单中已有的方法与既有参数字段；不新增 RPC 方法、参数字段、流 opcode，也不改变主机发布内容。
- 业务规则：
  - 会话创建、就绪等待、prompt 投递、agent 检测均走既有方法。
  - 桌面端与移动端共用的逻辑放在 `src/shared`，移动端生产代码不引用渲染进程模块。
- 验收标准：
  1. `src/main/runtime/mobile-rpc-allowlist.test.ts` 与 `pnpm verify:rpc-params-catalog` 无需修改即通过。
  2. `src/shared/rpc-contract/**` 无改动；`src/shared/protocol-version.ts` 无新增能力标识。
  3. 移动端新增代码对 `src/renderer/**` 零 import（移动端既有边界测试通过）。

### REQ-003 桌面端行为不变

优先级：P0。当前状态：已验收（2026-09-13 第三轮：上游实现与本分支实现 2304 组输入差分零差异；本分支桌面构建里入口与对话框完好；真启动的新会话收到的 prompt 与两份实现三方逐字一致 1395/1395/1395）。

- 描述：为共用 prompt 构建逻辑而对桌面端文件做的调整，不改变桌面端「在新会话中继续」与 Fork Session 的任何行为。
- 验收标准：
  1. 桌面端相关既有测试（`AgentSessionContinuationDialog.test.tsx`、`launch-agent-session-continuation.test.ts`、`agent-session-fork-context.test.ts`、`terminal-agent-session-continuation.test.ts`）不改断言即通过。
  2. 桌面端调用方文件的 import 路径不变。

### REQ-004 旧主机兼容

优先级：P0。当前状态：部分验收（真机端到端跑在不含本分支任何改动的 Orca 1.4.197 发布版主机上，证明本功能不需要主机侧配合；但该轮源会话无 startupCwd，「旧主机丢弃 cwd」分支仍未触发）。

- 描述：配对的主机版本不满足该功能所需能力时，移动端不展示入口或给出「需要更新桌面端」提示；不得向旧主机发送其会静默剥离的字段。
- 业务规则：能力判定复用移动端既有的主机能力门控范式（同 Quick Commands）。
- 验收标准：
  1. 主机能力列表缺少所需能力标识时，长按菜单不出现该入口。
  2. 具备能力时入口出现；能力尚未探测到时入口不出现。

### REQ-005 失败可感知且不产生幽灵会话

优先级：P1。当前状态：已验收（2026-09-13 第三轮真机注入四种失败：提示按「会话是否存在」二分且正确，失败分支不再调用其后的 RPC；同一源 tab 连续四次触发复用同一 clientMutationId）。

- 描述：用户能区分三种结果——会话未创建、会话已创建但上下文未送达、无可用上下文；重试不会因传输不确定而创建重复会话。
- 业务规则：
  - 创建复用既有幂等键；传输结果不确定时不自动重建。
  - 就绪等待超时或投递未被接受时，新会话保留，提示「上下文未送达」（对位桌面端同名提示）。
- 验收标准：
  1. 三种失败各有一条明确提示文案，且文案能区分「会话是否已创建」。
  2. 断网重试后不出现两个新会话。

### REQ-006 第一期范围限定 claude / codex

优先级：P0。当前状态：已验收（面板仅提供 Codex / Claude；普通 zsh 终端长按无该入口）。

- 描述：入口只对源 agent 为 claude 或 codex 的终端展示；目标 agent 候选只提供 claude 与 codex。
- 验收标准：
  1. 其他 agent 的终端 tab 长按菜单不出现该入口。
  2. 目标 agent 列表不出现 claude / codex 之外的项，即使主机检测到其他 agent。

## 9. 已确认结论

- 第一期只支持 claude 与 codex（2026-09-13 用户确认）。
- 方向为新增入口 + 复用主机既有能力，不重新实现一套（2026-09-13 用户确认）。
- 入口只在终端 tab 长按菜单，Agent History 页不加；两种上下文模式都提供；新会话创建后自动切换（2026-09-13 方案评审确认）。
- 真机验证（2026-09-13）：claude / codex 在「建终端 → 等就绪 → 投 14 行 prompt」路径上均一次跑通，prompt 作为一条消息提交并观测到 turn 开始。
