# 侧栏同名归类需求与方案复核

**复核结论：需求是补同名归类。额外操作 UI、人工配置兼容和折叠继承均越界；有效需求和方案已修正。源码已按此范围收缩，原操作与折叠组件恢复基线；最终应用与 PR 验证另记本轮 Test Run。**

来源：[当前需求](../requirements/requirement.md)、[当前方案](项目分组最小改动方案-10-23.md)与 [D-007](../journal.md#d-007-仅修改侧栏归类撤回所有操作-ui-改动)。本记录涵盖文档复核及随后获授权的源码收缩；不部署或修改在线目录。

## 1. 复核范围与方法

- 原实现以 `git show 0adbdab8c17582a665a0c943f566e87f94b48494:<文件>` 为证据；这是当前功能分支的集成共同基线。当前工作树用于核对未提交差异，不能把旧原型当成既有产品能力。
- 主流程回读模型、分组、菜单回调、折叠与导航；另进行只读独立复核，检查全仓相关显示键解析。没有启动应用或重新读取用户在线配置。
- 核对需求目录原有 13 份文档的入口、状态和当前/历史边界。有效需求、方案正文重新整理；原生迁移稿、人工成员原型及旧 Test Run 只保留历史，不继续作为本期要求。
- 需求、方案、现状事实、测试规格和测试结果分别维护；测试“曾通过”不等于现在的最终实现通过。
