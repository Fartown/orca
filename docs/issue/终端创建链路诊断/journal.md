## 2. 决策点记录

### D-803 补齐原版后推进合入，部署单独验收

- 日期：2026-10-22
- 背景：用户明确要求“合入啊”“看看缺少 再补一下”；原版本只有本地提交，没有 PR 或集成交付。
- 备选项：重新实现日志；沿用原版适配当前集成基线。
- 最终决定：沿用原版，覆盖两种 RPC 分发通道、显式历史恢复入口及现成关联字段，隔离验收后以 PR 合入；不更改 wire、恢复/去重、host 连接行为。
- 原因：合入授权不等于替换生产应用授权；不能再次把生产重启确认当作隔离验收与 PR 的前置阻塞。
- 影响范围：REQ-801～803；D-802 的生产保护仍适用，代码合入不再等待生产重启确认。

### D-801 仅增加观察性日志

- 日期：2026-10-09
- 背景：用户要求先查实再修复，旧现场入口未记录。
- 备选项：直接猜测修复；增加完整创建链路证据。
- 最终决定：复用现有本地 trace/breadcrumb/daemon log，只记录允许字段和身份摘要。
- 原因：不改变运行行为，不扩展 wire，不输出用户内容。
- 影响范围：REQ-801～803，客户端与执行主机各写自己的日志。

### D-802 代码验证与现场生效分开交付

- 日期：2026-10-09
- 背景：用户授权加日志，未授权替换或重启正在使用的两端应用；旧 daemon 仍能承载存活会话。
- 最终决定：诊断代码及本地验证交付完成；生产部署等待用户确认，整体状态 blocked，不标为 done 或 release-ready。本轮不自行创建或云端归档故障修复方案。
- 原因：必须先确认新构建 readiness，再对下一次现场记录作承诺，不能擅自影响现有 writer。
- 风险与补齐计划：历史入口仍无法反推；获准部署后执行受控现场复现，再进入修复方案和验收。
- 影响范围：REQ-801～803及部署后的现场验收。
