## 方案要点

**注入点**:不往终端里打字,而是用 agent 自己的 hook。Claude Code 与 Codex 的 hook 能力**完全对等**,
`Stop` 可以用 `decision: block` 加 `reason` 阻止停止并注入续跑指令,
`PostToolUse` 拿得到 `tool_name` / `tool_input` / `tool_response`。

**核心是机制不是提示词**。十一种失败模式里十种有机制兜底:

| 失败模式 | 机制 |
|---|---|
| 改小目标 / 压缩后忘了目标 | objective 存磁盘、模型无写通道、每轮原文重注入 + SessionStart 重注入 |
| **假完成** | **完成守卫**:声称完成时跑验收命令,失败原样回灌,宿主计假完成次数 |
| 改测试而不是改代码 | 证据账本 + 逐语言篡改特征扫描 |
| 改验收本身 | 验收文件哈希锁定 + PreToolUse deny 对状态目录的写入 |
| 空转 / 只写计划 / 声称跑了测试 | 证据账本(与模型叙述无关的地面真相) |
| 留 TODO 声称完成 / 原地打转 | 占位符扫描 / diff 内容指纹 |

唯一没有机制的是「偷换成更容易的方案」—— 判断意图没法用规则做,这条和 Codex 一样只有提示词。

## 三条代价(必须对用户讲清楚)

1. **插件会修改你的 agent 配置文件**(只写项目级),而这**不会出现在 Orca 安装时的 consent 清单里**
   —— fs 访问不在 capability 模型内。
2. **只支持有 block 语义 hook 的 agent**(claude / codex)。
3. **远程 / SSH / WSL 会话不支持** —— agent 与 hook 在远端,本地 worker 写不进去。

## 文档约定

- **画图用 Mermaid**,不用 ASCII 框线图(文件树的 `├──` 是例外,保留)
- 占位符用大写下划线(`KEY`、`WORKTREE`、`GOAL_ID`),**不用尖括号**。
  尖括号会被部分 Markdown 编辑器判为 HTML/JSX,导致文件「只能在代码模式下编辑」并在保存时被改写
  (已发生过:路径占位符被吞掉、`>` 变成实体、粗体标记被挪进反引号)。
- 提示词模板**单独成文件**放在 [`prompts/`](./prompts),不内嵌进设计文档 ——
  它们是可直接内联为常量的构建产物,不是散文;而且含字面 XML 标签,嵌进正文会触发编辑器的 HTML 误判。
