## 前两轮发现的问题

1. **第一轮：链接选了 VPN 地址。** 主机自动选择的链接 IP 是 utun4 的 VPN 地址，本机浏览器都打不开（`ERR_ADDRESS_UNREACHABLE`）。原因是 minizc 开着全隧道 VPN，用来判断默认网卡的探测地址（`192.0.2.1`、`8.8.8.8`、`1.1.1.1` 等）全部走 utun4。已修复：链接 IP 按网卡类型排序，物理网卡上的局域网地址优先，探测结果落在隧道网卡上时忽略；新增 `artifact-share-lan-ip.test.ts`（AT-14）。
2. **第二轮：测试步骤顺序错误。** TC-11 断开再重连 SSH 后，之前的 SSH 终端已失效，TC-15 的命令没有进入终端。调整为在断开前执行命令行用例，不是产品问题。

## 对本机造成的改动

- `~/.ssh/authorized_keys` 临时多一行（注释 `orca-artifact-lan-share-validate-temp-key`），每轮结束撤销，已核对无残留。
- `~/.orca-artifact-share` 由夹具创建并在每轮结束删除；`/private/tmp/orca-artifact-lan-share-validate` 已删除。
- 客户端实例向 minizc 部署测试版远程组件时，Orca 自带的旧版本回收删除了 `~/.orca-remote/` 下三个没有进程在用的旧 relay 目录（`relay-0.1.0+3d2a74b91373`、`+82bb49617a2e`、`+8a9daf38c289`，当时无任何 relay 进程）。mbp5 上的 Orca 下次连接 minizc 会重新上传一次 relay，旧目录里的 `relay.log` 已不在；`terminal-history` 未受影响。测试版 relay 目录已在结束后删除。
- 没有残留的测试进程或 relay 进程，18787 端口已释放。
