# 总管（调度会话）本机真机验证（2026-11-05）

- 对应：需求 REQ-022、REQ-030、REQ-031；技术方案 [§6.3](../../solutions/任务为主的工作流技术方案.md) 开工前验证 7～11。
- 构建：本分支的 e2e 构建（`electron-vite build --mode e2e`），CLI 用 `tsc` 输出到 `out/cli`。
- 方式：Playwright 驱动隐藏窗口的隔离实例（Xvfb，独立 userData）。智能体是 `agentCmdOverrides` 指向的假 `claude`（Node 脚本），它记下参数、工作目录、`ORCA_*` 环境变量和收到的每一行输入。总管的命令用它窗格的 `ORCA_PANE_KEY` 调用编译好的 CLI；唤醒指针到达后，假智能体在自己的终端里真的执行一次 `orca task inbox --json`。代理状态通过 Orca 的 hook 端口发 Claude 的 `UserPromptSubmit` 和 `Stop`。用户操作都走界面。
- 证据（本机目录，不进仓库）：`.docs/本地任务管理-ui-validation/2026-11-05/`。`README.md` 是逐条结果，`evidence/` 是截图和运行记录，`scripts/dispatcher.spec.ts` 是驱动脚本。

## 第二轮（同日）

聊天视图、总管台账页和代码审查修复之后，用同一脚本按新界面重跑，全部通过：

- 新开的总管是聊天视图，窗格头部可切回终端；
- 任务页导航最上方是「总管」，台账页列出等你确认的提案、它盯着的任务（带最新进展）、它派出的任务和还没处理的动态；
- 提案执行前先认领；确认后你停在台账页；
- 「需要你」视图里的提示能回到台账页；
- 在台账页可以让它不再盯一个任务。

## SSH 场景（同日）

- 夹具：root sshd 只监听 `127.0.0.1:2222`，密钥和配置放在会话临时目录（不改 `~/.ssh`）。Orca 连上后在那台主机上部署本地构建的 orcad 模板（linux-x64-glibc）。SSH 主机就是本机，所以 SSH 主机上的仓库、假智能体脚本和桌面在同一块盘上。
- 驱动脚本：`.docs/本地任务管理-ui-validation/2026-11-05/scripts/dispatcher-ssh.spec.ts`。证据在同目录的 `evidence/ssh/`。

### 第一次：不通过

- SSH 主机的仓库在桌面这边是 `runtime:<环境>` 主机，任务项目建在 SSH 主机自己的任务库里（D-008）。
- 总管提案「在 SSH 工作区新建任务并开会话」执行失败，回报「name the task project: more than one could take this task」：总管第一版只在桌面的任务库里找项目。提示文字也不对，实际一个可用项目都没有。
- 处理：补上跨任务库（提交 7b1cc4e6a），见技术方案 M13「其他库的任务」。

### 第二次（补上跨任务库之后）：通过

| 项                          | 结论 | 说明                                                                                                                                                 |
| --------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 派活到 SSH 工作区           | 通过 | 确认后提示「Done 1 of 1」；SSH-1 建在 SSH 主机的库里，挂上那台主机的工作区，会话开在那台主机上                                                       |
| SSH 主机上的会话            | 通过 | 假智能体在 SSH 主机的仓库目录启动，第一句指令带 SSH-1 的任务说明；`ORCA_USER_DATA` 是 SSH 主机的 `~/.orca`                                           |
| 在 SSH 窗格里调 `orca task` | 通过 | 方案验证 8 的 SSH 一半：`orca task show SSH-1 --json`、`orca task progress SSH-1 --needs-you` 都返回 0，读写的是 SSH 主机的库                        |
| 动态转进总管的收件箱        | 通过 | 桌面总管的收件箱列出 SSH-1 的状态变化、新会话和「Written back from the SSH host.」，任务 id 是 `runtime:<环境>/<id>`                                 |
| 台账页                      | 通过 | 「它盯着的任务」列出 SSH-1，带「Check the SSH result」                                                                                               |
| 主机失去联系                | 通过 | 断开 SSH 后收件箱多一条「loopback sshd is out of contact: its tasks can't be confirmed (unverifiable) until it is back」；任务页顶部提示主机不在联系 |
| 失联时给 SSH 会话追加一句   | 通过 | 提案确认后该项回报「the session's host is out of contact (unverifiable)」，没有对主机重连或重试                                                      |

- 夹具注意：SSH 主机按它自己的智能体设置启动会话，桌面的 `agentCmdOverrides` 不会带过去。脚本经 `settings.mutateAgentLaunch` 把假 `claude` 设在那台主机上；第一次重跑没设，主机启动了本容器里真的 `claude`，看起来像会话没起来。
- 未覆盖：恢复联系后的「back in contact」只有单元测试；配对服务器没有真机验证。
- 清理：停掉 sshd 和测试部署的 orcad，删掉测试中新建的 `~/.orca`、`~/.orca-remote`、临时目录和会话临时目录里的密钥。
