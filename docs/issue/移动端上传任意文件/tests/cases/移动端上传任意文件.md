# 移动端上传任意文件 Test Cases

> 本文档是可重复执行的测试规格，不记录某一次测试的实际结果、环境、版本、PASS/FAIL、截图或缺陷。

## 1. 范围与关联需求

- 功能范围：手机端「照片 / 文件」入口、任意类型文件的选择与分块上传、电脑端按工作区写入目标机器临时目录、交给终端或 agent、新旧版本组合、临时文件清理。
- 关联需求：REQ-001、REQ-002、REQ-003、REQ-004、REQ-005、REQ-006。
- 场景约定：「本机工作区」指工作区在运行 Orca 的电脑上；「SSH 工作区」指工作区在电脑经 SSH 连接的另一台机器上。凡标注「本机 + SSH」的用例两种都要执行。
- 不在本文件覆盖的范围：相册图片上传本身（上游既有能力，仅回归 TC-002）。

## 3. Test Cases

## TC-001 附件按钮弹出「Photo / File」

- 关联需求：REQ-001
- 功能模块：终端输入栏、聊天输入框
- 优先级：P0
- 测试类型：功能（真机，本机 + SSH）
- 前置条件：手机已与电脑配对；工作区内有一个终端会话，并能切到聊天视图。

### 操作步骤

1. 在终端输入栏点按回形针按钮。
2. 切到聊天视图，点按输入框的回形针按钮。

### 预期结果

1. 两处都弹出标题为「Attach」的底部菜单，含「Photo」「File」两项。
2. 菜单关闭后才出现系统选择器。

## TC-002 「Photo」沿用相册流程

- 关联需求：REQ-001
- 功能模块：相册附件（回归）
- 优先级：P1
- 测试类型：回归（真机）
- 前置条件：同 TC-001。

### 操作步骤

1. 在终端输入栏选择「Photo」并选一张照片。
2. 在聊天输入框选择「Photo」并选一张照片。

### 预期结果

1. 终端收到图片粘贴，与改动前一致。
2. 聊天输入框出现图片待发项，与改动前一致。

## TC-003 文件选择器可选任意类型

- 关联需求：REQ-001
- 功能模块：文件选择
- 优先级：P0
- 测试类型：功能（真机：原生会话页与网页版会话页）
- 前置条件：手机「文件」里有 `report.pdf`、`logs.zip`、`notes.txt`。

### 操作步骤

1. 选择「File」，依次浏览上述三个文件。

### 预期结果

1. 三个文件都可被选中，不再置灰。

## TC-004 本机工作区：写到本机私有临时目录并保留原名

- 关联需求：REQ-002
- 功能模块：电脑端写入
- 优先级：P0
- 测试类型：功能（真实 App）
- 前置条件：工作区在运行 Orca 的电脑上，`git status` 干净。
- 测试数据：约 3 MiB 的 `设计 说明 v2.pdf`。

### 操作步骤

1. 以手机身份上传该文件。

### 预期结果

1. 返回路径位于电脑应用临时目录下的 `orca-file-attachments-{uid}/{时间戳}-{uuid}/设计 说明 v2.pdf`。
2. 该根目录权限为 `700`。
3. 文件内容与原文件逐字节一致。
4. 工作区 `git status` 仍然干净。

## TC-005 SSH 工作区：写到 SSH 主机临时目录

- 关联需求：REQ-002
- 功能模块：电脑端写入
- 优先级：P0
- 测试类型：功能（真实 App，SSH）
- 前置条件：电脑已连接 SSH 主机，工作区在该主机上。

### 操作步骤

1. 以手机身份上传 `server-logs.tar.gz`。

### 预期结果

1. 返回路径位于 SSH 主机上远端用户家目录的 `~/.orca-remote/file-attachments/{时间戳}-{uuid}/server-logs.tar.gz`（绝对路径），不在远端共享的 `/tmp`。
2. 文件内容在 SSH 主机上与原文件一致；电脑本机的上传目录里没有它。
3. 远端工作区 `git status` 仍然干净。

## TC-006 同名文件互不覆盖

- 关联需求：REQ-002
- 功能模块：电脑端写入
- 优先级：P1
- 测试类型：功能（自动化）
- 前置条件：无。

### 操作步骤

1. 连续上传两个名为 `same.txt`、内容不同的文件。

### 预期结果

1. 两个返回路径不同，内容各自正确。

## TC-007 SSH 主机未连接时拒绝且不重连

- 关联需求：REQ-002
- 功能模块：电脑端写入
- 优先级：P0
- 测试类型：异常（真实 App，SSH）
- 前置条件：SSH 工作区已连接过，随后断开。

### 操作步骤

1. 断开 SSH 连接后立即上传一个文件。

### 预期结果

1. 上传被拒绝，错误为「The workspace host is not connected」，手机提示「Workspace host is not connected」。
2. 电脑端不发起重连，SSH 连接状态保持未连接。

## TC-008 终端交付：路径可直接被 shell 使用

- 关联需求：REQ-003
- 功能模块：终端交付
- 优先级：P0
- 测试类型：功能（真实 App，本机 + SSH）
- 前置条件：工作区内有一个普通 shell 终端。
- 测试数据：名字含空格、单引号、括号的文件（如 `it's a log (1).txt`）。

### 操作步骤

1. 上传文件，并把手机交付的文本写进终端。
2. 在其前加 `wc -c <` 并回车。

### 预期结果

1. 输出等于上传的字节数；本机与 SSH 工作区都成立。

## TC-009 Claude Code 终端读取上传的 PDF

- 关联需求：REQ-003
- 功能模块：终端交付
- 优先级：P0
- 测试类型：功能（真机）
- 前置条件：工作区内有一个 Claude Code 终端会话。

### 操作步骤

1. 在终端输入栏选择「File」，上传一份 PDF。
2. 在其后输入「总结这个文件」并发送。

### 预期结果

1. agent 读取到该 PDF 并给出与内容相符的总结。
2. 若出现读取工作目录外文件的权限确认，记录其表现（关联未决问题 Q-2）。

## TC-010 聊天交付：路径文本与待发图片

- 关联需求：REQ-003
- 功能模块：聊天交付
- 优先级：P0
- 测试类型：功能（自动化 + 真机）
- 前置条件：聊天视图可用。

### 操作步骤

1. 在聊天输入框选择「File」，上传 `notes.txt`。
2. 再选择「File」，上传 `shot.png`。
3. 输入「读一下这个文件」并发送。

### 预期结果

1. 第 1 步后输入框末尾出现 `{绝对路径} `（含空格时加引号），不出现 `@`，原有文字保留。
2. 第 2 步后出现一个图片待发项，输入框文字不变。
3. 发送后消息直接提交（不停留在 agent 输入框），agent 能读到 `notes.txt` 的内容并看到图片。

## TC-011 90 MiB 文件上传

- 关联需求：REQ-004
- 功能模块：流式写入
- 优先级：P0
- 测试类型：性能（真实 App）
- 前置条件：本机工作区。

### 操作步骤

1. 上传 90 MiB 文件，记录电脑端主进程上传前后的常驻内存。

### 预期结果

1. 上传成功，内容一致。
2. 主进程内存增长明显小于文件大小。

## TC-012 超过 100 MiB 预先拒绝

- 关联需求：REQ-004
- 功能模块：大小校验
- 优先级：P0
- 测试类型：异常（真实 App + 真机）
- 前置条件：无。

### 操作步骤

1. 以 100 MiB + 1 字节的大小发起上传。
2. 在手机上选择一个超过 100 MiB 的文件。

### 预期结果

1. 电脑端在开始时拒绝，错误为「File is too large to attach」，不创建任何目录。
2. 手机提示「File is over 100 MB」，不发起上传。

## TC-013 取消或中断后不留半截文件

- 关联需求：REQ-004、REQ-006
- 功能模块：中断清理
- 优先级：P0
- 测试类型：异常（真实 App）
- 前置条件：无。

### 操作步骤

1. 发起上传并写入第一块后取消。

### 预期结果

1. 写入第一块后出现一个新的上传目录。
2. 取消后该目录被删除。

## TC-014 旧电脑端

- 关联需求：REQ-005
- 功能模块：版本兼容
- 优先级：P0
- 测试类型：兼容（自动化）
- 前置条件：电脑端对 `fileAttachment.startUpload` 回 `forbidden` 或 `method_not_found`。

### 操作步骤

1. 上传 `photo.jpg`（不超过 18 MiB）。
2. 上传 `report.pdf`。

### 预期结果

1. `photo.jpg` 经现有图片通道上传成功。
2. `report.pdf` 不经图片通道，提示「Update Orca on your computer to attach files」。

## TC-015 网页版会话页配旧手机壳

- 关联需求：REQ-005
- 功能模块：版本兼容
- 优先级：P1
- 测试类型：兼容（自动化）
- 前置条件：手机壳未授予 `native.file.pick`。

### 操作步骤

1. 选择一个 1 MiB 的 PDF。
2. 选择一个超过约 18 MiB 的文件。

### 预期结果

1. 第 1 步经 `native.media.*` 上传，文件名按类型生成（`attachment.pdf`）。
2. 第 2 步提示「Update the Orca app to attach files over 18 MB」。

- 优先级：P0

- 前置条件：手机已配对。

### 操作步骤

### 预期结果

1. 返回 `forbidden`。

## TC-018 网页版会话页：原名与 100 MiB

- 关联需求：REQ-004、REQ-005
- 功能模块：网页版会话页
- 优先级：P0
- 测试类型：功能（真机，新手机壳）
- 前置条件：手机壳授予 `native.file.pick`；会话页以网页形态渲染。

### 操作步骤

1. 选择「File」，上传 `report.pdf`。
2. 选择「File」，上传一个约 60 MiB 的文件。

### 预期结果

1. 主机上的文件名为 `report.pdf`（不是 `attachment.pdf`）。
2. 60 MiB 文件上传成功，内容一致。

## TC-017 保留期清扫只删自有过期目录

- 关联需求：REQ-006
- 功能模块：清扫
- 优先级：P1
- 测试类型：功能（自动化，本机 + SSH）
- 前置条件：上传根目录下有一个超过保留期的上传目录、一个未过期的上传目录、一个名字不符合格式的目录。

### 操作步骤

1. 发起一次新上传。

### 预期结果

1. 过期的上传目录被删除；未过期目录与名字不符的目录保留。
