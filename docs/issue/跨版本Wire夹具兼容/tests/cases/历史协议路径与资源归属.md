# 历史协议路径与资源归属

### TC-001 旧路径和唯一迁移路径

关联 REQ-001。分别使用旧路径 `src/shared/terminal-stream-protocol.ts` 和唯一新路径 `src/shared/terminal/stream/terminal-stream-protocol.ts` 的隔离 release checkout 夹具。发布校验均通过，并保留与 checkout commit 绑定的 stamp。实际历史 v1.4.256 两个 cross-version Wire suite 需分别真跑。

### TC-002 缺失和歧义拒绝

关联 REQ-001。在隔离 checkout 中移除终端协议文件，或放置两个同名候选，校验应拒绝发布并指出协议文件缺失；不得因同名文件位于其他 `src/*` 根目录而误接收。

### TC-003 本地和 SSH 测试机资源归属

关联 REQ-001。分别在本地和经 SSH 访问的隔离测试执行机执行相同单测与历史 suite。Git checkout、缓存、临时目录和任何 `127.0.0.1` 测试端口均归执行测试机；清理只操作本例持有资源，不手工删除共享缓存，不连接用户 SSH 服务。记录执行机与 checkout commit；SSH 通路不可用时记未覆盖，不伪称通过。

### TC-004 fork 快照候选与边界

关联 REQ-002。配置指向 `Fartown/orca` 的 remote，在 `HEAD` 与 `origin/main` merge-base 时间前放置 v1.4.245（即使不是 HEAD 祖先），时间后放置 v1.4.256；同一时间放置另一稳定标签，并加入 RC、无效格式标签。默认 baseline 和 recent 均只按稳定版本号从合格标签中选择；时间相等允许，晚发标签与 RC 不入池。不使用祖先关系代替发布时间。

### TC-005 上游与显式版本

关联 REQ-002。上游 remote 未配置为 `Fartown/orca` 时仍从全局稳定标签选择最新版本。显式 `ORCA_CROSS_VERSION_BASELINE_REF=v1.4.256` 和 daemon `--release-ref v1.4.256` 均直通，真实不兼容必须保留失败；REQ-001 已通过的 `cross-version-web-device-key.unit.test.ts` 和 `preflight-workspace-scoped-downgrade.unit.test.ts` 两套 v1.4.256 历史 suite 仍须保留显式验证，不因默认候选变更而失效。

### TC-006 缺失快照与候选不足

关联 REQ-002。fork 缺少 `origin/main` 或无法求 merge-base 时显示明确错误；合格稳定标签少于 recent 所需数量时显示候选不足，不回退超快照版本。分别在本地和 SSH 测试执行机验证 Git、缓存和临时路径由该执行机持有；不触碰用户 SSH 服务或共享缓存。
