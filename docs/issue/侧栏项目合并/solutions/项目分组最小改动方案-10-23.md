# 侧栏同名归类：仅扩展现有分组计算

**保留原仓库分组，在原侧栏区块结果上按显示名称归类。原按钮、菜单、弹窗、设置入口和操作回调全部沿用。** 不建立新的项目归属、成员配置或操作流程。

- 来源：[REQ-611 至 REQ-615](../requirements/requirement.md)、用户指定的显示名称截图及“只改归类”纠正；决策：[D-007](../journal.md#d-007-仅修改侧栏归类撤回所有操作-ui-改动)。作者：Codex。
- 状态：文档已整理并完成范围复核；源码已按最终范围收缩，正在完成最终门禁与 PR #62 更新；不替换用户运行中的应用。
- 本地文件：`docs/issue/侧栏项目合并/solutions/项目分组最小改动方案-10-23.md`；未关联飞书，沿用仓库内评审。

## 1. 现状与目标

### 1.1 改动前：名称相同也分开

下面使用此前已读回的名称说明结构，不表示本轮重新读取或修改了在线 App。方括号表示原执行主机；实际已有的主机/路径消歧样式沿用。

```text
workspace [本机]
  本机原工作区
workspace [mini]
  mini 原工作区
workspaces [dbox]
  dbox 原工作区

Movo
  原工作区 [主机一]
  原工作区 [主机二]
```

前三个普通目录没有共同仓库身份，各有原 Repo、Project/setup 和工作区，因此当前显示为三个项目头；本机和 mini 即使同名也不合并。已经正确识别为同一仓库的 Movo 原本就只有一个头，不需要本功能再合一次。

### 1.2 改动后：先保留原分组，再补同名归类

**不改任何名称时：三个头变为两个头。** 本机和 mini 的 `workspace` 合在一起，dbox 的 `workspaces` 仍独立。

```text
workspace
  本机原工作区
  mini 原工作区
workspaces
  dbox 原工作区

Movo                         ← 原仓库分组保持原样
  原工作区 [主机一]
  原工作区 [主机二]
```

**将 dbox 的已有显示名称改成 `workspace` 后：三个原工作区归在一个头下。再改成 `workspace-dbox` 后：dbox 的原工作区单独显示。** 这两步只使用原设置页，效果见本节后面的完整示意，不增加合并入口。

### 1.3 改动前后逐项对照

| 对象/行为                                              | 改动前                             | 改动后                                                               |
| ------------------------------------------------------ | ---------------------------------- | -------------------------------------------------------------------- |
| 名称为 workspace、workspace、workspaces 的三个普通目录 | 三个项目头                         | 两个项目头，前两项同名归类                                           |
| 三个目录显示名称都为 workspace                         | 仍为三个独立头                     | 一个头，下面仍是三个原工作区                                         |
| 将其中一个显示名称改为 workspace-dbox                  | 原头改名，原生身份保持             | 对应工作区离开同名归类，原生身份仍保持                               |
| 原本已合并的同仓库项目                                 | 按原仓库身份合并，包含原有拆分例外 | 继续使用同一原结果，不因某个副本改名而强制拆散                       |
| 不同仓库恰好同名                                       | 原本独立                           | 只合并显示；各自 Git、目录、账号、工作区和执行目标独立               |
| 文件和工作目录                                         | 各自在原主机的原路径               | 完全相同，不产生共同根目录，不移动文件                               |
| Repo/Project/setup/工作区/会话 ID                      | 各自使用原值                       | 仍使用原值；另一个显示键只用于找到归类后的头                         |
| 项目头按钮、图标及拖拽                                 | 每个原头持有自己的 repo 上下文     | 一个归类头保留一个原代表 repo；原组件、回调和单目标语义沿用          |
| 折叠状态                                               | 每个原分组键有自己的状态           | 新名称键使用原保存机制；无记录按原默认展开，不继承或删除原键         |
| 手机与旧客户端                                         | 按各自已有逻辑显示                 | 支持新归类的客户端使用新结果；旧客户端仍显示原分区，原数据可继续使用 |

### 1.4 原有模型与完整示意

| 概念            | 现在的含义                                                         | 本次是否改变                     |
| --------------- | ------------------------------------------------------------------ | -------------------------------- |
| 目录            | 某台电脑上的实际文件夹与文件                                       | 不变，不移动或同步文件           |
| Repo            | Orca 对某个 Git 或普通目录的登记，保存 ID、路径、显示名称等        | 沿用已有字段与改名接口           |
| Project / setup | 原逻辑根据仓库来源识别的项目及其主机位置；无共同来源的目录各自独立 | ID、关系与身份推导不变           |
| 工作区          | 关联原目录、主机、执行目录和会话的工作上下文                       | 原路径、归属、终端与业务 ID 不变 |
| 侧栏区块        | 原算法算出的项目头及工作区行                                       | 同名区块共用一个头，原行放到一起 |

三个普通目录目前没有共同 Git 身份，原算法也不按显示名称归类，因此分开。历史读回名称为本机/mini 的 `workspace` 与 dbox 的 `workspaces`；新规则下本机和 mini 合并，dbox 改成同名后加入，再改成不同名后分开。名称来自设置里的“显示名称”，不取磁盘文件夹名代替。历史路径和模型细节见[现状调研](../research/项目目录工作区与属性归属现状.md)。

```text
显示名称都为 workspace：          dbox 改为 workspace-dbox：
workspace                        workspace
  原工作区 [本机]                  原工作区 [本机]
  原工作区 [mini]                  原工作区 [mini]
  原工作区 [dbox]                 workspace-dbox
                                   原工作区 [dbox]
```

## 2. 归类规则与处理顺序

1. 先按原算法产生原生区块和排序。同仓库自动关系及独立 checkout 等原有例外原样保留。
2. 在同一个既有显示容器内，按**原区块实际显示的标题**归类。手工 ProjectGroup、按主机查看等容器边界不改变。
3. 标题去除首尾空白后精确比较；不忽略大小写，不按路径、名字片段或任意副本别名关联。空名、无法建立原映射的区块沿用原结果。
4. 两个或以上可归类区块同名才组合；单区块沿用原键。组合只累积原工作区行、活动信息和 `repoIds`，不改输入对象。
5. 组合头保留原全局区块排序中首个来源的 `repo`，作为原按钮上下文；各行仍持有原 ID。之后继续交给已有容器排序，不增加新的排名规则。

名称比较使用路径消歧之前的原区块 `label`，不把界面自动补的路径后缀作为名称。已有 Project/setup 映射未就绪时保留原回退区块，不为归类额外读主机。按主机查看时，计算额外使用原 setup 的主机作为名称容器，键增加 `::host:<编码主机>`；不同主机不新增名称归并。同一个原生仓库跨主机的既有结果继续保留。

Movo 等原本按同仓库归并的项目，改名不会拆开原仓库关系。同一原项目在不同位置有不同别名时，只取原逻辑选定的标题，不把多个别名作为桥梁串入其他项目。

```mermaid
flowchart LR
  A[现有项目与目录数据] --> B[原仓库分组与排序]
  B --> C[同一显示容器内按标题归类]
  C --> D[原侧栏渲染与操作]
  D --> E[原目录与原执行目标]
```

**原全局区块排序结果决定代表来源**：手动和近期模式分别沿用原手工/活动比较逻辑。桌面 ProjectGroup 内的 `projectGroupOrder` 或活动排序仍由原 `appendProjectGroupSections` 执行。**不承诺归并头必定位于原屏幕中最靠前成员的位置**，也不为此新增排序算法或改组内顺序字段。手机保留它已有的排序链，不假定与桌面的二次排序相同。

## 3. 键、折叠与原操作

名称分组键只是界面内部的归类键，例如 `sidebar-name:<编码名称>`；不同手工分组的键也区分各自容器。原生 `projectId`、`repoId`、工作区 ID 不变，名称键不进入业务接口。

渲染、导航、reveal 和现有 host 标签计算使用一致的显示键。Cmd-J 继续产生原生项目目标；现有 pending reveal 在当前 occurrence plan 中解析到实际显示的名称键，避免改写原项目候选或过滤含义。原 `getProjectGroupingForRepo` 和 `buildProjectOwnershipIndex` 继续表达真实归属，不改成名称归属。

**折叠直接复用原 `toggleCollapsedGroup` 与 `collapsedGroups`。** 新归类键没有记录时按原默认展开；点击时按原流程保存这个键。原来源键不删除、不迁移，不新增“全部来源折叠才继承”或“展开时清理旧键”的规则。改名后按其重新计算出的键读取已有偏好。

**按钮和菜单源码不改。** 原菜单继续接收区块的原 `repo`，设置、新建、移除、图标和拖拽仍走原处理及原主机路由。合并头使用第 2 节保留的代表目录；这不表示对所有同名成员批量操作。不增加目录选择器、子菜单、弹窗、合并设置页或新的目标选择逻辑。拖拽也不改成移动全部同名成员。

```mermaid
flowchart LR
  A[已有项目设置] --> B[修改已有显示名称]
  B --> C[原接口保存并发送已有通知]
  C --> D[重算侧栏归类]
```

## 5. 保存、远端与影响面

不新增字段、数据库、服务、端口、环境变量或网络读取。归类在桌面/手机上消费已有 catalog 和通知；失联、无权限、保存失败均沿用原处理，不增加重连、重试或轮询。

改名仍由原目录登记的 owner 保存：本机 profile、配对 runtime 或既有 SSH catalog owner；文件和进程始终归原执行主机。旧服务端继续发送原字段，旧客户端显示原分区；映射信息不足时保留原布局，等已有 catalog 通知后重算，不新增协议升级要求。macOS、Linux、Windows/WSL、SSH 的名称规则相同，Git 与普通目录均覆盖。

现有通知行的主机标签继续按原生项目判断，不因显示同名而扩展通知或任务语义；不修改 `getNoticeHostContextLabels`。

变化仅为项目头数量、工作区行位置及相应显示键。设置、文件、终端 cwd/PTY/会话、Git remote/upstream、任务、AI Vault、快捷命令、自动化和运行偏好继续使用原 ID 和原作用域。回退时移除名称组合即可，不需要归属或配置迁移。

### 5.1 影响矩阵：哪些表现变化，哪些处理保持

| 范围                 | 会发生的变化                                                            | 保持的处理/边界                                                      | 验证重点                                             |
| -------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| 项目头与工作区行位置 | 同名头减少，原行出现在同一头下                                          | 工作区行 ID、内容、选择和执行归属不因归类改写                        | 头数由 3→2→1→2，行仍对应原目录                       |
| 数量和活动显示       | 同一头汇集原区块的可见行与活动信息；按头计数的父分组项目项数随头数减少  | 行级统计、归档、置顶及过滤继续走原逻辑；工作区不会因合头被删除       | 合头前后原行集合相同；筛选后的计数与实际可见行一致   |
| 排序                 | 多个原头压为一个，归类头使用保留的原代表目录参与后续原排序              | 全局/ProjectGroup 手动排序及近期比较器不重写，排序字段不迁移         | 分别核对手动与近期模式；不把全局首项误当成原屏幕首项 |
| 折叠与展开           | 点击归类头作用于其显示键，新键可能没有旧记录                            | 原 toggleCollapsedGroup、保存接口与默认行为保持；原键不清理          | 新头默认、点击往返、改名拆开后的原键状态             |
| 键盘与定位           | 要找到归类后的头，并在需要时展开原父分组                                | 复用原模式切换、父链、滚动、高亮；仅补显示键识别                     | Cmd-J、非 repo 模式、折叠及嵌套 ProjectGroup         |
| 原按钮与拖拽         | 多个头归为一个后，侧栏只留下该头的一套原操作入口                        | 上下文是第 2 节定义的代表 repo；不新增选择器，不批量操作所有成员     | 设置/新建/移除/拖拽仍传代表 repo 的原 ID 与 host     |
| 文件、工作区与终端   | 仅列表位置可能变化                                                      | 原路径、cwd、Git 状态、工作区、实例、会话、PTY 和原执行主机保持      | 改名前后 ID/路径比对，现有远端终端保持可写           |
| 主机标签与通知       | 项目头的原主机上下文计算读取新的显示分组                                | 原标签组件不改；通知仍按原生 projectId/repoId 判断，不扩成名称组通知 | 跨主机同名、同名主机、失联缓存及原通知行为           |
| 手机与混合版本       | 新版本手机使用同一名称归类结果                                          | 原工作区操作标识、各端已有排序和原协议保持；数据不足降级原布局       | 移动列表、老字段兼容、catalog 到达前后               |
| 名称与 UI 偏好保存   | 用户改名仍保存原 displayName；点击折叠仍保存现有 collapsedGroups 的键值 | 不新增成员名单、配置字段或数据库；改名失败沿原提示，不伪装成功       | owner 回读、重载持久化、失败时不改变归类依据         |
| 其他项目能力         | 不增加同名成员之间的共享范围                                            | 任务、AI Vault、快捷命令、自动化、Git、运行偏好均按原 ID             | 对照原 scope 与业务请求参数，不接收名称显示键        |

归类头上的图标、连接 gate、菜单和拖拽继续代表保留下来的那个原目录，不能解释成全组共享同一仓库或运行环境。这是复用原上下文的结果，不增加新的操作交互。

## 6. 验收与当前缺口

1. 本机/mini/dbox 的普通目录同名归类、改名分开；不同名和空名保留原结果。
2. 同仓库不同名仍沿原规则；独立 checkout、手工分组、按主机查看的边界保持，不出现别名传递串组。
3. 原工作区行和身份不变；代表目录按第 2 节确定，仍用原排序；导航/reveal/手机使用一致的显示键。
4. 原按钮和菜单文件无功能差异；折叠用原默认与保存逻辑，无继承、迁移或清理旧键。

### 6.3 测试层次与完成标准
