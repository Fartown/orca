## 4. 过程记录：两轮执行与一次误判

第一轮 SSH 用例 BLOCKED，两次误判都已定位并修正，记录在此以免重复踩坑。

1. **非特权 sshd 起不来 relay。** 最初用当前用户在 22222 端口起了一个一次性 sshd 当 SSH 主机。Orca 用 `nohup … &` 启动 relay，报 `nohup: can't detach from console: Inappropriate ioctl for device`，relay 起不来。一度判断为「macOS 不能当 Orca 的 SSH 主机」。用 `pty.fork()` 在普通 PTY 下跑同一条命令证伪了该结论：那里 nohup 正常分离。真因是**非特权 sshd 的会话建立方式**，改用本机 root 运行的 sshd（2222）后一次通过。
2. **验证脚手架把自己的问题读成了产品缺陷。** 上一次 omnibox 关闭时内容仍短暂挂载，脚本直接向该实例输入，命中的是 `menuOpen` 已为 false 的组件，表现为「工作区主机就绪后才能打开绝对路径。」。据此曾改写主机策略实现，确认误判后已完整还原，并恢复被删的 selector 记忆化测试。修法是每次打开前等待上一个 omnibox 完全卸载。

另有两点与结论无关但值得知道：Playwright 的页面夹具名为 `orcaPage`，用默认的 `page` 会去拉起 chromium 而非 Electron 窗口；应用在本机按系统区域设置启动为中文界面，脚本在断言前显式切到英文。

- 向 `~/.ssh/authorized_keys` 临时追加了一把一次性密钥（注释 `orca-absolute-path-validate-temp-key`），跑完由夹具的 EXIT trap 撤销。已核对：运行后的文件与运行前备份逐字节一致。
- SSH 主机就是本机，relay 按 `relayGracePeriodSeconds: 1` 部署并在用例末尾 `resetRelay` + `disconnect`。核查无遗留 relay 进程。
- `~/.ssh/known_hosts` 新增了 loopback 主机密钥若干条（由 `ssh` 客户端在排查过程中写入）。
- Playwright 下载了 `chromium-1217` 到共享缓存（后证明不必要，真因是夹具名应为 `orcaPage`）。
