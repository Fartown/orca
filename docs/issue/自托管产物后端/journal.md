## 2. 决策点记录

### D-006 实施中收窄分享范围、取消共享内核

- 日期：2026-09-17
- 背景：实施与回归中发现三处和方案原稿不符的情况：抽共享内核（WP0）要改动白名单外的上游文件和 Goal 自有文件；按 Git 根目录猜工作区可能把家目录这类仓库整个开放，且命令行与界面的范围不一致；`errors.ts` 被 Issues 功能锁定为上游原样。
- 备选项：按原稿改动上游文件并扩大白名单；或在本功能目录内实现同样的规则。文件不在工作区里时：往上找 Git 根目录；或只开放文件所在目录。
- 最终决定：取消 WP0，路径安全与分发请求在本功能目录内按原规则实现并由本功能测试覆盖；文件不在任何工作区里时，只开放已分享的上层文件夹或文件所在目录，命令行取终端所在工作区；分享前在弹层写明会开放哪个工作区；分享错误码改经 `dispatcher-error-response.ts` 接缝返回。
- 原因：遵守「一个功能一个分支、上游文件只改注册点」和其他功能的锁定规则；链接开放整个工作区，范围宁可小，不可猜大。
- 影响范围：方案 5.3、5.5、M0、M5、M6、M9、5.7、6.4 与接口契约；REQ-305、REQ-306、REQ-308。

### D-005 分享服务作为静态文件服务，按工作区随机码直接读取原文件

- 日期：2026-09-16
- 背景：重构方案初稿把分享内容复制到分享目录。用户指出被分享的文件不应复制，而应指向原始位置的相对路径，分享服务应是静态文件服务。
- 备选项：复制内容快照；静态文件服务并开放整个工作区；只开放文件所在目录；只开放文件及其引用的资源。链接带随机码或不带随机码。
- 最终决定：静态文件服务，不复制文件；链接为「随机码 + 文件在工作区里的相对路径」；一个随机码开放整个工作区（不列目录，拒绝 .git、.env 等敏感路径和越出工作区的符号链接）；停止分享即作废随机码。
- 原因：用户确认；相对路径资源和互相引用的文档可直接打开，保存后即为最新内容；随机码防止局域网扫描（2026-09-16 minizc 已被扫描器探测）。
- 影响范围：方案 2～6 节与接口契约；Q4 随之确定为不包含未保存的修改；停止分享以工作区为单位。

### D-004 下线外挂服务，由文件所在电脑上的 Orca App 提供局域网分享

- 日期：2026-09-16
- 背景：用户在 mbp5 的 Orca 中通过 SSH 打开 minizc 上的文件分享失败。请求发往 mbp5 本机 `127.0.0.1:8787`，该端口是 llm-proxy，文档正文与 Orca 账号 token 被转发到内部上游服务并返回 404。另查明外挂服务会被畸形请求打崩，且对列表、覆盖、删除不做鉴权。
- 备选项：保留外挂服务并增加按设备的地址配置；把分享服务挂在 relay 进程中；每台电脑一个独立常驻后台进程；分享服务放在 Orca App 里、跟着 App 启停。
- 最终决定：分享服务放在 Orca App 里、跟着 App 启停。文件在哪台电脑就由那台电脑上的 Orca 提供链接；该电脑的 Orca 开着且开启了局域网分享时提供，退出即停止；与你是否连着那台电脑无关；发布不走网络 HTTP、不依赖 Orca 官方账号；外挂服务下线，旧链接不保留。
- 原因：用户确认 artifact 是局域网服务、应由 Orca 自己实现、服务跟着 App；relay 跟着连接走、空闲 15 分钟退出，不能承载；独立常驻进程与「跟着 App」不符且需额外的启动与版本接替；外挂方案需要每台电脑单独部署，且无法确认对端身份。
- 影响范围：REQ-201～REQ-205 将由 REQ-301～REQ-309 替代；D-003 的固定本地默认地址被取代；技术说明与测试用例需重写；方案见 solutions/局域网Artifact分享服务重构方案.md。

### D-003 固定本地默认地址修复配置丢失

- 日期：2026-09-10

- 最终决定：Artifact 业务入口默认 http://127.0.0.1:8787，保留显式参数和环境覆盖；独立后端单个 HTTP 端口提供 API 和分享页面。
- 原因：按用户明确指令完成最小修复，不增加配置或启动流程。
- 影响范围：REQ-201、REQ-205；共用解析器其他调用方保持原默认值。
