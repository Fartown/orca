# TC-415 Linux 服务应用内更新

关联 REQ-414。

| 场景         | 操作与预期                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 本地更新     | 隔离 profile 启动包 A 的受监督服务，网页点击普通检查入口；检查到包 B 后下载、安装，服务返回 B 的版本和新 runtime ID，原终端仍可读取及执行 |
| SSH 更新     | root sshd 接受独立测试用户；客户端通过转发访问远端服务，下载和替换发生在 SSH 主机，客户端安装及配置不变                                   |
| 来源与监督   | 普通直接运行、无 AppImage 来源、非 Linux 或失去父进程 IPC 时不得假报 Linux 自动更新支持                                                   |
| 完整性       | 无效下载或 SHA512 不符时拒绝安装；旧服务保持可用，不把错误当成最新版本                                                                    |
| 替换与版本   | AppImage 原路径替换，实际新包版本必须等于 handoff 目标；新进程 ready 前不报完成，不生成安装备份                                           |
| 停止和失败   | 停止发生在 probe 或等待中不得重新拉起；安装失败/版本不匹配保留明确失败，不形成无界重启                                                    |
| 页面与旧服务 | 普通检查按钮打开真实更新界面，服务版本可信；旧服务仍显示手动更新；连接不可达时不自行请求或重连                                            |
| 跨平台回归   | macOS 既有 handoff、Windows 和 deb/rpm 的支持判断保持通过                                                                                 |
| 数据目录别名 | 相同目录通过真实路径或符号链接启动均可接管更新；handoff 文件未创建时也通过；其他目录与错误文件名仍拒绝，本地和 SSH 各核对一次             |
| 安装验收判定 | 初始化未完成、automatic 为 false、运行版本不符、原标签/PTY/provider session 丢失均失败；只有初始化完成且原会话保留才通过                  |
| PTY 生命周期 | 标签、PTY 与 provider ID 相同但 incarnationId 改变时失败；任一快照缺少已有 PTY 的 incarnationId 时失败；没有 PTY 的标签可正常保留         |
