# 终端创建链路诊断

## 背景与目标

原始事实：octo 两个终端同时使用同一 provider session；17:54 的创建入口未被日志记录。用户确认要求“加个日志”“要保证下次一定查到问题”。本轮记录因果证据，不宣称已查明或修复历史故障。

## 范围

In Scope：本地、paired runtime、SSH 的创建/恢复入口、RPC、PTY 候选与结果的脱敏诊断。Out of Scope：修改恢复、去重、状态生产者、wire、退出策略；重启或替换用户运行的应用；上传日志。

### REQ-801 入口及请求关联

当前状态：实现中。本地：记录 AI Vault、自动恢复、冷恢复、IPC 和全部新 Tab；远程/SSH：记录执行主机请求与调用方摘要，不把远端失败当成本地请求。验收：可区分入口，并以请求、Tab/leaf、PTY 摘要关联两端事件。

### REQ-802 候选与结果记录

当前状态：实现中。本地和 SSH 均记录实际已有候选、提前接回、provider 返回、最终提交/失败；只读取既有数据，不增加探测或改变 live / unverifiable / exited 判断。验收：早期返回、失败和并发路径均有记录。

### REQ-803 隐私与行为保持

当前状态：实现中。本地和 SSH 均只写身份摘要、闭合入口名、布尔字段；不写命令、prompt、环境变量、凭据、输出和异常正文。日志保留在各自执行主机现有 logs 中，磁盘/记录失败不改变请求结果。验收：隐私、失败开放和磁盘落盘测试通过。

## 已确认及未决问题

用户授权加日志，不授权重启。旧现场确切入口仍未知；运行实例只有升级到此代码后才具备新取证能力。磁盘不可写、未部署新版等不能保证有记录，必须明确核查。
