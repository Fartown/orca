# 远程工作区绝对路径打开

## 1. 背景与目标

标签栏「+」弹窗（omnibox）今天已经能按输入的相对路径打开或创建文件，本地、SSH、远程 runtime 三种工作区都可用。但输入绝对路径时，只有本地工作区放行；SSH 或远程 runtime 工作区一律显示「绝对路径需要本地工作区。」状态行，没有可点的选项。这是上游 PR #10222 的明确设计（"remote and SSH workspaces stay blocked"）。

目标：在弹窗输入绝对文件路径时，工作区归属本地就打开本机文件，归属 SSH 主机就打开远端文件；远程 runtime 工作区在协议允许范围内打开。现有相对路径、URL、搜索、智能体启动等行为不变。

目标分级：P0 为 SSH 工作区放行、平台校验、归属标记与 fail-closed；P1 为远程 runtime 工作区的协议边界降级。优先级不等于实现或验收状态。

## 2. 用户场景

用户在远程项目里工作，从终端输出、Agent 回复或其他地方复制到一个远端绝对路径（例如 `/home/me/notes/known-pitfalls.md`），点击标签栏「+」把路径粘进弹窗，期望直接出现「打开文件」行，回车后在当前 pane group 新开一个编辑器 tab 显示该远端文件。文件不存在或是目录时，在弹窗内看到错误行并可继续修改输入。

## 3. 范围

### In Scope

- 「+」弹窗对绝对路径的分类、校验、执行与落 tab；覆盖 git worktree 与 folder workspace；覆盖本地、SSH、远程 runtime 三种归属。
- 绝对路径的平台校验按工作区主机判定，而不是按客户端平台。
- worktree 之外的 SSH 文件沿用编辑器已有的 external SSH file 契约。
- 归属未就绪或提交过程中主机漂移时拒绝，保持 fail closed。
- fork 功能登记、门禁、测试用例与 UI 验证证据。

### Out of Scope

- 远端为 Windows 的 SSH 主机（用户确认不考虑）。
- 远程 runtime 工作区 worktree 之外的绝对路径（协议不支持，只做明确降级，不新增 RPC）。
- `~/` 家目录路径展开（本地入口今天也不支持）。
- 编辑器 tab 右键「在本机打开」、Markdown `file://` 链接等复用同一守卫的其他入口。
- 打开后编辑器的读写、监听、保存行为。
- 新增 RPC、IPC 或 relay 能力；UI 视觉改动。

### 来源与结论分类

- 原始事实（来自代码与上游提交）：弹窗绝对路径在远程工作区被 `isLocalPathOpenBlocked` 封禁；SSH 的文件系统 IPC 带 `connectionId` 时不限制 worktree 范围；终端链接入口已能在 SSH 上打开 worktree 外绝对路径并写入 `externalSshTargetId`；远程 runtime 的 `files.*` RPC 只接受 worktree 相对路径；路径平台校验目前按客户端平台。
- 用户已确认结论：见第 9 节。
- 推断（已随实现与验收确认）：用户截图中的 `known-pitfalls.md` 属于相对路径、无精确匹配的场景，与本需求的绝对路径场景不同；本需求按用户文字描述"输入文件地址"理解为绝对路径。

> 只有原始事实和用户已确认结论可升级为业务规则或验收标准。

## 5. 需求点

### REQ-301 本地工作区行为不变

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-11 真机验证通过）。
- 描述：本地 git worktree 与本地 folder workspace 输入绝对路径时，分类、授权、stat、打开与今天完全一致。
- 业务规则：本地工作区继续按客户端平台校验路径根形态；继续调用本地路径授权。
- 验收标准：
  1. 现有本地放行、平台不符、`~` 拒绝、目录拒绝、不存在报错的单测全部保持通过。
  2. 本地工作区真机回归：输入本机绝对路径新开 tab。

### REQ-302 SSH 工作区绝对路径在远端打开

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-11 真机验证通过）。
- 描述：工作区归属 SSH 主机时，输入绝对路径出现「打开文件」行；提交后在远端 stat 并打开，不再显示「绝对路径需要本地工作区。」。
- 业务规则：stat 与读取必须带该工作区的 `connectionId`；不得调用本地路径授权；不得回落到本机文件系统。
- 验收标准：
  1. SSH git worktree 与 SSH folder workspace 下，输入 POSIX 绝对路径得到 `absolute-file` 行。
  2. 提交后 `fs:stat` 以 `connectionId` 发起；`authorizeExternalPath` 未被调用。
  3. 文件存在且非目录时在目标 pane group 新开编辑器 tab；不存在或为目录时弹窗内显示错误行。

### REQ-303 路径平台按工作区主机判定

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-11 真机验证通过）。
- 描述：绝对路径根形态的校验基准不再固定为客户端平台。
- 业务规则：远程工作区（SSH、远程 runtime）一律按 POSIX 绝对路径校验；本地工作区按客户端平台校验。
- 验收标准：
  1. Windows 客户端连接 Linux SSH 主机，输入 `/home/x/a.md` 通过校验并可打开。
  2. macOS 客户端在本地工作区输入 `C:\x.md` 仍被拒绝（与现状一致）。

### REQ-304 worktree 外 SSH 文件沿用 external SSH file 契约

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-11 真机验证通过）。
- 描述：SSH 工作区打开 worktree 之外的绝对路径时，tab 需要携带主机归属标记，编辑器读取与恢复才能正确定位主机。
- 业务规则：路径不在 worktree 内时，`openFile` 写入 `externalSshTargetId = connectionId`，tab 标题为完整路径；路径在 worktree 内时不写标记，标题为相对路径。与终端链接入口的写法一致。
- 验收标准：
  1. worktree 外路径打开后 `OpenFile.externalSshTargetId` 等于工作区的 `connectionId`。
  2. worktree 内路径打开后无该字段，`relativePath` 为相对路径。

### REQ-305 归属未就绪与主机漂移时拒绝

- 目标级别：P0；当前状态：已实现（单测覆盖）。
- 描述：保持上游 fail-closed 行为。
- 业务规则：工作区归属无法解析（SSH 仍在连接、repo 未 hydrate、本地与配对 runtime 归属冲突）时显示状态行「工作区主机就绪后才能打开绝对路径。」，不给可点行；提交过程中归属主机或连接 id 发生变化时中止，不调用 `openFile`。
- 验收标准：
  1. 归属未解析的既有单测场景全部保持封禁。
  2. stat 期间归属由 SSH 变为本地或 `connectionId` 变化时，提交以错误结束且未打开 tab。

### REQ-306 远程 runtime 工作区按协议边界降级

- 目标级别：P1；当前状态：已实现（单测 + 2026-09-11 真机验证通过）。
- 描述：远程 runtime 工作区的文件 RPC 只接受 worktree 相对路径，弹窗只放行 worktree 内的绝对路径。
- 业务规则：路径在 worktree 内时折算为相对路径后经 RPC stat 并打开；路径在 worktree 外时在分类阶段显示状态行「该远程工作区只能打开工作区内的文件。」，不发起请求，不提供可点行（与现状的状态行形式一致）。
- 验收标准：
  1. worktree 内绝对路径得到 `absolute-file` 行，stat 经 `files.stat` 且参数为相对路径。
  2. worktree 外绝对路径只得到状态行，未发起 stat。

## 7. 业务规则

- 执行主机拥有文件系统：远程工作区的路径不得在本机 stat、读取或授权（`docs/reference/ssh-execution-boundary.md`）。
- 不改协议：不新增 runtime RPC 方法或字段（`docs/reference/remote-wire-compatibility.md`）。
- 不改共享守卫 `isLocalPathOpenBlocked`，它另有编辑器 tab 右键与 Markdown 链接两个消费者。
- 新代码进功能自有目录，上游文件只在登记接缝处改动（`AGENTS.md` Fork Maintenance）。
- 新增或修改的文案同步 6 个 locale 并通过 4 个 `verify:localization-*` 门禁。
