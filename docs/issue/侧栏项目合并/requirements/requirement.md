# 同仓库与同显示名称的项目归并

## 背景与来源

用户要求三个 workspace 目录及其工作区归在同一项目下，并保留 Movo 和 orca 的正确归属。2026-10-23 用户进一步明确：“同 repo 合并，同 project 合并”“原本逻辑不要改动太多”“不要改变了其他归属逻辑”，并核对同仓库自动归并是否原本已有。来源为本需求的用户对话；历史目录与配置事实见[现状调研](../research/项目目录工作区与属性归属现状.md)。

用户随后提供“项目设置 → 身份 → 显示名称”的截图，明确要求：“重名的话我希望合并，不希望合并我改名字就行了”。同仓库自动归并是现有能力；本期只补充按现有显示名称的侧栏归并，不维护额外成员名单。[上一版原生归属稿](../solutions/原生项目归属方案-10-23.md)保留为历史，由[最小改动方案](../solutions/项目分组最小改动方案-10-23.md)替代。此前 Agent 提出的人工分组记录也已被此轮用户规则替代；旧原型及历史测试不能证明当前规则已经实现。

## 用户场景与范围

本期处理 Local Mac `/Users/bytedance/workspace`、mini 同路径目录、dbox `/home/zhangchao.zc/orca/workspaces` 的共同项目归属。Movo 保留此前修复的原生身份；真正的 orca 仓库和 octo 不被移入 workspace。

范围包括保留同仓库自动归并、按当前显示名称合并侧栏项目、通过已有改名入口加入/离开同名归并，以及 Local/配对 runtime/SSH 和移动端的展示与操作边界。跨主机文件同步、物理目录移动、重建会话、原生 catalog/工作区项目 ID 迁移、额外成员配置、AI Vault 分类或快捷命令等业务范围扩张不在本期范围。

### REQ-612 同显示名称归并与改名拆分

### REQ-613 保留工作与执行

### REQ-614 保护已有正确项目

当前状态：已实现；TC-612、TC-617 覆盖。

来源：明确的成员范围和“这是原逻辑吧”的核对。验收：Movo 依现有仓库身份归并，无须手工配置；未命中同名归并的区块与原结果一致；workspace 展示归并不迁移 orca、octo 或其他项目的原生归属。相同仓库原本就归并时，单独改名不用于强行拆散它。

### REQ-615 可实施、可验证

当前状态：已实现；TC-613 至 TC-617 覆盖。

来源：本轮“不改变其他归属逻辑”和使用现有显示名称的明确约束。验收：新增归并依据、比较规则与优先级明确，项目头/行位置/排序/折叠/导航/菜单及移动端影响列清；文件/终端/设置等操作继续选中原 host/repo/worktree。改名沿用既有标题变化，不隐含目录移动或业务身份变化。

## 已确认结论与未决问题

已确认：同仓库自动合并沿用原逻辑；新增同显示名称归并；不希望同名归并时改名；原逻辑小范围改动，其他归属逻辑不变。用户随后明确“改吧”，本轮完成源码实现与隔离验证。

实现采用：先按原规则产生项目区块，再按这些区块的有效显示名称合并视图；仅去除首尾空白，其他字符精确比较。区块名来源与原有同仓库标题选择复用现有链路，禁止按任意成员别名传递合并。这些属于实现细节，不写成用户逐项确认的规则。跨客户端新增配置同步、业务原生 Project 统一及所有项目能力共享不在范围。
