# 终端头部切到聊天视图

## 1. 背景与目标

终端窗格头部原来有「Show chat view」按钮：把正在跑的 Codex 或 Claude 终端会话就地以聊天界面显示，agent 照常在终端里运行，随时可切，本机与 SSH 工作区都能用。上游 #27184（2026-10-12）把这个按钮换成了「在新的原生聊天中恢复」：开一个新聊天标签接管这段对话，这要求终端里的 agent 先退出，而且只对本机执行的终端提供。2026-10-21 的上游同步把它带进了 fork。

两个功能在界面上都叫「在聊天界面中继续」：头部按钮是「新聊天接管」，窗格右键与 ⌘⇧J 是「就地 chat view」。用户照旧点头部按钮，agent 运行中一定被拒，SSH 工作区里按钮干脆不出现，以为功能坏了。

目标：头部**新增**「切到聊天视图」按钮恢复就地切换，原按钮保留，两个功能改用不同名字。

## 2. 用户场景

用户在终端里跑着 Codex，想换成聊天界面看并继续对话：点头部「切到聊天视图」，同一个标签立即切成聊天视图，Codex 不受影响；需要的话点「显示终端」切回。想把对话交给一个新的聊天会话、终端里的 Codex 已退出时，用「在新聊天中接管」。

## 3. 范围

### In Scope

- 终端窗格头部（当前活动窗格）新增「切到聊天视图」按钮，提示框带 ⌘⇧J（其他平台 Ctrl+Shift+J）。
- 名字区分：就地 chat view 统一叫「切到聊天视图 / Switch to Chat View」（头部新按钮、窗格右键菜单）；新聊天接管沿用上游的文案 key，中文改叫「在新聊天中接管」（头部原按钮、终端标签右键菜单），英文保持上游的「Continue in Chat UI」。
- 只维护中英文；其他语言回退英文。

### Out of Scope

- 两个功能本身的行为与可用条件（沿用现有逻辑，不改）。
- Session History 的「在新聊天中恢复」名字不变（那是从历史记录恢复，不是当前终端的切换）。
- 手机端：已有自己的「终端/聊天视图」切换，不在本需求内改动。

## 4. 需求点

### REQ-1 头部可就地切到聊天视图

- 目标级别：P0；当前状态：已实现（2026-10-23 单测与本机、SSH 真机验证通过，见 TC-1、TC-3、TC-4）。
- 描述：活动窗格的 agent 支持聊天视图时，头部显示「切到聊天视图」；点击后同一标签切成聊天视图，agent 继续在终端运行，不弹任何拒绝提示；已在聊天视图时只显示「显示终端」。可用条件与窗格右键「切到聊天视图」完全一致（同一判断、同一切换动作）。
- 本机终端：Codex、Claude 运行中可切。
- SSH 工作区终端：同样可切（聊天视图通过执行主机读取会话记录）。

### REQ-2 两个功能名字区分

- 目标级别：P0；当前状态：已实现（2026-10-23 单测与真机验证通过，见 TC-2、TC-3、TC-4）。
- 描述：就地 chat view 在头部和窗格右键都叫「切到聊天视图 / Switch to Chat View」；新聊天接管在头部和终端标签右键都叫「在新聊天中接管」（英文界面仍是上游的「Continue in Chat UI」，与「Switch to Chat View」已可区分）。两个按钮并排时图标也不同（单气泡与双气泡）。
- 本机终端：两个按钮都出现（接管按钮按原条件出现）。
- SSH 工作区终端：只出现「切到聊天视图」；「在新聊天中接管」按上游规则只对本机提供，不出现。
