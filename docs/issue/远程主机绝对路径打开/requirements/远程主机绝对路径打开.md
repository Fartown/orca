# 远程主机绝对路径打开

## 1. 背景与目标

配对 runtime 的客户端在「+」弹窗里输入主机上一个 **worktree 之外**的绝对路径时打不开。主机的 `files.read` / `files.write` 只按 `worktree + 相对路径` 寻址，worktree 外的路径在这套 RPC 里**没有可表达的形式**，客户端因此报「该远程工作区只能打开工作区内的文件」。

主机并非没有能力：它早就有一套**授权（grant）机制**，由 `files.resolveTerminalPath` 为终端打印过的 `/tmp` 文件、native-chat 产出的文件发放，读写走 `files.readTerminalArtifact` / `files.writeTerminalArtifact`。缺的是两件事：主机不肯为「没有出处」的任意路径发 grant，客户端桌面端也从未消费过 grant（只有移动端消费过）。

目标：主机为客户端点名的任意绝对路径发放 grant，客户端按 grant 打开、读取与保存。

## 2. 用户场景

用户在客户端连着一台配对 runtime 主机，从别处复制到主机上一个绝对路径（例如另一个项目里的 `/Users/me/workspace/forge/tmp/task`，或 `/tmp` 下的一份产物），粘进「+」弹窗回车，期望像本地一样打开并可编辑保存。

## 3. 范围

### In Scope

- 主机新增 `files.grantHostPath`：为任意绝对路径发放 grant。
- 客户端按 grant 打开、读取、保存；grant 过期时自动换发一次。
- 弹窗在 worktree 外路径上改为申请 grant（该请求同时充当存在性检查）。
- 标签页持有 grant，使重载与保存仍指向同一个文件。

### Out of Scope

- SSH（非配对 runtime）工作区：该链路已有 `externalSshTargetId`，本需求不改。
- 目录。grant 只针对单个普通文件。
- 主机上的文件浏览器/搜索等其他入口按绝对路径寻址。
- 把 grant 暴露给终端链接以外的其他既有消费者（移动端已有自己的实现）。

## 4. 需求点

### REQ-801 主机为任意绝对路径发放 grant

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-16 真机 UI 验证通过）。
- 描述：新增 `files.grantHostPath`，入参为 `worktree` 与 `absolutePath`，返回既有的 `absolute-file` 形态（含 `grantId`）。
- 业务规则：**不检查 provenance，也不限制在 /tmp**——这是 2026-09-15 用户拍板的扩大暴露面（D-301）。
- 验收标准：客户端点名一个从未被打印过、且不在任何 worktree 内的路径，能拿到 grant。

### REQ-802 扩大暴露面后仍然保留的约束

- 目标级别：P0；当前状态：已实现（单测覆盖）。
- 描述：放开 provenance 之后，其余护栏必须原样保留，并集中在一个具名文件里以便审查。
- 业务规则：
  1. 必须是绝对路径；
  2. 必须存在且是普通文件，目录报错；
  3. 硬链接拒绝（第二个名字会让撤销 grant 失效）；
  4. 路径先规范化再铸造 grant（否则存的是软链别名，撤销同样失效，且主机自身的新鲜度检查会判 stale）；
  5. grant 仍然过期、仍然绑定请求方客户端。
- 验收标准：上述每条都有单测；路径规范化另有真机证据（见 TC-801 的排障记录）。

### REQ-803 客户端按 grant 打开与读取

- 目标级别：P0；当前状态：已实现（单测 + 真机验证通过）。
- 描述：弹窗对 worktree 外路径改为申请 grant 而非 stat；标签页记录 grant；编辑器读取走 `files.readTerminalArtifact`。
- 业务规则：标签页以**主机规范化后的路径**命名；带 grant 的标签页豁免「远程工作区不支持外部本地文件」这条既有拒绝——那条成立的前提正是本需求消除的限制。
- 验收标准：真机中打开 worktree 外文件，编辑器显示其内容，标签页持有 grant。

### REQ-804 保存走同一个 grant

- 目标级别：P0；当前状态：已实现（单测覆盖）。
- 描述：`writeRuntimeFile` 在上下文带 grant 且路径匹配时改走 `files.writeTerminalArtifact`。
- 业务规则：只有 grant 的 `absolutePath` 与被写路径一致才走该分支，避免一个 grant 被用来写另一个文件。
- 验收标准：单测覆盖分支选择；真机保存未验（见测试记录）。

### REQ-806 授权路径上的超大文件明确拒绝

- 目标级别：P0；当前状态：已实现（单测覆盖）。
- 描述：`files.readTerminalArtifact` 与 `files.read` 一样会截断，但授权路径没有 `files.readChunk` 那种按 worktree 相对路径的分块形式可以补读。
- 业务规则：返回 `truncated` 时拒绝并说明大小，**不得**把前缀交给编辑器——那样下一次保存会把主机文件的后半截抹掉，正是「远程大文件编辑器读取」功能存在的理由。
- 验收标准：主机返回 `truncated: true` 时抛出含字节数的错误，不返回内容。
- 备注：这条是本功能与「远程大文件编辑器读取」合流时才出现的交互，两者单独存在时都没有这个口子。

### REQ-805 grant 过期可自动换发

- 目标级别：P0；当前状态：已实现（单测覆盖）。
- 描述：主机以 `terminal_file_grant_expired` / `terminal_file_grant_mismatch` 拒绝时，重新申请一次并重试。
- 业务规则：只重试一次；与 grant 无关的失败（权限、传输）不触发换发，否则会用第二次同样的错误盖住真实原因。
- 验收标准：单测覆盖换发成功、只换一次、不该换时不换。
