## 执行主机归属

| 能力                     | 本地场景                                          | SSH 场景                                                                                                                       |
| ------------------------ | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Goal                     | 本地 runtime 注册服务，使用本地配置、存储和执行器 | SSH 主机的 orcad 注册同一服务；客户端通过已连接 runtime 调用，Goal 文件、环境变量、CLI 和进程都属于执行主机                    |
| 会话身份与名称           | 本地 hook store 和会话文件提供身份/名称           | orcad 使用执行主机 hook store 和会话文件，向客户端发布结果；WSL guest 的 provider 状态折叠独立，但会话替换检查读取主机进程状态 |
| 产物分享                 | 本地服务读取本地文件并占用本地监听端口            | orcad 服务读取 SSH 主机文件并占用该主机端口；客户端的 `127.0.0.1` 不代表服务端。页面始终使用预览授权建立时的主机与根目录       |
| 文档预览及绝对路径       | 当前 runtime 授权本地文件；文档上限保持 20 MiB    | 文件所属 runtime 验证路径授权并分块返回，单帧保持传输预算，客户端组装完整文档                                                  |
| 移动端附件               | 上传临时文件和最终文件均在当前执行 runtime        | 手机发给工作区所属 orcad；临时目录、分块文件、提交后的文件全在该 SSH 主机。文件夹工作区同样适用                                |
| 终端身份、续聊、Tab 发布 | 保留终端身份、工作目录和 publication epoch        | 通过主机 runtime 路由保留相同语义，不把断联解释为进程退出                                                                      |

旧 direct SSH relay 不再是新上游支持的执行通路。遗留地址返回需要连接所属 Orca Server 的错误，不回退到客户端同名路径，不自动重试或连接。配对 runtime 仅在共享连接层判定可达时读取。客户端与服务端版本可独立更新：新增可选字段保持兼容，旧服务不支持的方法明确拒绝，不伪装成功。

## 合并中修正的行为

- `integration-builds/orcad-fork-services.ts` 作为 fork 构建的服务组合入口，按顺序注册 Goal、Issues 与分享服务，启动中途失败也能清理已启动的服务。架构仅为这个明确组合入口开放依赖。
- 将文档 MIME 类型表从桌面 IPC 读取器拆出，分享服务的 Node bundle 不再引入 Electron。
- 保留 provider 的独立事件折叠，Claude 会话替换判断改读主机的进程归属，避免已退出进程继续拦住新会话。
- 标题刷新限定焦点面板；会话切换仍能找到其他运行中的分屏，不复用已退出面板的身份。
- LAN 分享使用预览建立时的授权主机，切换当前工作区主机后不会分享另一台机器的同名文件。
- 旧 relay 专用入口与测试迁往 orcad、runtime 和 WSL guest；注册表、依赖和接缝随代码迁移。
