# 文档预览大小

用户在文档预览出现“文件过大”后要求将限制改到 20 MB。本轮沿用代码的二进制单位：20 MiB，即 20,971,520 字节。

### REQ-401 文档文本预览支持 20 MiB

优先级：P0。当前状态：实现中。

专用文档读取链路（直连 SSH、配对 runtime，以及宿主内部的文档读取方法）允许不超过 20 MiB 的完整文本文件；超过一字节仍返回原有过大错误。按文件字节数而非字符数判断，不显示截断正文。包括 HTML 及其文本子资源，不改变二进制图片/PDF 的限制。

纯本地工作区的 UI 预览原本通过 `file://` 浏览器标签直接加载，并不经过上述专用读取链路。本次保留该行为，验证 20 MiB 可以正常显示，不给原有本地预览新增 20 MiB 上限。依据：`src/renderer/src/lib/file-preview.ts` 的 `getWorkspaceFilePreviewPlan`；先前把本地 runtime 方法测试等同纯本地 UI 入口的描述不准确，现予以纠正。

### REQ-402 保留非文档读取和传输边界

优先级：P0。当前状态：实现中。

普通文件/手机端读取维持原限制；既有授权、主机路由和错误展示不变。旧客户端的单次文档读取维持 512 KiB，配对 RPC 的约 4 MiB 单次传输预算保留；新版文档客户端按 256 KiB 分块取回文件，不放大全局通信限额。

## 范围与待确认项

- 本轮只改专用读取上限及必要传输接线，不改变 UI、增加设置或替换用户 App。
- 旧版本 SSH 执行端仍可能保留旧上限；升级执行端后才具有新能力，不通过客户端本地读取替代。
- 远端预览入口依赖执行主机读取，因此配对分块属于打通远端预览的必要接线：复用既有方法，新增可选 chunk 字段；旧主机忽略字段时回退原行为，完整 20 MiB 需要两端更新。纯本地 `file://` 不受此版本条件限制。
- SSH 复用既有可协商的大响应流，不新增 opcode，也不扩大 16 MiB 单帧上限。
- 小范围实现直接依据本需求与 Journal，不另建技术方案或交互稿。
