# 终端 ID 复制主机路由方案

## 原因与方案

配对终端的菜单仅调用客户端本机 runtime，因此 terminal.resolvePane 返回 terminal_not_found，尚未执行剪贴板写入就触发失败提示。镜像 Tab 还需要先还原为主机 Tab ID。

新增 feature-owned 适配器，复用 resolveTerminalHostOwnership 的既有终端归属规则、terminal-handle-copy 的响应校验及剪贴板写入顺序。folder 分支先使用 getResolvedExecutionHostIdForWorktree 验证主机证据，拒绝缺失或歧义的目录归属，同时保留恢复记录中的配对主机；不能把 teardown 的本机兜底作为归属证据。菜单只增加 worktreeId 透传与调用注册点。直接选当前活跃环境会串主机；复制 PTY ID 则与 CLI 可寻址的 terminal handle 语义不符，因此不采用。

## 主机与资源归属

| 场景 | 查询位置 | 剪贴板位置 |
| --- | --- | --- |
| 本地 git / folder | 本机 runtime | 客户端 |
| 直接 SSH | 管理该 SSH 会话的本机 runtime | 客户端 |
| 配对 git / folder | 所属配对 runtime | 客户端 |
| 配对主机代理 SSH | 所属配对 runtime；检查其 SSH 连接状态 | 客户端 |

客户端 store 只提供已有主机路由和连接层的可达性事实，不创建状态缓存、重连、轮询或重试。无主机归属、失联和 RPC 错误都终止，绝不回退本机。远端 tab 使用 toHostSessionTabId 转换；调用附上 worktreeId 防止跨工作区解析，并传入已有 pairing revision 防止同名环境重配后串主机。

功能不读写远端文件、127.0.0.1 端口、环境变量、配置或服务。测试夹具在独立 profile / 临时仓库启动本地和 SSH 终端，生产进程与用户工作目录不参与测试。

## 兼容与风险

复用既有 terminal.resolvePane 和可选 worktreeId 参数，不增加 RPC、stream opcode、协议能力或远端版本要求。菜单文案、普通复制与窗格 ID 复制不变。查询和写入任一步失败均走原菜单错误提示，只有客户端剪贴板写入成功才显示成功。

## 验证

24 项功能与复制助手单元测试覆盖主机归属、镜像 ID、folder、SSH 代理、失联、异常不回退和剪贴板失败。后台双 Electron 实例验证配对查询：客户端本机解析确实失败，修复后的菜单却能复制主机真实 ID。真实 SSH 验证同样通过菜单读取剪贴板，并核验 executionHostId 为 ssh:。全部窗口保持隐藏。
