# 富文本 Markdown 强制打开 需求

## 背景

Markdown 编辑器的富文本模式对三类语法有硬拦截，横幅提示「只能在代码模式下编辑，因为该文件包含 HTML、JSX 或 MDX / 引用样式链接 / 脚注」，并强制回落到 Monaco 源码模式。

拦截本身有依据：这三类语法经 TipTap 往返（round-trip）后可能被改写或丢失，在富文本模式里保存会静默破坏源文件。但当前实现有两个问题：

1. **没有任何逃生口。** `EditorMarkdownFileSurface.tsx` 只给「体积超限」这一种回落配了「仍然打开」按钮，语法不支持的回落不给按钮（原注释：`only a size fallback is recoverable`）。用户无法自行承担风险。
2. **大文件被无条件误判。** `markdown-rich-mode.ts` 的往返验证只对 ≤50,000 字符的正文执行；超过这个阈值且含任何 HTML 的文档一律按「不支持」处理，即使它的 HTML 本可无损往返。富文本模式自身的体积上限是 600 KiB，所以 50 KB～600 KiB 之间带 HTML 的文档落在这个空档里。

用户诉求：把这个限制放开，但保留它防止的那件事的可见性。

## 目标

### REQ-401 语法不支持的回落提供「仍然打开」

- 当前状态：已实现
- 描述：`html-or-jsx`、`reference-links`、`footnotes` 三类回落横幅都提供「仍然打开」按钮，点击后该文件进入富文本模式。
- 约束：
  - 默认行为不变——不点按钮时仍然回落到源码模式，横幅文案不变。
  - 覆盖是显式的、按文件生效的，复用体积回落已有的 per-file 覆盖标记，不新增 store 字段。
  - `other`（无匹配器、无文案）不在可覆盖范围内。

### REQ-402 强制期间持续提示改写风险

- 当前状态：已实现
- 描述：覆盖生效后，富文本编辑器内常驻一条提示，说明在此保存可能改写或丢失文件中的 HTML、引用式链接或脚注。
- 约束：
  - 提示只在「确实存在不支持语法且已覆盖」时出现；纯体积覆盖的干净文档不出现。
  - 提示挂在编辑器 header slot，与 Front Matter 横幅共存，不占工具栏位置。
  - 只用 STYLEGUIDE 已有的语义 token，不引入 raw palette 颜色。

### REQ-403 中文界面下横幅与按钮为中文

- 当前状态：已实现
- 描述：`editor.richMarkdown` 文案组在 `zh.json` 中补齐（`tooLarge` / `openAnyway` / `overrideActive`），中文界面不再显示英文原文。
- 约束：不改动 en.json 既有文案含义。

## 非目标

- **不去掉往返检测本身。** 检测仍然运行，仍然决定默认行为；改的是「检测失败之后用户有没有选择权」。
- **不提高 50,000 字符的往返验证阈值。** 那是主线程同步解析的成本问题，属于独立议题；本需求让用户能绕过这个保守判定，不改判定本身。
- **不重命名 `markdownRichModeSizeOverride`。** 见 journal D-001。
