# 终端 Chat 发送链路现状

基线 fdfe5c51a26。调研时只读源码和既有证据，没有向用户会话发送输入。

| 链路                                | 已确认事实                                                                                              | 证明边界                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 普通 composer → observed PTY writes | 调度后立即清草稿；Codex 请求 strict settlement；unknown 默认仍继续下一段                                | 字节 ACK 不能证明消费                            |
| pending                             | renderer Map，8 条/128 scopes；只有 lost ACK 有 20 秒 deadline                                          | 无 renderer/app 跨运行持久性                     |
| draft                               | IndexedDB + localStorage journal + BroadcastChannel                                                     | 是未发送输入；清草稿会持久删除                   |
| durable terminal.send               | agentPrompt/text/enter/desktop + envelope requestId；SQLite ledger 先 pending 后 checkpoint；同 ID 去重 | 普通 Chat 未接入；默认不清终端草稿               |
| requestShow                         | 同认证 caller 指纹读取 pending/completed/absent                                                         | 不写终端；absent 不证明未发送                    |
| turn_started                        | Enter 后新 lifecycle edge，FIFO request claim                                                           | 不核对正文，不等于转录消费回执；关联内存不跨重启 |
| transport settlement                | daemon socket callback/timeout 和 provider settlement                                                   | 仍不是 agent 消费证明                            |
| legacy SSH                          | ssh:target@@relayId 的 mux.notify 原始字节；本地 runtime 不再拥有该 terminal                            | 无可复用的 durable 执行端提交协议                |
| managed/paired SSH                  | remote:environment@@handle 路由至执行主机 RPC                                                           | 有主机 ledger、PTY 与 transcript 所有权          |

普通 pending matcher 对账有 boundary 与 occurrence，但失败记录、空读及分页不能直接复用为严格 durable 消费证据。既有真实 Codex PTY integration 使用本地 Responses fixture，只证明 orchestration pointer；没有一个现成测试贯通普通 Chat DOM、真实 Codex、丢回执、重启和同请求查询。

历史那次未收到的正文，已有证据只能定位为 UI 假定投递成功；具体停在 body、Enter 或 provider 消费哪一步仍无逐写记录，不能倒推。也没有证据支持“用户已打开的 tab 因隐藏回收导致这次丢消息”的归因。
