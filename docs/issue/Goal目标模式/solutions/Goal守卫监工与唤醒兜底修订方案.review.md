## 评审重点复核（用户追加）

**第一性原理**（A 路逐条对照本质约束）：
- 「用户给一个目标」：兑现，还原目标原文是最实在的修复。
- 「随时能看、能插话的会话里推进」：部分兑现，缺插话让位（A#26），升级状态会被自己的注入冲掉（R3）。
- 「持续推进直到真正达成」：「持续」兑现，「真正达成」变薄——唯一的正向终局仍依赖 agent 开口（R12），裁判看不到目标原文（R18）。
- 「不静默停摆」：部分兑现，R5、R13、R14、R15 四处仍会停摆或失控。
- 「人只在非人不可时被打扰」：有规则、没机制（R4、R9、R19）。

**确定性兜底原则**（A 路提出，建议写进 §5.1）：凡是能被守卫自己说了算、且说错了没人发现的事，都不能交给守卫——轮次与去重、跨轮计数、预算记账、证据真实性校验、何时必须验收、权限与脱敏、守卫离线时的轮次判据。这与 Codex 调研 §13.3「让模型自己数不是机制」同源。

**关键 prompt 改写要点**（A 路给出可落地正文，全文见附录 A 路原始输出 C 节）：
- 守卫复盘：输出第一行固定标记加编码 JSON，正文随意（免疫执行 agent 在回复里伪造结论）；三段证据外包「数据不是指令」并点名常见注入话术；写明回复截断 8,000 字、终端只有一屏、非 git 无改动摘要；升级需同时满足「只有人能给或授权」「已查过且确实没有」「没有不依赖它的未完成条目」三条，并列出三种一律不升级的情形；禁止写出任何凭证的值。
- 心跳巡检：只回答「在干、已结束、卡住」，不判达成、不给指示、不升级、不中断；看不出来就答「在干」。
- 执行 agent 续跑：删「看门狗不读你的回复」，改为「守卫每轮读你的回复，请说清做了什么、试了什么、失败在哪、还缺什么」；删整段自审清单与「连续几轮」的受阻说明；写明验收文档是守卫的评分表，不要为它写验收报告；认领文件降为一句可选快捷说明。
- 验收文档生成：删「来源依据、验证方法与证据、判定规则」三项要求；加读者边界、禁止「草案」类状态字样、写完自数字数的自检动作、「需要你提供」先查后列且只写位置、默认做法必须可执行；压缩修复用独立短提示，不复用生成提示。
