## 2. 决策点记录

### D-005 复用显示名称归并，改名解除同名归并

- 日期：2026-10-23
- 背景：用户提供项目设置中显示名称截图，明确重名合并、不希望合并时自行改名；不希望为此改变其他归属逻辑。
- 最终决定：采用显示名称驱动的最小视图扩展，不增加人工成员名单；同仓库自动归并和原有例外继续保留。
- 原因：用户已有明确可操作的改名入口；复用已保存名称即可表达同名归并意图，避免重复配置和业务归属迁移。
- 影响范围：REQ-612、REQ-614、REQ-615及最小改动方案；取代D-004中的人工成员名单。用户随后授权“改吧”，已完成源码与隔离应用验证；未替换用户当前 App 或修改在线名称。

#### 备选项

- 维护额外人工分组ID和成员名单
- 沿用原有仓库归并，再按现有项目区块显示名称归并

#### 关联文档与需求点

- requirements/requirement.md

### D-004 保留自动仓库归并，只补显式项目分组（备选，已被 D-005 替代）

- 日期：2026-10-23
- 背景：用户要求同repo和同project合并，并明确原本逻辑少改、其他归属不变；同仓库自动归并是已有能力。
- 当时建议：以人工成员名单组织展示，未获用户对该实现的明确选择；随后用户指定使用现有显示名称，按 D-005 撤回成员名单建议。
- 原因：共同侧栏项目不应扩张为文件、终端、Git、AI Vault或快捷命令的归属迁移。
- 影响范围：REQ-612、REQ-614、REQ-615及有效方案入口；历史方案和测试保留，不改产品代码或在线配置。

#### 备选项

- 继续改原生项目ID并迁移工作区和业务引用
- 保留自动归并和全部业务身份，只在侧栏归组结果补显式分组

#### 关联文档与需求点

- requirements/requirement.md

### D-003 重写模型、属性所有权与提交契约（已被 D-004 替代）

- 日期：2026-10-23。
- 背景：用户指出原稿没有解释当前项目、文件、工作目录和属性，也未明确改造后的模型；源码评审发现偏好继承、导入和并发恢复缺口。
- 备选项：在旧稿补问题清单；先核对事实再重写当前与目标模型，并写定实施契约。
- 最终决定：采用后者。复用原生 Project/Repo/setup；显式归属以 Repo 为来源；本地主机偏好按成员迁移；工作区当前归属一并更新；owner 端 CAS、durable 确认和待确认恢复。
- 原因：共同项目身份必须能解释文件、执行与属性，而不能仅说明共同标题。普通内存读回和凭据命中不足以证明落盘。
- 影响范围：REQ-611 至 REQ-615、主方案、现状调研、未来接缝与验收；不部署旧原型或修改在线配置。详细规则为设计决定，尚未实现。

### D-002 原生项目归属方案（已被 D-004 替代）

- 日期：2026-10-23。
- 背景：用户要求复用项目概念，并明确要求写清改造前后；上一版额外侧栏合并层未被采用为最终交付方向。
- 推荐：给原 Repo 保存显式项目归属，复用 Project / ProjectHostSetup 及原生 catalog；三个 workspace 共享项目 ID，Movo 保持此前已修复的原生身份。
- 差异：配置由目录所属 runtime 管理；真正统一身份需要相应端支持新能力，不能继承旧方案“旧远端无需更新”的结论。
- 当前边界：本轮只改文档；旧源码和安装包留存但不继续部署。新方案未实现、未验证，也没有修改在线归属或重启应用。

### D-001 展示合并与执行身份分离（历史原型方案）

- 日期：2026-10-22。
- 背景：普通目录使用主机内独立项目 ID；Movo 两端保存的上游身份不同。用户要求三个 workspace 和两端 Movo 分别显示在一个项目下。
- 决定：在客户端 UI 偏好中显式记录合并名称和主机限定的 repo 成员，只对侧栏项目投影应用。
- 原因：不能通过修改 upstream、伪造远端身份、移动目录或重建工作区改变原有会话和 Git 语义。
- 所有权：偏好由显示侧栏的客户端保存；目录、文件、进程、会话和 Git 操作仍由原执行主机持有。此能力不监听端口、不连接失联主机，不需要远端升级。
- 兼容边界：未配置时保持既有行为。旧端未声明该 UI 字段时不提供写入；旧版读取新偏好可以忽略该字段。
