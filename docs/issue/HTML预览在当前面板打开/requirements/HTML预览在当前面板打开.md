# HTML预览在当前面板打开

## 1. 背景与目标

编辑器头部的眼睛按钮（以及合并 diff 每个文件段头部的同一个按钮）是 HTML 的渲染预览入口。它今天调用 `openFilePreviewToSide`，沿用 VS Code 的「Open Preview to the Side」语义：在来源 pane 右侧找一个兄弟分组，没有就新建一个右分屏，把预览放进去。结果是每次点预览都把编辑区一分为二，左边源码右边渲染。

Markdown 不走这条路径——它的富文本渲染跑在编辑器内部，所以有「源码 / 富文本」的原地切换开关，不会分屏。用户的诉求是让 HTML 预览也不分屏，与 Markdown 观感一致。

目标：点预览时，在发起这次操作的那个 pane 里新开一个预览 tab 并切过去，不再创建或占用右分屏。返回源码就是切回原来的 tab，与其他 tab 的切换方式相同。

## 2. 用户场景

用户在编辑器里打开一个 HTML 文件，点头部的眼睛按钮，期望当前面板换成渲染后的页面，而不是把面板劈成两半；想回看源码时点回原来那个 tab。在合并 diff 的评审界面里点某个 HTML 文件段的预览，期望同样落在当前面板。

## 3. 范围

### In Scope

- 编辑器头部预览按钮与合并 diff 段头部预览按钮的落位行为。
- 三种工作区归属下的落位一致：本地工作区的 `file://` 浏览器 tab，SSH / 配对 runtime 工作区的 `orca-preview` 文档 tab。
- 预览无法进行时（无浏览器通道、配对工作区的 worktree 外文件）保持现有的 toast 提示，不静默开空 tab。
- 按钮文案随行为改写（不能再叫「打开侧面预览」）。

### Out of Scope

- 给编辑器 tab 增加内嵌 webview 显示模式，实现 Markdown 那种同一 tab 内的原地切换。这需要新的编辑器显示模式，量级与本需求不同。
- 预览内容本身的渲染、文档授权、`orca-preview` 协议。
- Markdown / Mermaid / CSV / Notebook 等其他语言的查看方式。
- 上游 `openFilePreviewToSide` 的实现（保留不动，供上游同步后可能出现的新调用方使用）。

## 4. 需求点

### REQ-401 预览落在发起操作的 pane 并切过去

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-15 真机验证通过）。
- 编辑器头部预览按钮触发时，预览 tab 建在该编辑器 tab 所属的分组里，并成为该分组的活动 tab。
- 不调用 `createEmptySplitGroup`，也不复用右侧兄弟分组。
- 验收：TC-601。

### REQ-402 无法判定来源分组时落在用户正在看的 pane

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-15 真机验证通过）。
- 调用方给不出来源分组 id 时，依次回退到该工作区的活动分组、第一个分组。
- 验收：TC-602。

### REQ-403 远程工作区的预览同样落在当前 pane

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-15 真机验证通过）。
- SSH 或配对 runtime 工作区走本地渲染的文档 tab（`docLocation` + `browserRuntimeEnvironmentId: null`），落位与激活规则与本地一致。
- 验收：TC-603。

### REQ-404 不可预览时保持可解释的失败

- 目标级别：P0；当前状态：已实现（单测 + 2026-09-15 真机验证通过）。
- 浏览器通道不可用、配对工作区的 worktree 外文件等情况沿用 `getWorkspaceFilePreviewPlan` 的判定，toast 显示其原因，不建 tab。
- 非可预览语言直接返回，不提示也不建 tab。
- 验收：TC-604、TC-605。

### REQ-405 合并 diff 的预览入口与编辑器保持一致

- 目标级别：P1；当前状态：已实现（单测 + 2026-09-15 真机验证通过）。
- 合并 diff 段头部的同一个眼睛按钮改用同一条落位逻辑，避免同一图标在两处行为不同。
- 验收：TC-601（共用实现）、TC-606（真机）。

### REQ-406 按钮文案与新行为一致

- 目标级别：P1；当前状态：已实现（单测 + 2026-09-15 真机验证通过）。
- 文案由「打开侧面预览 / Open Preview to the Side」改为「打开预览 / Open Preview」，六个语言包同步。
- 验收：TC-606。
