## 观察

- SSH 和配对服务器上，启动后 tab 在 0.4 到 1 秒后异步出现，客户端 id 是 `web-terminal-` 加主机 tab id，和状态表一致；进程环境里的 `ORCA_PANE_KEY` 是主机原始 id。SSH 一次启动多出两个 tab，其中一个是迟到的默认终端。
- 终端句柄 `term_*`：本机和 SSH 重启后不变，配对服务器重启后会变。
- 配对服务器重启约 2 秒后，两个原本 `done` 的条目自己变成 `working`，没有 hook 事件，也不带 `restoredUnconfirmed`；连跑 3 次都复现，主机上的 `last-status.json` 前后都是 `Stop`，原因未定位。
- 带 hook 的会话，OSC 只给条目加 `programStatus`，`state` 仍是 hook 给的；没有 hook 的程序，permission、question 映射为 `waiting`，auth 映射为 `blocked`。
- 配对服务器上，同一终端里第一次 OSC 上报能送达，第二、第三次 9 秒内都没有条目，两次整套重跑都如此，原因未定位。
- Codex 的权限请求带 `tool_name` 时有 approval，`request_user_input` 有 questions，只有不带 `tool_name` 的事件没有 `interactivePrompt`。
