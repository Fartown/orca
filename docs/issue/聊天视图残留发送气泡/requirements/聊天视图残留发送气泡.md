# 聊天视图残留发送气泡

用户反馈（2026-11-12）：终端标签的聊天视图底部一直显示前一天 21:39 发出的两条消息，下面是「处理中」，看起来像聊天停在那句话；终端里却有后续一整天的输出。排查结论：聊天视图并未丢消息，那两条是没对上账的本地「待确认」气泡。聊天视图只在可见时读取 transcript，发送后半分钟内切走、会话又写满一窗（桌面最近 300 条）再回来时，气泡对应的行和它的发送边界都已不在窗口里，对账永远失败，气泡固定排在最后直到界面进程重载。上游 main（2026-11-12）逻辑相同。排查记录见 `.docs/chat-view-stale-transcript-investigation/2026-11-12/`。

外部 issue：Fartown/orca#106。

### REQ-8001 桌面聊天视图撤下已被越过的发送气泡

优先级：P0。当前状态：已实现。

正常对账之后，若同时满足以下条件，撤下该气泡：读取已完成（ready）、窗口之外还有更早历史（hasMore）、发送时记录的边界行不在已加载消息里、已加载的最早一条 transcript 行晚于边界行的时间。撤下后会话以最新消息结尾，不再出现旧发送时间的气泡与其下的「处理中」。

- 本地：本机工作区的 Claude/Codex 终端，从聊天框发送后切到别的标签或终端模式，会话写出超过 300 条后切回，旧气泡消失。
- SSH：工作区在 SSH 主机上时，transcript 由 SSH 主机持有，客户端照常经已有通道读取；同样操作后旧气泡消失。

### REQ-8002 判断只用已加载的消息，不增加读取

优先级：P0。当前状态：已实现。

判断在客户端界面进程里完成，只使用当前已加载的消息、`hasMore` 和读取阶段。不新增读取、请求、协议字段、端口、配置或文件；不在主机离线时读取，也不重试。

- 本地：客户端与执行主机是同一台机器，transcript 读取路径不变。
- SSH：transcript 文件、Claude/Codex 进程在 SSH 主机；读取仍走已有的主机读取链路，SSH 断开时沿用现有表现（窗格不就绪则不判断）。配对的远程 Orca 走已有 runtime 读取，同样只用已送达的消息。

### REQ-8003 仍可能有用的气泡保持不变

优先级：P0。当前状态：已实现。

以下情况不撤：写入失败或送达未确认（气泡可能是这条消息唯一的副本，用户仍可手动关闭）；写入确认还在等待；窗口仍覆盖到边界时间；已加载全部历史；读取未完成；发送时没有边界行或边界行没有主机时间。气泡对应行仍在窗口里时，沿用原有对账。

- 本地与 SSH：判断不依赖执行位置，两种场景行为相同；SSH 主机时钟只与该主机的 transcript 时间比较，不与客户端时钟比较。

### REQ-8004 手机聊天视图同样撤下

优先级：P1。当前状态：已实现。

手机会话页在重连后拿到一页新的消息（最近 40 条），若与发送时的窗口没有重叠且满足 REQ-8001 的条件，文字气泡与图片气泡都撤下；已加载全部历史时保留。

- 本地：手机连接桌面 Orca，工作区在桌面本机。
- SSH：手机连接的桌面 Orca 通过 SSH 打开远端工作区，transcript 在 SSH 主机；手机只用桌面转来的消息页判断。
