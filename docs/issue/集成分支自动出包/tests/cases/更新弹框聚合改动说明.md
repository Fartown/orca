# REQ-417 更新弹框聚合改动说明测试用例

- **TC-422 跨版本用户可见改动聚合与边界停止（关联 REQ-417）**：
  - 场景：客户端已装 `1.4.214-preview.100`（或 Android `versionCode=211392001`），远端依次存在 `preview.101`（含用户可见改动 `#152`）与 `preview.102`（`changes: []`，仅含 `docs` 工程改动）。
  - 预期：`fetchIntegrationRelease` 聚合 `(100, 102]` 返回 `#152`，不混入 `docs` 工程改动，且到达 `preview.100` 标题时停止，不请求 `preview.100/build-info.json`。
- **TC-423 纯工程版本回退与历史 Release 正文/Atom 提取（关联 REQ-417）**：
  - 场景：客户端已装 `1.4.214-preview.101`，最新 `preview.102` 无用户可见改动，分别测试新清单 `engineeringChanges`、历史 GitHub Release Markdown `<summary>工程改动…</summary>` 与 HTTP 429 限流回退的 Atom `<content>`。
  - 预期：`manifestChanges` 仍为空以保持跨版本干净，`manifestEngineeringChanges` 产出工程条目；客户端在区间内无用户可见改动时准确回退显示工程改动标题，不再退回英文固定签名套话。
- **TC-424 本地桌面、Web 与 SSH 远程服务器更新弹框展示（关联 REQ-417）**：
  - 本地场景：隐藏 Electron 桌面渲染 `UpdateCard`，核对真实 `Fartown/orca` 历史聚合结果在卡片正文与发行说明链接中完整显示。
  - SSH 场景：通过本机 `127.0.0.1:2222` 隔离 `sshd` 建立真实 SSH 转发隧道并关联远端 `orca serve` 运行环境，打开 `RemoteServerUpdateDialog`（不手传参数），验证自动触发 `refresh({})`、经 SSH 隧道获取远端主机计算的 `status.changelog`，并在对话框行内显示版本号箭头、改动摘要与发行说明入口；断开清理后 `~/.orca-remote` 与用户 `~/.ssh/authorized_keys` 无污染。
- **TC-425 Android 手机端更新弹框与设置/关于入口一致性（关联 REQ-417）**：
  - 场景：集成渠道下 `IntegrationUpdateGate`、`IntegrationSettingsUpdateSection` 与 `IntegrationUpdateRow` 挂载，控制器发现新版本。
  - 预期：`Alert.alert` 正文包含聚合改动摘要与 `preview.N (sha12)`；外层设置页备注与关于页详情行同步显示同一改动摘要。
