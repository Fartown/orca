# 自托管产物后端功能测试

这是可重复执行的测试规格；实际结果另记入 `../runs/`。需求来源为 [自托管产物后端](../../requirements/自托管产物后端.md)。

## 1. 功能清单

| 功能               | 关联需求 | 是否测试 | 覆盖                                                            |
| ------------------ | -------- | -------- | --------------------------------------------------------------- |
| 配置与默认值       | REQ-201  | 是       | TC-401、TC-409                                                  |
| 私网与 loopback    | REQ-202  | 是       | TC-402、TC-403、TC-406、TC-407                                  |
| origin 与公网限制  | REQ-203  | 是       | TC-404、TC-405                                                  |
| 既有鉴权与请求复用 | REQ-204  | 是       | TC-408；完整后端链路复用现有服务测试，不以 URL 单测替代网络验收 |

## 2. 用例

### TC-401 默认第一方 origin

- 关联需求：REQ-201；优先级：P0；类型：单元；模块：配置。
- 前置条件：向 resolver 显式传空环境对象，避免宿主环境干扰。
- 数据：override 为 undefined，env 为 `{}`。
- 步骤：调用 `resolveArtifactCloudApiUrl`。
- 预期：严格等于 `https://share.onorca.dev`。

### TC-402 loopback HTTP

- 关联需求：REQ-202；优先级：P0；类型：单元；模块：地址分类。
- 前置条件：使用空环境或显式环境 fixture。
- 数据：`http://127.0.0.1:8787`、`http://localhost:8787`、`http://[::1]:8787`。
- 步骤：分别通过环境变量和 override 解析。
- 预期：返回各自规范化 origin。

### TC-403 私网与 .local

- 关联需求：REQ-202；优先级：P0；类型：单元；模块：地址分类。
- 前置条件：独立 resolver 调用，不依赖实际 DNS。
- 数据：10 段、192.168 段、172.16 起点、172.31 末端、`nas.local`。
- 步骤：分别传入已有测试中 HTTP/HTTPS 样例。
- 预期：接受合法 origin；不发生网络请求。

### TC-404 公网与协议限制

- 关联需求：REQ-203；优先级：P0；类型：单元；模块：地址校验。
- 前置条件：空环境。
- 数据：`http://share.onorca.dev`、`http://example.com`、`https://example.com`。
- 步骤：逐项调用 resolver 并捕获错误。
- 预期：前两项拒绝明文公网，第三项拒绝非第一方公网。

### TC-405 仅接受 origin

- 关联需求：REQ-203；优先级：P0；类型：单元；模块：地址校验。
- 前置条件：第一方 HTTPS 主机。
- 数据：分别带非根 path、userinfo、query、fragment 的 URL。
- 步骤：调用 resolver。
- 预期：均拒绝；不返回裁剪后的地址悄悄继续。现有测试显式覆盖 path，其余条件须在扩展回归时检查，不能由 path 的单测代替。

### TC-406 伪造私有地址名称

- 关联需求：REQ-202、REQ-203；优先级：P0；类型：单元；模块：地址分类。
- 前置条件：空环境。
- 数据：`10.0.0.1.evil.com`、`192.168.1.5.evil.com`、`172.16.0.1.attacker.net`、`127.0.0.1.evil.com`、`notlocal`。
- 步骤：按 HTTPS URL 传入。
- 预期：全部拒绝，不能靠私网前缀命中。

### TC-407 私网边界与非法 octet

- 关联需求：REQ-202；优先级：P1；类型：单元；模块：地址分类。
- 前置条件：空环境。
- 数据：172.15、172.32、11、192.169 各段的地址，以及 `999.168.1.1`。
- 步骤：逐项解析。
- 预期：越界地址不按私网接受；非法 octet 由 URL 解析拒绝。

### TC-408 auth override 环境隔离

- 关联需求：REQ-204；优先级：P1；类型：单元与服务回归；模块：鉴权。
- 前置条件：隔离测试 fixture，不使用真实凭据。
- 数据：非 production 非 packaged、production、packaged 三类组合。
- 步骤：调用 `allowsArtifactCloudAuthOverride`；服务级测试使用模拟账号和 fetch。
- 预期：仅第一类允许显式 override；常规请求仍走原 Profile/session 校验。URL 放宽不得改变 bearer、重定向、超时或 profile fence 契约。

### TC-409 优先级、trim 与标准化

- 关联需求：REQ-201；优先级：P1；类型：单元；模块：配置。
- 前置条件：传入显式环境 fixture。
- 数据：不同的合法 override/env，空白 override，带空白与末尾 `/` 的合法 origin。
- 步骤：依次解析。
- 预期：override 优先；空白回退 env；返回规范化 origin。此规格由现有代码契约整理，现有九个测试项未逐项覆盖这些组合，需与执行结果分开。
