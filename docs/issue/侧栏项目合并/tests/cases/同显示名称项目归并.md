# 同显示名称项目归并测试规格

> D-007 最终范围：只增加同名归类及显示键接线。原菜单、按钮、折叠机制、业务归属和原容器排序均沿用；历史目录选择/折叠继承预期已删除。完整 20 场景见[方案测试矩阵](../../solutions/项目分组最小改动方案-10-23.md#62-测试场景操作与明确预期)。

## TC-611 同名加入与改名分开

- 优先级/类型：P0，逻辑与真实 DOM。
- 前置：本机、mini、dbox 各有一个独立普通目录项目和工作区；本机/mini 显示名称为 workspace，dbox 为 workspaces，记录原路径和标识。
- 操作：按项目显示；把 dbox 显示名称改为 workspace，再改为 workspace-dbox；另检查首尾空白、大小写和空名。
- 预期：开始为两项，本机与 mini 共一项；改为同名后同一头下三个原工作区；改为不同名后只分开 dbox。仅去首尾空白，大小写不同不合并，空名不触发新归并。路径和工作区名称分别保留。

## TC-612 保留原仓库规则

- 优先级/类型：P0，逻辑及 Local/SSH DOM。
- 前置：同仓库的两个主机目录显示名称不同；另准备不同 provider 同名项目及同一执行面的两个独立 checkout。
- 操作：查看项目区块与原项目身份。
- 预期：同仓库按原规则合并，即使不同名也不因改名拆开；不同原生仓库同名可组合展示，原身份保留；原先需要区分的同执行面 checkout 不被同名规则强行合并。其他副本别名不触发传递串组。

## TC-613 原生身份与业务归属保留

- 优先级/类型：P0，结构与副作用检查。
- 前置：记录 Repo、原生 Project/setup、工作区及原归属索引，准备同名目录。
- 操作：计算名称组合、加入、改名拆分，并读取原对象。
- 预期：纯展示计算不改任何输入；native projectId、路径、repo/worktree/instance ID 不变，原 ownership index 保留。文件、Git、任务、AI Vault、快捷命令等不接收展示键；无人工成员名单或新归属 RPC 写入。

## TC-614 原菜单与原终端

- 优先级/类型：P0，真实 Electron/IPC/RPC 与基线差异核对。
- 前置：同名组含本机和远端目录，沿用原手工排序将远端目录排在首位；选中远端工作区并建立终端，记录原 PTY/实例；目录的已知 upstream 状态为 null。
- 操作：打开归类头的原 Project actions 菜单，直接进入原 Project Settings 修改显示名称。
- 预期：没有新增目录选择子菜单；原设置页展示代表 repo 的原远端路径。owner 回读仅 displayName 改变；原工作区与终端身份保留，仍连接、可写。SectionHeader、原菜单、回调和拖拽源码与集成基线一致；新建/移除/图标仍是代表 repo 的原单目标行为，不变为批量操作。

## TC-615 原折叠、容器排序与导航

- 优先级/类型：P0，逻辑、hook 与真实 DOM。
- 前置：准备同名区块、原手动顺序、近期活动、不同手工 ProjectGroup 与嵌套父组；预存全部原来源折叠键，新名称键无记录。
- 操作：计算新列表；点击归类头折叠/展开；从不分组、状态、PR 视图定位名称头；折叠后定位成员工作区；再改名检查键。
- 预期：新名称键无记录时默认展开，不继承或删除原来源键；原 toggleCollapsedGroup 只切换传入键。原全局区块顺序中首个来源决定代表 repo，之后原容器二次排序不变，不承诺原屏幕首个位置。不同手工容器不新归并；显式按主机查看时仅在各自主机内补同名归类。同一原项目横跨容器时保留原组。原代表项目自定义颜色保持。
- 导航预期：三种视图均按原流程切回项目视图并完成定位；名称头能解析原 ProjectGroup 父链；工作区通过 occurrence plan 找到名称区块并展开。原工作区 ID/主机与真实 ownership 不变。无模型或缺少原映射时保持原回退分区，不主动读取主机。

## TC-616 移动端共享归并

- 优先级/类型：P0，移动列表模型。
- 前置：手机收到含原项目/目录的 catalog，三主机各有独立同名普通目录。
- 操作：生成列表并变更其中一个显示名称。
- 预期：同名区块合一，原排序下的三个工作区身份保留；改名后对应区块分开；原 catalog 和工作区输入不变。旧端仍能使用原字段和原 ID。

## TC-617 SSH、原执行目标与名称持久化

- 优先级/类型：P0，隔离应用与真实 SSH 传输。
- 前置：当前客户端和独立 owner，通过已认证 SSH 转发连接；两边有普通目录与同仓库 Git 目录。
- 操作：加载归并列表，选择远端工作区，通过原菜单编辑远端目录名称，owner 回读并重载客户端。
- 预期：普通目录按同名归并；同仓库 Git 的不同显示名称保持原自动归并；选中远端时执行 host 不变。名称在 owner 及重载后保留；原路径、工作区项目 ID/实例保留；名称功能不发起额外直连 SSH。测试授权公钥与临时环境能精确清理。
