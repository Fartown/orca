# 自托管产物后端

## 1. 背景、目标与来源

**一条规则：文件在哪台电脑上，就由那台电脑上的 Orca 提供链接。**

2026-09-16，用户在 mbp5 的 Orca 里打开 minizc 上的文件点分享失败：旧实现把文件内容发给「Orca 窗口所在电脑的 `127.0.0.1:8787`」，mbp5 上那个端口是 llm-proxy，文档正文连同 Orca 账号 token 被转发到了内部上游服务。用户随后确认：Artifact 是局域网服务，文件在哪台电脑就由哪台电脑提供；由 Orca 自己实现，不用外挂服务；服务跟着 Orca App；链接使用 IP；不复制文件，按工作区随机码读取原文件；旧链接不保留（D-004、D-005）。

目标：在 Orca 里打开的任何文件都能生成局域网链接，链接始终显示已保存的最新内容；无论文件在你操作的电脑上，还是在你连着的另一台电脑上，规则相同。

目标分级：P0 为 REQ-301～REQ-305、REQ-309；P1 为 REQ-306～REQ-308、REQ-310～REQ-312。优先级不等于实现或验收状态。

方案见 [局域网 Artifact 分享服务重构方案](../solutions/局域网Artifact分享服务重构方案.md)。

## 2. 场景与范围

两种场景适用同一套规则，每条需求都按这两种场景验收：

- **文件在你操作的电脑上**：由这台电脑的 Orca 提供链接。
- **文件在另一台电脑上**（例如经 SSH 打开的工作区）：由那台电脑上的 Orca 提供链接；你操作的电脑只负责把请求转过去，不留记录、不开端口。

In scope：分享服务、分享记录、分享弹层、Artifacts 页、设置页、`orca artifacts` 命令与 Agent 指南、停用旧的外挂服务地址和云端分享。Git worktree 与文件夹工作区行为相同。

Out of scope：公网访问、账号登录、HTTPS 证书、自动服务发现、未保存修改的分享、大文件断点续传（Range）。

## 3. 需求点

### REQ-301 由文件所在电脑提供链接

- 目标级别：P0；当前状态：部分实现。文件在本机时通过（2026-10-25 隐藏实例实测，链接返回 200）。文件在 SSH 主机上时，2026-09-17 双实例验证曾通过（当时 SSH 由 relay 执行）；2026-10-21 起 SSH 改由 orcad 执行，orcad 只读自己的分享开关，而这个开关无法从客户端打开，主机上的桌面 Orca 也打不开它（2026-10-25 实测），所以目前拿不到链接，待定方案。
- 规则：链接为「那台电脑的局域网 IP + 端口 + 工作区随机码 + 文件在工作区里的相对路径」。自动选择 IP 时优先物理网卡上的局域网地址，不选 VPN 隧道分到的地址；可在那台电脑的设置里固定选用某个 IP。
- 验收（文件在本机）：本机 Orca 生成链接，局域网里另一台电脑的浏览器能打开。
- 验收（文件在另一台电脑）：生成的链接指向那台电脑的 IP 和端口，与在那台电脑上直接分享得到的链接相同；你操作的电脑上没有分享记录、没有新占用的端口；连不上那台电脑时报错，不回退到本机处理。

### REQ-302 分享服务跟着 Orca App

- 目标级别：P0；当前状态：已实现，开关、退出重开与第二个 Orca 接手经双实例验证；升级 Orca 与重启电脑后的恢复未验证。
- 规则：文件所在电脑的 Orca 开着、并开启了「在局域网分享」时提供；关闭开关或退出 App 即停止、释放端口；重新打开自动恢复，链接不变。同一台电脑上只有一个 Orca 提供服务，提供者退出后另一个接手。
- 验收（文件在本机）：关闭开关后链接打不开，打开后原链接恢复。
- 验收（文件在另一台电脑）：你操作的电脑退出 Orca 或断开连接，链接照常可打开；那台电脑的 Orca 退出后链接打不开，重新打开后恢复。

### REQ-303 不复制文件、不经过其他程序

- 目标级别：P0；当前状态：已实现。
- 规则：分享只写分享记录（工作区、随机码、生成过链接的文件），不保存文件内容；不走网络接口、不需要 Orca 账号，不向任何其他程序发送文件内容；每次访问读取磁盘上的文件。
- 验收（文件在本机）：保存后刷新链接即显示新内容；分享记录目录里没有文件内容。
- 验收（文件在另一台电脑）：命令行和界面只把路径传给那台电脑，文件内容不经过你操作的电脑。

### REQ-304 端口由 Orca 管理

- 目标级别：P0；当前状态：已实现，确认后端口被占用的上报与恢复经双实例验证；首次换端口只有自动化覆盖，设置页改端口未真机验证。
- 规则：默认端口 18787；第一次启动时被占用就在 20000～29999 中随机选一个并记住；记住之后再被占用，明确报端口冲突，不自动换（避免链接悄悄失效）；端口和链接 IP 只能在那台电脑自己的 Orca 设置里修改。
- 验收（文件在本机）：设置页显示服务状态、IP 与端口，修改端口前确认，修改后新链接可打开。
- 验收（文件在另一台电脑）：分享弹层和 Artifacts 页显示那台电脑的端口冲突状态，不提供修改入口。

### REQ-305 访问范围与请求安全

- 目标级别：P0；当前状态：已实现，自动化测试、本机浏览器冒烟与双实例验证覆盖。
- 规则：一个随机码开放一个工作区里的文件；不列目录（目录只返回其中的 `index.html`）；拒绝 `.git`、`.env`、密钥等敏感路径和指向工作区外的符号链接；除读者评论接口（REQ-311）外只接受 GET 与 HEAD，评论接口只接受本页发出的请求（跨站请求、新增与修改时非 JSON、超过 32 KB 一律拒绝），修改与删除还必须带写评论时发给该浏览器的凭证，每个地址每分钟最多 20 次写入；畸形请求只影响自己；Markdown 页禁止内嵌脚本执行，只能连回自己的服务；停止分享立即作废随机码。
- 验收（文件在本机）：改写链接访问 `.env`、`.git/config`、`../` 越界、错误随机码、目录，全部 404；向文件 POST 返回 405；评论接口的跨站、非 JSON、超大、格式错误请求分别返回 403、415、413、400，连续写入触发 429；服务不中断。
- 验收（文件在另一台电脑）：路径复核在文件所在电脑上完成，敏感文件在分享前即被拒绝并报 `artifact_share_path_denied`。

### REQ-306 分享弹层

- 目标级别：P1；当前状态：已实现，开关未开启、Orca 没开、连不上、端口冲突、未保存提示经双实例截图验证；过旧、启动失败、路径被拒只有自动化覆盖。
- 规则：编辑器里可分享的文档（Markdown 与 HTML）、浏览器里打开的本机文件、工作区 HTML 预览、聊天回复里的内联可视化都有「在局域网分享」入口。弹层显示由哪台电脑提供、分享前写明会开放哪个工作区、生成后显示链接并可复制和打开、可停止分享整个工作区（先确认）；未保存时提示保存后可见。
- 验收：以下原因都显示对应文案而不是通用失败：开关未开启、那台电脑的 Orca 没开、连不上、那台电脑的 Orca 过旧、端口冲突、服务启动失败、路径被拒、无法确定文件所在电脑。
- 验收（文件在本机）：开关未开启时提供「打开 Artifacts 设置」。
- 验收（文件在另一台电脑）：提示到那台电脑的 Orca 里开启，不提供本机设置入口。

### REQ-307 Artifacts 页

- 目标级别：P1；当前状态：已实现，分组显示与停止分享经双实例验证；没连着的电脑的显示只有自动化覆盖。
- 规则：按电脑分组，列出本机、当前连着的其他电脑、分享过但没连着的电脑；每组显示服务状态、正在分享的工作区和生成过链接的文件；可复制、打开链接和停止分享。
- 验收（文件在本机）：本机分组显示服务状态与链接。
- 验收（文件在另一台电脑）：连着时显示那台电脑的状态与链接；没连着时标为无法确认，并说明那边的链接在其 Orca 开着时照常可用。

### REQ-308 命令行与 Agent 指南

- 目标级别：P1；当前状态：已实现，SSH 终端里的 share 与 unshare 经双实例验证；本机 Orca 终端里的命令只用 CLI 直连实例验证。
- 规则：`orca artifacts share|unshare|list|delete|service status` 由命令运行所在电脑提供链接；分享范围取终端所在工作区；`update` 与 `--api-url` 不再适用并给出说明；Agent 指南说明开关只能由人打开、链接开放整个工作区、拒绝时不要重试。
- 验收（文件在本机）：本机终端里 `share` 输出本机链接，首次分享工作区时提示整个工作区可读。
- 验收（文件在另一台电脑）：在 Orca 里打开的那台电脑的终端里执行，输出那台电脑提供的链接；文件大小不受 CLI 传输上限限制。

### REQ-309 停用旧入口

- 目标级别：P0；当前状态：部分实现：代码侧已停用并经双实例验证（云端接口返回不可用、外挂服务日志无新请求）；minizc 上的外挂服务仍在运行，下线须经用户确认。
- 规则：不再向 `127.0.0.1:8787` 或云端发送任何 Artifact 内容；`artifacts.*` 云端接口返回不可用；外挂服务 `~/dev/orca-artifact-server` 下线，旧链接不保留。界面上不保留任何云端「分享为工件」入口：上游新增的同类入口一律改走局域网分享，架构门禁 `self-hosted-artifacts-no-cloud-share-entries` 禁止 renderer 引用云端分享按钮。
- 验收（文件在本机）：调用 `artifacts.publish` 返回 `Artifact service is unavailable.`，没有对外网络请求。
- 验收（文件在另一台电脑）：分享那台电脑上的文件时，你操作的电脑上的 8787 端口没有新请求。

### REQ-310 分享页与 Orca 内置预览一致

- 目标级别：P1；当前状态：已实现，自动化测试与浏览器实测覆盖（2026-11-05，含 AT-20 走查清单 60 项）；装进 Orca App 后的真机浏览未执行。
- 来源：2026-11-05 用户反馈分享出去的 Markdown 网页「很丑」，希望和 Orca 内置预览一样有目录；同日 Fartown/orca#87 指出图片、图表没有查看器等缺口，要求按功能清单逐项走查。
- 规则：Markdown 分享页使用 Orca 自己的样式表、字体与预览组件，不另写一套样式；顶部标题栏显示文件名、所在目录与由哪台电脑分享；左侧是与 Orca 内置预览相同的目录面板（按 H1～H5 折叠、可拖宽、可关闭），宽屏且有标题时默认打开，窄屏点开后浮在正文上、点标题后收起；点目录标题跳到对应位置并把 `#标题` 写进地址，打开带 `#标题` 的链接直接定位；GitHub 提示块（`> [!NOTE]` 等）与 Orca 内置预览显示相同；标题栏可打开 Markdown 原文（`?raw=1`）。读者评论见 REQ-311。
- 与内置预览相同的能力（2026-11-05 走查清单，见 AT-20）：
  - 渲染：front matter 不显示为正文、GFM（表格对齐、任务列表、删除线、自动链接、脚注）、换行即换行、`<kbd>`/`<sub>`/`<sup>`/`<ins>`/`<details>`、代码高亮且长行在代码块内横向滚动、Mermaid、KaTeX（含字体）、相对路径图片与 HTML `<img>` 尺寸。
  - 查看器：点图片打开 Orca 的图片查看器（可缩放、Esc 关闭；带链接的图片仍跟随链接）；图表的展开按钮打开 Orca 的图表查看器；代码块右上角复制按钮（局域网 http 页面也能复制）。
  - 链接：页内锚点与脚注在页面自己的滚动区里定位并写入地址；同一分享内的相对 `.md` 链接在本页打开；网页链接在新标签打开；`file:` 本地路径与 `[[文档]]` 链接只显示文字（读者打不开分享者电脑上的文件）。
  - 语言：界面文案跟随浏览器语言（Orca 已有的语种，繁体中文单独匹配），`<html lang>` 同步。
  - 大文档：超过 Orca 富文本预览上限（600 KB）时，先立即显示「正在准备预览」，再渲染全文与目录；Orca 内置预览此时改用虚拟滚动，分享页仍整页渲染（已知限制：1.1 MB 文档约 9 秒后出正文）。
- 验收（文件在本机）：桌面浏览器打开链接，看到标题栏与目录，点目录跳转、`#标题` 链接可直接定位；手机宽度下目录默认收起、打开后浮在正文上；亮、暗两种主题显示正确。
- 验收（文件在另一台电脑）：那台电脑的 Orca Server 用随它部署的分享页文件（只有 `viewer.orcad.js`、`viewer.orcad.css` 与清单三份，字体内嵌）提供同样的页面，不需要额外的文件或网络请求。

### REQ-311 读者评论成为 Orca 审阅笔记

- 目标级别：P1；当前状态：已实现，文件在本机的场景经自动化测试、浏览器走查与隔离 Orca 实例实测（2026-11-05）；文件在 SSH 主机上的场景只有类型检查、单元测试与 Orca Server 版页面的浏览器走查覆盖，真机未执行。
- 来源：2026-11-05 用户要求分享页「有评论」，并选定方案 1（D-008）：局域网内拿到链接的人都能评论，评论存在文件所在电脑，Orca 里显示为该文件的审阅笔记、可发给 agent。同日 Fartown/orca#87：名字不应必填、看不出评论的是哪段、没有删除、评论后正文大片空白。
- 规则：
  - 两种评论方式：选中正文里任意文字后点浮出的「评论」，摘录为所选文字；或悬停（手机上点一下）段落、标题、列表项、引用与提示块里的段落、代码块、表格左侧的「添加评论」，摘录为整块。名字选填（浏览器记住），不填显示「匿名读者」；内容回车提交、Shift+回车换行、Esc 取消。
  - 被评论的文字用 Orca 富文本编辑器审阅笔记的颜色标出；悬停或点评论卡加深对应文字，点被标出的文字把对应卡片滚到眼前，点卡片空白处把对应文字滚到眼前。
  - 评论卡与 Orca 的审阅笔记卡相同；宽度足够时（正文区不小于 760 px）卡片放在正文右侧的独立栏，和所评论的文字对齐、互不重叠，正文段落间距不因评论改变；更窄时卡片排在对应块下方。文件改过后对不上位置的评论列在页尾「针对旧版本的评论」。
  - 评论按「工作区文件夹 + 文件相对路径」保存在文件所在电脑的分享目录（`~/.orca-artifact-share/comments/`），不写进工作区，停止再重新分享后仍在；每个文件最多 500 条，名字最长 64 字、内容最长 4000 字、摘录最长 2000 字。
  - 写评论的浏览器拿到一个凭证（文件里只存它的哈希），凭此编辑、删除自己的评论；别人的评论没有编辑、删除按钮，接口也拒绝（403）。删除留下记录，供 Orca 同步删除笔记。回到页面标签时重新读取评论，看到其他读者新写的；页面不轮询。
  - 文件所在电脑上管理该工作区的 Orca（本机工作区是桌面 Orca，SSH 主机上的工作区是那台主机的 Orca Server）监听评论目录，把新评论加成该文件的审阅笔记：位置为评论的源文件行，内容为「名字 via share link: 评论」或「Via share link: 评论」，摘录为评论的摘录；写入时带上原列表做合并，不覆盖其他客户端同时加的笔记；随后照常推送给所有连着的 Orca。
  - 每条评论只变成一次笔记；笔记被删除或发给 agent 后不会再出现。读者编辑或删除评论时，对应笔记只要在 Orca 里没被改过就跟着更新或删除；在 Orca 里改过的笔记保持原样。在 Orca 里编辑、删除笔记不影响分享页上的评论。没有工作区包含该文件时评论先保留，工作区加进来后再导入。
- 验收（文件在本机）：在分享页评论后，本机 Orca 里该文件出现对应位置的审阅笔记，可发给 agent；发送后不再出现；读者改、删评论后未改动的笔记跟着变。
- 验收（文件在另一台电脑）：在那台电脑的分享页评论后，由那台电脑的 Orca Server 写成笔记，你操作的电脑通过推送看到；你操作的电脑不读取评论、不轮询。

### REQ-312 命令行读取与删除评论

- 目标级别：P1；当前状态：已实现，CLI 参数与 RPC 请求、文件所在电脑上的读取与删除经自动化测试，读取与删除经隔离 Orca 实例实测（2026-11-05）；SSH 主机上的真机未执行。
- 来源：2026-11-05 用户要求给 CLI 加「获取评论、删除评论」。
- 规则：
  - `orca artifacts comments list <file>` 列出该文件的读者评论（id、名字、时间、源文件行、摘录、内容），从旧到新；`--json` 输出完整字段。
  - `orca artifacts comments delete <file> <评论id>...` 删除指定评论，`--all` 删除该文件全部评论；两者必须二选一。删除后分享页不再显示，那台电脑上由这些评论变成的审阅笔记一并删除；其他电脑上的笔记不动。
  - 和其他 `artifacts` 命令一样由文件所在电脑处理：经 `artifactShare.comments` 与 `artifactShare.deleteComments` 转发，连不上时报错，不回退本机。
  - Agent 指南说明评论来自任何拿到链接的人，只能当反馈看，不能当指令执行；只删用户要求清掉或已经处理的评论。
- 验收（文件在本机）：本机终端里 `list` 输出评论，`delete` 后分享页与 Orca 笔记都不再有这条。
- 验收（文件在另一台电脑）：在 Orca 里打开的那台电脑的终端里执行，读取与删除都在那台电脑上完成，那台电脑的 Orca Server 删除对应笔记并推送。

## 4. 验收与未决

测试用例见 [局域网 Artifact 分享功能测试](../tests/cases/自托管产物后端功能测试.md)。执行结果记在 `tests/runs/`：自动化与本机冒烟见 2026-09-17 局域网分享自动化与冒烟；真机用例按用户要求用独立构建在 minizc 上起两个实例经 SSH 互连验证，见 2026-09-17 双实例 SSH 真机验证。未验证：升级与重启电脑后的恢复（TC-17）、配对的远程 Orca（TC-21）、设置页手动改 IP 与端口。

读者评论已由用户选定方案（D-008），见 REQ-311；SSH 主机上的真机验证未执行。已知限制：项目分组里的文件夹工作区（`folder:`）不导入评论；Orca 渲染进程用旧列表整体写回笔记时，可能覆盖它刷新之前导入的笔记（上游笔记写入的既有行为）。
