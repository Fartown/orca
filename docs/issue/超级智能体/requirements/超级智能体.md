# 超级智能体（super agent）

## 背景

用户现在亲自驱动 Orca：开工作区、选智能体、写提示词、盯着各个会话、在「需要你」里逐个处理、记得回头检查 CI 和 PR。会话一多、主机一多（本机、SSH 主机、配对服务器），注意力就成了瓶颈。

用户希望以后**只和一个 super agent（下称「总管」）对话**：说清要什么，由总管拆任务、开工作区和会话、派给合适的智能体、跟进到底；只在必须由用户决定、结果可以验收、或者做不下去时主动找用户；能按时间处理事情，也能过一阵子回头检查。

调研结论（[参考产品调研](../research/参考产品调研.md)、[Orca现有能力盘点](../research/Orca现有能力盘点.md)）：

- 同类产品的共识是「一个对话入口 + 多个执行者」、「注意力最贵、默认安静」、「问人是结构化对象」、「权限由代码裁决而不是提示词」、「时间也是事件」。
- Orca 已经有派工与唤醒（编排）、工单与「需要你」（本地任务）、持续推进与验收（Goal）、主机上的定时运行（自动化）、结构化聊天与手机聊天、通知与推送。缺的是把它们串起来的一层。

所以总管**不是一个新的任务系统，也不是 Orca 自己调大模型**：它是一个常驻的官方智能体 CLI 交互式会话（用户平时用的 `claude`、`codex`，用用户自己的订阅登录），作为 Orca 编排的协调者；加上 Orca 主进程里一个负责记账、裁决、问人、计时的内核。

## 范围

### 本需求做

- 一个唯一、常驻、可恢复的总管会话，桌面和手机都能和它对话。
- 总管能看全局、建任务、建工作区、开会话或派 worker、跟进、汇总、问人、通知、定时和复查。
- 动作分级与审批、预算与熔断、活动记录、记忆。
- 以上全部在本机工作区和 SSH 工作区（以及配对服务器）上都成立。

### 不做（至少第一期）

- 不另做任务库、派工系统、续跑循环或调度器：分别用本地任务、编排、Goal、自动化。
- 不在 Orca 里直接调用大模型 API、不保管模型凭据。
- 不做研发流程本身（评审、合并策略、发布）；总管可以派 worker 去做，但合并、推送这类动作要先问。
- 第一期不接外部聊天渠道的**入站**（在飞书、Slack 里和总管对话、读别人的回复）。**对外发送**（飞书消息、建 PR、合入）在切片 3 提供，且只在用户确认过的委托内或逐次审批后执行（REQ-2316、REQ-2318）。
- 不自动批准 worker 的权限请求（终端里的「允许执行吗」）。
- 不做没人请求就直接落地的「投机执行」；没人请求的工作只以「建议」出现。

## 需求

### REQ-2301 唯一的总管会话，桌面与手机都能对话

当前状态：待确认

用户在 Orca 里有一个固定入口打开总管；首次打开时引导选择总管使用的智能体（默认 Claude Code，其次 Codex），由 Orca 创建总管工作区，并在其中以终端会话启动官方 CLI——用用户自己已有的登录（订阅或 API Key 都行），Orca 不经手凭据，也不经 Claude Agent SDK。之后每次打开都是同一个会话；会话崩溃或 Orca 重启后恢复原会话，恢复不了时新开一个并带上恢复说明（之前在跟进什么、还有哪些卡片未关），不丢已记录的事。

- 本地场景：总管工作区、总管会话、总管内核都在总管所在机（默认桌面）上；用户在桌面侧栏入口与它对话。
- SSH 场景：总管仍在总管所在机上运行，不搬到 SSH 主机；它通过 Orca 已有的主机路由管理 SSH 主机上的工作区和会话。SSH 断开不影响和总管对话。
- 手机：手机连上总管所在机后，在首页看到总管入口，进入的是同一个会话（手机已有的终端会话聊天视图）。总管所在机离线时手机显示「总管不在线」，不假装能用。
- 验收：桌面与手机先后发消息，看到的是同一段对话；重启 Orca 后入口回到同一会话；同一台 Orca 上不会出现两个总管。

### REQ-2302 一句话看全局

当前状态：待确认

用户问「现在都在干嘛」「哪些要我处理」时，总管能给出跨主机的全局概览：各主机的联系状态、各工作区、各会话（智能体、在做什么、状态与判定）、本地任务和「需要你」、总管派出的 worker、正在跑的 Goal 与自动化、未关的卡片。概览先给摘要和编号，细节按编号再读，避免一次塞满上下文。

- 本地场景：读本机 runtime 的记录与状态。
- SSH 场景：只读在联系中的 SSH 主机（连接状态为 `connected`）；不在联系的主机整体标「无法确认」，其上的会话判定为 `unverifiable`，绝不写成「已结束」；总管不为了出概览去重连或重试。重新联系上之后，下一次概览自然读到新状态。
- 配对服务器：同样只读在联系中的。
- 验收：本机、SSH、配对三类工作区同时存在时，概览分别列出；拔掉 SSH 连接后再问，SSH 主机显示「无法确认」且没有产生重连请求。

### REQ-2303 代办：建任务、开工作区、派活、汇总

当前状态：待确认

用户描述一件事，总管能：在合适的项目里建本地任务（可拆子任务）；为任务开工作区（指定或推断仓库、主机、分支）；开会话或派 worker（指定或按偏好选智能体），把任务说明、约束、验收证据要求交给它；worker 做完后汇总结果和证据，向用户报告；同时更新任务状态与评论。

- 总管自己不写业务代码，实现交给 worker；它只读必要的信息来拆分和验收。
- 本地场景：工作区与会话建在本机。
- SSH 场景：工作区与会话建在用户指定（或项目所在）的 SSH 主机上，任务存进那台主机自己的任务库（本地任务 D-008）；worker 的会话归 SSH 主机，判定归 SSH 主机。SSH 不在联系时，总管不建、不重试，告诉用户「那台主机现在连不上」。
- 验收：一句「在 X 仓库修 Y，用 codex，做完告诉我」能在本机和 SSH 主机上各走通一遍：出现任务、工作区、worker 会话，worker 完成后用户收到一条带证据的结果，任务状态随之变化。

### REQ-2304 跟进与异步检查

当前状态：待确认

总管跟进它派出去的工作，以及用户明确要它盯的会话或任务：完成、卡住、等人、失败时，总管被唤醒并决定下一步（继续指示 worker、回答 worker 的问题、换方案、问用户、向用户报告）。总管能给自己预约复查：到某个时间点，或等某个条件成立（某会话这一轮结束、某 worker 交付、某任务状态变化、某 PR 的检查有了结果、某主机重新联系上），条件成立前不唤醒总管、不花 token。

- 总管不轮询、不 sleep 等待；唤醒由 Orca 推送。
- 本地场景：条件由本机的智能体状态、编排、任务库事件判定。
- SSH 场景：条件由 SSH 主机推来的状态判定；主机失联期间条件既不算成立也不算失败，复查保持等待；到达截止时间仍不能确认时，唤醒总管并明确告知「无法确认」，不当成失败或完成。
- 验收：「30 分钟后看看 CI 过没过」「minizc 上那个会话这轮结束了叫我」都能触发；SSH 断开期间到期的复查给出「无法确认」而不是「失败」。

### REQ-2305 主动通知：只在值得打断时

当前状态：待确认

总管通过「卡片」找用户：问题卡片（一次一个具体问题，带选项和推荐项，可附自由回答）和通知卡片（结果可验收、做不下去、日程报告）。卡片出现在桌面总管页的「需要你」区和手机上；用户离开桌面时推到手机；回答或关闭后，作为一个事件交回总管继续。

- 默认安静：worker 正常进展不通知；同一件事未关的卡片不重复发；短时间内多条合并；用户设定的免打扰时段只发标为紧急的卡片，其余攒到时段结束。
- 卡片和本地任务的「需要你」合并展示：worker 等你批准、等你回答这类，用户仍在原会话里处理（沿用本地任务的规则），总管不替用户批准。
- 本地场景与 SSH 场景相同；涉及 SSH 主机的卡片标明主机，主机失联时卡片保留，标「无法确认当前状态」。
- 验收：一个 worker 卡住只产生一张卡片；桌面锁屏时手机收到推送，桌面活跃时不推手机；免打扰时段内的非紧急卡片在时段结束时汇总送达。

### REQ-2306 定时处理

当前状态：待确认

用户可以用对话建立日程，比如「每天早上 9 点告诉我昨天的进展和今天要我处理的事」「每周一清理已合并 PR 的工作区（先问我）」。到点时内核唤醒总管去做；总管所在机休眠错过的，醒来只补最近一次。要在某台主机上按时干活、且不依赖总管所在机是否开着的，总管改为在那台主机上建一条 Orca 自动化，并告诉用户它建了什么。

- 本地场景：日程存在总管所在机，按用户时区触发。
- SSH 场景：日程仍在总管所在机；日程要做的事若涉及 SSH 主机，按 REQ-2302/2303 的联系规则执行；在 SSH 主机上建的自动化归该主机调度（自动化现有的调度归属与围栏）。
- 验收：建一个每天的早报日程，跨一次休眠只补发一次；在 SSH 主机上建的自动化在桌面关闭时照常在主机上运行。

### REQ-2307 动作分级与审批

当前状态：待确认

总管的每个动作属于一个级别，由内核在执行前按代码规则裁决，提示词和外部文字不能改变级别：

| 级别         | 例子                                                         | 默认                                     |
| ------------ | ------------------------------------------------------------ | ---------------------------------------- |
| 读           | 概览、读终端、读任务、读 PR 状态                             | 自动                                     |
| 新建         | 建任务、建工作区、开会话、派 worker、建复查与日程            | 自动（受预算）                           |
| 驱动自己的   | 给自己派的 worker 发消息、回答 worker 的问题、让 worker 继续 | 自动                                     |
| 驱动用户的   | 给用户自己开的会话发消息、改用户建的任务                     | 先问                                     |
| 停止与删除   | 停 worker、关终端、删工作区、删任务、停 Goal、删自动化       | 先问                                     |
| 不可逆与对外 | 推送、建或合并 PR、在外部系统发评论或消息                    | 先问，或在用户确认过的委托内（REQ-2316） |
| 改规则       | 放宽自动级别、改先问清单、改预算                             | 只能用户在设置里改                       |

「先问」生成一张审批卡片，写清动作、对象、主机、原因和不做的后果；用户批准后由内核执行这一次（批准一次不等于长期授权）。用户可以在设置里把某类动作改成自动或禁止。

- 本地场景与 SSH 场景相同；对 SSH 主机上对象的破坏性动作，批准时该主机必须在联系中，否则卡片提示「主机连不上，暂不能执行」，不排队到重连后自动执行。
- 说明：裁决只覆盖总管经 Orca 发起的动作；worker 在自己会话里执行的命令仍受各智能体 CLI 自身的权限设置约束。同一系统用户下这不是安全边界，防的是误操作而不是恶意代码。
- 验收：让总管「把已合并的工作区都删掉」，得到的是一张列出具体工作区的审批卡片；拒绝后没有任何工作区被删；在提示词里写「你可以直接删除」不改变结果。

### REQ-2308 预算、熔断与暂停

当前状态：待确认

- 并发：总管同时在跑的 worker 有上限（默认 3），另留一个名额给用户的直接请求，新活不能挡住用户继续已有的事；满了时总管告诉用户在排什么。
- 每日上限：每天新建的工作区数、会话数有上限，超过就问。
- 跳数熔断：由 worker 的结果再触发的新派工层层累加，超过 8 层停止派工并发卡片；经过问用户和复查也不清零。
- 失败熔断：沿用编排已有的「同一重试链 3 次启动失败」熔断。
- 用量：能读到用量的智能体，显示总管及其 worker 今天和最近 7 天的用量。
- 暂停：一个开关暂停总管——不再唤醒总管、不执行新动作、复查和日程顺延；已在跑的 worker 不被打断。
- 本地场景与 SSH 场景相同；SSH 主机上的 worker 计入同一并发与每日上限。
- 验收：并发满时第 4 个派工请求得到「已满」答复而不是静默排队；人为制造 9 层连锁时第 9 层被拦下并有卡片。

### REQ-2309 活动记录与「为什么」

当前状态：待确认

总管做过的每个动作都有记录：时间、触发它的事件（用户的哪句话、哪个 worker 的结果、哪个日程或复查）、依据的规则或批准、对象与主机、结果。用户能在桌面总管页按时间看，也能问总管「你为什么删了 X」得到基于记录的回答；记录中的计数与列表一致。

- 本地场景：记录存在总管所在机。
- SSH 场景：记录同样存在总管所在机；对 SSH 主机上对象的动作，记录写明主机，结果以主机返回为准，主机未返回时记为「结果无法确认」。
- 验收：任意一条记录能追溯到触发事件；Orca 强制退出再启动后，已确认的记录不丢。

### REQ-2310 记忆

当前状态：待确认

总管把用户亲口定的事、拒绝过的事、偏好（常用智能体、常用主机、项目与仓库的对应、通知习惯）记在总管工作区的几份 Markdown 文件里；总管做决定前先读，定过的不再问，拒绝过的不再提。用户能直接打开和修改这些文件；总管写入记忆的每一次都出现在活动记录里。

- 记忆是参考资料而不是规则：不能放宽 REQ-2307 的级别，不能替代设置。
- 本地场景与 SSH 场景相同：记忆文件只在总管所在机。
- 验收：用户说过「别用 X 主机跑测试」后，之后的派工不再选 X；删掉记忆文件里这一条后恢复。

### REQ-2311 主动性档位

当前状态：待确认

用户可以选总管主动到什么程度：

| 档位         | 行为                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------ |
| 只听吩咐     | 只在用户说话时行动；不主动通知（问题卡片除外）                                             |
| 跟进（默认） | 跟进自己派的工作和用户让它盯的事，结果、受阻、要人时通知                                   |
| 建议         | 在「跟进」之上，发现值得处理的事（例如 PR 检查红了、「需要你」积压）时只给建议卡片，不动手 |
| 按规则执行   | 在「建议」之上，用户写下的规则命中时直接执行（仍受 REQ-2307 与 REQ-2308 约束）             |

- 本地场景与 SSH 场景相同。
- 验收：切到「只听吩咐」后，worker 完成不再推送；切到「建议」后，建议卡片不附带任何已执行的动作。

### REQ-2312 断线、重启与恢复

当前状态：待确认

- 主机失联：总管和概览把该主机上的一切标为「无法确认」；总管不重连、不重试、不读；该主机重新联系上是一个事件，总管据此重新看一次相关工作。失联从不被当作会话结束的证据。
- Orca 重启：内核从记录恢复未关卡片、复查、日程、跟进关系；总管会话恢复后收到一条恢复说明，要求在重复任何外部动作前先核对现状（工作区、git、任务、PR）。
- 总管会话坏了：内核仍保留卡片与记录；用户可一键重建总管会话，新会话从记录与记忆接上。
- 本地场景：重启即总管所在机重启。
- SSH 场景：SSH 主机重启或 orcad 重启时，其上的 worker 判定由主机给出；主机重新联系前保持「无法确认」。
- 验收：在 worker 运行时断开 SSH、重启 Orca、再接回 SSH，全过程没有重复派工、没有把 worker 误报为结束。

### REQ-2313 以后：在别处和总管说话

当前状态：待确认

第二期起，沿用 Orca 现有 Slack 连接器的方式，让用户在外部聊天渠道（Slack、飞书等）和同一个总管对话、回答卡片，并读取别人在这些渠道里的回复（例如评审人回「点了」）。第一期只预留，不实现；对外发送见 REQ-2318。

- 本地场景与 SSH 场景相同：渠道接在总管所在机上。
- 验收：第一期无。

### REQ-2314 事项：交代的事必须有收尾

当前状态：待确认

用户交代的每件事都成为一个事项，存在总管所在机的账本里（不在总管的对话上下文里），带用户原话、类型、完成条件、计划、关联对象和预期时间。事项只有三种收尾：完成（完成条件由内核核对成立）、用户取消、失败（原因已告诉用户）。总管不能把事项标成完成而完成条件不成立，也不能不收尾就放下。

内核持续检查未收尾的事项：没有任何活的触发（在跑的 worker、观察器、复查、未关卡片）就判「无人跟进」并报警；过了预期时间就提醒用户；worker 停下 30 分钟没有汇报就判「停滞」。早报和概览列出全部未收尾事项。

- 本地场景：事项、检查都在总管所在机；关联的会话、任务在本机。
- SSH 场景：事项仍在总管所在机；关联对象在 SSH 主机上时，主机失联期间这些对象的事实为「无法确认」，不触发「停滞」，也不当作完成；预期时间到了照样提醒用户，并写明「主机连不上」。
- 验收：交付 PR 事项在 PR 合入前无法被标成完成；人为让一个事项失去所有触发，10 分钟内出现「无人跟进」并有卡片；SSH 断开期间该主机上 worker 的事项不被判停滞。

### REQ-2315 看得到没有推送的外部状态

当前状态：待确认

对于不会推给 Orca 的外部状态——PR/MR 的评审结论、合入状态、检查结果，以及用户要盯的监控——总管可以给事项挂观察器。观察器是确定性检查，不消耗模型额度，只在状态变化时唤醒总管（例如 `review_required → approved`、首次异常、恢复）；持续异常不重复通知。PR/MR 状态经 Orca 已有的托管评审读取，覆盖 GitHub、GitLab、Gitea、Bitbucket、Azure DevOps。

看不到时（没有权限、令牌过期、被限流、主机失联）如实标「无法确认」；连续看不到时给用户一张卡片，写明看不到什么、为什么，并提供「已经好了」「我去看看」「取消跟进」。用户确认会记为「用户确认」的事实。

- 本地场景：观察器在总管所在机运行。
- SSH 场景：目标只在某台 SSH 主机上可达（例如那台主机的 `127.0.0.1` 服务）时，检查在那台主机上运行，建成该主机的一条自动化，调度归该主机；总管所在机只在主机在联系中时读取结果，失联期间不重连、不加速重试。PR 状态读取在哪台机器执行，沿用托管评审现有的执行主机路由。
- 验收：PR 在别人点 approve 后 15 分钟内（按默认频率）唤醒总管；撤销读取权限后出现「看不到」卡片，点「已批准」后流程继续；SSH 主机上的监控在桌面合盖时照常运行，桌面醒来后补读一次结果。

### REQ-2316 委托：一次确认，按计划执行对外动作

当前状态：待确认

事项的计划里涉及对外或不可逆的步骤（发飞书、建 PR、合入、通知别人）时，总管把它们写成具体动作——对谁、做什么、内容、最多几次、什么时间段——交给用户在一张卡片上确认（可修改）。确认后，内核对计划里写明的动作直接执行，不再逐个审批；超出委托的（换了对象、多发一次、合入方式不同、approve 之后又有新提交）一律先问。合入前内核再核对一次评审结论、检查状态、有无新提交。委托随事项收尾失效，用户随时可撤销。

- 本地场景与 SSH 场景相同：委托记录在总管所在机；动作在哪台机器执行见 REQ-2318。
- 验收：委托「最多催 2 次」时第 3 次提醒被拒绝并转为问用户；approve 之后推一个新提交，合入被拦下。

### REQ-2317 进度随时可问，压缩和重启后不丢

当前状态：待确认

用户随时问「xx 做到哪了」，总管按事项账本回答：原话、当前步骤、状态及原因、最近几条事实及时间（worker 汇报、工作区提交、Goal 验收进度、PR 状态、观察结果）、下一个触发、预期时间。总管的对话被压缩、Orca 重启、总管会话被重建之后，回答依据不变。事实陈旧时如实说明有多久没有新事实。

- 本地场景：事实来自本机的会话、工作区与记录。
- SSH 场景：SSH 主机上的事实以最近一次在联系时读到的为准，并标明读取时间；主机不在联系时说明「现在连不上，以下是 X 时的情况」。
- 验收：交代一件开发任务，第二天在新的总管会话里问进度，得到与账本一致的答复；断开 SSH 后再问，答复标明数据时间与「连不上」。

### REQ-2318 对外动作：飞书发送、建 PR、合入

当前状态：待确认

总管能经内核执行三类对外动作：用总管所在机上用户已登录的 `lark-cli` 发飞书消息（私聊或群）；在 worker 推送分支后经 Orca 已有的托管评审创建 PR/MR；合入 PR/MR。这些动作只在委托内或逐次审批后执行，由内核执行并记下回执；失败时告诉用户，不静默重试。总管工作区的权限配置让总管与 worker 不能绕过内核直接运行这些命令而不经用户批准。

- 本地场景：`lark-cli` 与它的登录在总管所在机；PR 的创建与合入按托管评审现有的执行主机路由。
- SSH 场景：worker 在 SSH 主机上推送；创建与合入在哪台机器执行、用谁的凭据，沿用托管评审现有路由（待验证 V-6、V-7）；SSH 主机失联时不执行，告诉用户。
- 验收：在委托内完成一次「建 PR → 飞书提醒 → approve 后合入 → 群通知」，每一步在事项里有回执；断开 SSH 时合入不执行并有说明。

### REQ-2319 分工得当：不老是自己干，也不芝麻小事都派

当前状态：待确认

总管按固定判据决定自己做还是派 worker：会改工作区里的东西、会超过 30 秒、要读的内容超过一屏、需要在某台主机的环境里动手——任一为「是」就派 worker；否则自己做。状态、进度、历史和 Orca 自己的控制动作（建任务、改状态、复查、日程、回 worker、发卡片）由总管直接处理；一眼能看完的事实（PR 状态、最近提交、文件的几行、终端最后几行）用只读、限时、限量的探查。同一事项的后续发给原 worker，不新开。

代码层兜底：总管只能编辑自己的工作区，shell 命令超时上限 30 秒，构建、测试、包管理命令需批准；探查输出有上限；派 worker 必须带事项编号与理由，只是读、且在探查范围内的派工被拒绝；同一事项已有 worker 时再派需写明并行理由。活动页与早报给出每日分工统计（直接答、探查、派 worker、短命 worker、被拦下的「想自己动手」）；用户的纠正记入记忆。阈值可在设置里调。

- 本地场景：探查与派工在本机工作区上执行。
- SSH 场景：探查按工作区所属的 SSH 主机执行，只在该主机在联系中时；不在联系时返回「主机连不上」，不重试，也不因此改为派 worker。
- 验收：「PR#123 现在什么状态」「把 S-12 改成进行中」不产生任何新会话；「修一下登录页的 bug」产生一个挂在事项上的 worker，总管不直接改文件；在聊天里要求总管直接改仓库文件，被权限配置拦下并转为派 worker；同一事项的第二个问题发给原 worker。
