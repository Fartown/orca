# 终端退出模式恢复

## 背景与事实

用户报告 dbox 终端经常出现鼠标坐标字符串，并明确要求修复。2026-11-24 原 PTY 的执行主机证明 shell PID 等于前台 PGID、无子进程，但快照仍开启 any mouse、SGR、alternate screen、Kitty 和 modifyOtherKeys。现场已临时恢复，产品自动复位遗漏仍需修复。外部问题：Fartown/orca#156。

## 范围

修复现有前台读取与模式复位之间丢失明确宿主 shell 证据的链路。保留现有终端、路由和复位入口；不修改 Agent 任务状态含义，不新增主机轮询、重连、计时重试或关闭终端。

### REQ-001 明确 shell 观察触发既有模式复位

当前状态：已实现。对应 [TC-001、TC-002、TC-005](../tests/cases/宿主观察与模式恢复.md)；本地和 SSH 隔离实例已验收，用户安装版本尚未更新。

本地场景：前台检查返回明确 shell 结论时，命令结束/恢复可见性的路径调用现有模式复位，不把没有进程名等同没有观察。原有本地字符串接口保持兼容。

SSH/paired 场景：只接受执行主机提供的原 PTY/incarnation、新鲜 observation 和未回退 authority/epoch；显式 shell 观察进入相同的复位回调。检查在执行主机执行，客户端只校验和应用复位，不读取客户端同名 PID。

验收：明确 shell 且名称为 null 的合法观察能复位；原 PTY 身份保留；不新增检查请求。

### REQ-002 活跃和无法确认的会话保留模式

当前状态：已实现。对应 [TC-003、TC-004、TC-005](../tests/cases/宿主观察与模式恢复.md)；活跃 TUI 和无法确认的观察均有回归覆盖。

本地场景：明确 non-shell、尚在启动的命令、失败检查不能触发 shell 复位；旧接口继续使用原有语义。

SSH/paired 场景：失联、旧主机无观察、名称 null 但无明确 shell 证据、过期观察、旧 authority/epoch、错误 PTY/incarnation 和替换中的绑定不能触发复位。所有请求仍跟随共享连接层接触状态。

验收：活跃 TUI 的鼠标模式保持，越界或迟到观察不修改当前会话。

## 未决问题与边界

原退出当时是命令标记缺失还是证明时序失效尚无完整日志。本轮修复有独立失败回归的确定链路，不把一次恢复作为防复发完成。旧主机不提供明确前台观察时保留保守行为，不能用空名称授权复位。
