# 总管执行主机与启动等待

关联 REQ-033、D-027、[Issue #135](https://github.com/Fartown/orca/issues/135)。

此前总管固定本机浮动工作区，全部提案、收件箱、注册与唤醒 RPC 固定 SELF。新流程选择总管来源；本机旧浮动会话兼容保留，远端复用来源普通文件夹工作区、已有主机发布终端及目录归属机制。

| 对象                                         | 所有者                                                                |
| -------------------------------------------- | --------------------------------------------------------------------- |
| 来源选择、客户端镜像 tab/pane                | 当前桌面窗口；来源偏好保存在本机任务库                                |
| 总管目录                                     | 选择的 Orca profile 的任务 DB 父目录下 dispatcher；来源主机创建及验证 |
| 总管进程、CLI、认证环境、原始 pane、会话注册 | 所选来源；不复制账号或进程到客户端                                    |
| 总管提案、收件箱、watch、唤醒偏好和游标      | 总管来源任务库                                                        |
| 任务及工作区                                 | 原任务库和原执行主机；不因切换总管而搬迁                              |
| RPC 端口、连接与恢复                         | 既有共享连接层；产品不新建端口服务、探测或重试循环                    |
| 验证 SSH 密钥、HOME、sshd、端口              | 隔离夹具，完成后按所有权标记清理                                      |

prepareWorkspace 使用来源既有 ProjectGroup/FolderWorkspace API，能力为 local-tasks.dispatcher-host.v1。register 在原事务内保存 dispatcher.session.v1 与旧 pane preference，不升数据库版本；source pane 保持 raw，客户端只在展示和输入前转换 mirror ID。

来源绑定的客户端处理提案与收件箱。提案、conversation、任务和会话 ID 在边界转换；proposal 的写回根据其来源 ID 路由，不随当前选择漂移。外库 watch 使用稳定来源 installationId 的 opaque runtime namespace，不能将它当可连接主机。未知来源拒绝动作，不落到本机。

显式显示远端总管时，若本机浮层当前显示的是原总管，则仅最小化该浮层以露出目标；原 tab、PTY、进程和其他浮动会话保留。

切换来源增加 epoch，列表清理并拒绝旧响应；进行中的已确认执行仍回原提案来源记录。跨库动态跟随已有共享变化通知，所选来源在零项目时也保持订阅需求；失联取消读取与发送，返联后由共享层通知触发刷新。

总管在 prehook waiting/blocked 且没有 providerSession 或结构化 interactivePrompt 时，显示同一 pane 的终端，使目录信任、登录或启动菜单可处理；ready 会话继续默认 Chat，用户手动视图偏好保留。Orca 不替用户回答信任菜单。

验证覆盖本机旧浮动会话、配对来源、真实 SSH 普通 folder 来源、同 ID 隔离、切换期间延迟响应、断联零私有请求与恢复、旧版能力拒绝。手机不新增总管主机选择界面，prepareWorkspace 保持桌面专用权限。
