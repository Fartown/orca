## 三、硬性不变量（违反任一条即 FAIL）

- 开库必须设 `journal_mode=WAL`、`synchronous=NORMAL`、`busy_timeout`，**以及每连接的
  `foreign_keys=ON`**，并读回校验。
- 迁移必须事务性，**只在成功时** bump `user_version`；中途失败后旧数据可读。
- Issue / Conversation 的 `executionHostId` 创建后不可变；`runtime:*` 不能写入；
  `hostPartitionKey` 不漂移；跨主机 parent / binding 被拒。
- 已读（`readAt`）与处理状态（`resolvedAt`）是两个独立字段，mark-read **绝不**写 `resolvedAt`。
- hook preview 的 completeness 必须是 `runtime-preview`，运行态预览不得冒充全文。
- 同 `mutationId` 重试不产生第二次副作用；同 launch token 的后续 session 不复用已消费/退休 claim。
- prepareLaunch / Resume / Retry 的 receipt、DB、日志、响应均不含明文 token，只存 fingerprint。
- 普通 Workspace 启动在没有可信 hook 时**不创建** Conversation。
- v1 schema 不得包含 execution-chain / supersession、digest / FTS / events / body-read 表或字段。
- profile A / B 互不可见。

## 五、§12.3 不得发布的半态（命中任一条即 FAIL）

1. Issues 已显示持久 Conversation，但 Workspaces 仍只显示 pane/status 临时行；
2. `issueId` 穿透 terminal 参数链，或 `OrcaRuntimeService` 持有 repository/allocator；
3. Activity / Dashboard / 通知 / 移动端仍注册实验 Issue 服务，却没有统一 read/resolve；
4. hook preview 可能被标为全文，或 ack 会写 `resolvedAt`；
5. Project move 可在 Conversation 已纳管时继续，产生跨 profile 半迁移；
6. PTY、main-window service 或 hook server 被改造成 Issue 领域接缝，或普通启动在无可信 hook 时伪造 Conversation；
7. filter-scoped Issue response 覆盖/删除 canonical Conversation entity，或分页混合不同 revision；
8. v1 保留无法从真实 provider evidence 生成的 supersession 字段/状态；
9. capability 被当作运行健康，DB/hook 失败只能表现成 generic RPC error；
10. 失败预分配无法同 ID retry/forget，导致幽灵记录和不可解除的 Project move guard。

## 六、真实 App 功能测试（§12.2，缺证据即 FAIL）

单测和 dev renderer **不能**替代发布验收。必须有真实 Electron App 上跑通的旅程证据：

- `tests/e2e/` 下必须存在文件名含 `issues-journey` 的 Playwright spec，覆盖 §12.2 的 16 步旅程；
  spec 必须真的驱动 App 并断言 DOM / 状态，不是空壳或 `test.skip`。
- `.docs/并行任务看板/goal/真实App验收报告.md` 必须存在，且逐步给出：
  预期、实际、截图路径、CDP/DOM 证据、失败归因、构建产物路径。
- 报告里引用的截图文件必须**真实存在于磁盘**，请逐个核对路径。引用了不存在的截图 = 伪造证据 = FAIL。
- 报告必须覆盖：三级 hierarchy 与第四级/自环/跨主机被阻止、launcher 失败后 retry 复用同一
  `conversationId`、attached 时 forget 被拒、pane 关闭后 Conversation 仍在且 detached、
  原 Workspace Resume 复用而跨 Workspace Continue 新建、重启 App 后持久、切换 profile 互不可见、
  runtime unsupported / hook degraded / DB unavailable / route offline 四种状态可区分、
  Project copy 不复制而 move 被阻断且 forget 后可解除。
