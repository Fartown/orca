# 移动端续接会话 Test Cases

> 本文档是可重复执行的测试规格，不记录某一次测试的实际结果、环境、版本、PASS/FAIL、截图或缺陷。

## 1. 范围与关联需求

- 功能范围：移动端从当前 claude / codex 终端会话新建续接会话的入口、上下文模式选择、prompt 生成与投递编排。
- 关联需求：REQ-001、REQ-002、REQ-003、REQ-004、REQ-005、REQ-006。
- 不在本文件覆盖的范围：桌面端「在新会话中继续」自身的交互（上游能力，回归见 TC-007）；`stdin-after-start` 类 agent；结构化会话通道。

## 3. Test Cases

## TC-001 agent 终端长按出现「Continue in New Session…」

- 关联需求：REQ-001、REQ-006
- 功能模块：终端 tab 长按菜单
- 优先级：P0
- 测试类型：功能
- 前置条件：移动端已连接主机；工作区内存在一个 claude 或 codex 终端 tab，且其 `agentStatus.providerSession.transcriptPath` 非空。
- 测试数据：源 tab 标题 `claude · add auth middleware`。

### 操作步骤

1. 进入该工作区的会话页。
2. 长按该 agent 终端 tab。

### 预期结果

1. 弹出长按菜单，其中包含「Continue in New Session…」一项。
2. 该项位于「Switch to chat view」之下、「Switch to Desktop」之上。
3. 菜单标题为该 tab 的标题。

## TC-002 非 agent 终端长按不出现该入口

- 关联需求：REQ-001、REQ-006
- 功能模块：终端 tab 长按菜单
- 优先级：P0
- 测试类型：边界
- 前置条件：工作区内存在一个普通 shell 终端 tab（无 `launchAgent`、无 transcript）。
- 测试数据：源 tab 标题 `zsh`。

### 操作步骤

1. 长按该普通终端 tab。

### 预期结果

1. 菜单中不包含「Continue in New Session…」。
2. 其余菜单项（Switch to Desktop / Rename / Clear Terminal / Close 等）不受影响。

## TC-003 选择面板展示来源与两个目标 agent

- 关联需求：REQ-001、REQ-006
- 功能模块：续接选择面板
- 优先级：P0
- 测试类型：功能
- 前置条件：同 TC-001。
- 测试数据：源 agent 为 claude。

### 操作步骤

1. 长按 agent 终端 tab，点击「Continue in New Session…」。

### 预期结果

1. 面板标题为源 tab 标题，副标题为 `Original agent: Claude`。
2. 面板包含上下文模式切换行、`Continue with Codex`、`Continue with Claude` 三项，且仅这两个目标 agent。
3. 两个目标项的说明文案为「Starts a new session in this workspace」。

## TC-004 上下文模式双向切换且默认为 focused

- 关联需求：REQ-001
- 功能模块：续接选择面板
- 优先级：P0
- 测试类型：功能
- 前置条件：同 TC-003，面板已打开。
- 测试数据：无。

### 操作步骤

1. 记录切换行当前文案。
2. 点击切换行。
3. 再次点击切换行。
4. 关闭面板后重新打开。

### 预期结果

1. 初始状态为 focused handoff，切换行提示可切到完整记录。
2. 第 2 步后状态变为完整记录，切换行文案改为可切回 focused，并说明会读取完整会话记录、更慢且更耗额度。
3. 第 3 步后回到 focused 状态与文案。
4. 第 4 步后状态回到默认 focused，不保留上次选择。

## TC-005 投递 prompt 并自动切换到新会话

- 关联需求：REQ-001、REQ-002
- 功能模块：续接投递编排
- 优先级：P0
- 测试类型：功能
- 前置条件：同 TC-003；主机可接受 `session.tabs.createTerminal`、`terminal.wait`、`terminal.send`。
- 测试数据：分别在 focused 与完整记录两种模式下各执行一次。

### 操作步骤

1. 打开面板，选定上下文模式。
2. 点击其中一个目标 agent。
3. 在主机侧记录收到的 RPC 方法、入参与 `terminal.send` 的文本全文。

### 预期结果

1. 依次收到 `session.tabs.createTerminal`、`terminal.wait`、`terminal.send`，不出现其他 RPC 方法。
2. `createTerminal` 带 `agent`（所选目标）、`cwd`（源 tab 的 `startupCwd`）、`afterTabId`（源 surface tab）、`clientMutationId`。
3. `terminal.wait` 的条件为 `for: 'tui-idle'`。
4. `terminal.send` 使用括号粘贴且 `enter: true`。
5. 收到的 prompt 正文与共享内核 `buildAgentSessionContinuationPrompt(source, mode)` 的输出逐字一致。
6. 投递成功后客户端订阅新终端并将其置为前台。

## TC-006 失败态提示与幂等键复用

- 关联需求：REQ-005
- 功能模块：续接投递编排
- 优先级：P1
- 测试类型：异常
- 前置条件：可控主机，能分别令 `createTerminal` 报错、不返回终端句柄、`terminal.wait` 超时、`terminal.send` 拒绝。
- 测试数据：同一个源 tab 连续触发两次。

### 操作步骤

1. 令 `createTerminal` 返回错误后触发一次续接。
2. 令 `createTerminal` 成功但不带终端句柄后触发一次。
3. 令 `terminal.wait` 超时后触发一次。
4. 令 `terminal.send` 拒绝后触发一次。
5. 在第 1 步失败后于同一源 tab 再次触发续接，比较两次 `clientMutationId`。

### 预期结果

1. 四种情况内部分别判定为 create-failed / created-without-handle / not-ready / send-rejected，并映射到两条用户文案：会话没建起来时提示「Could not start a new <Agent> session.」，会话已建但 prompt 未送达时提示「The new <Agent> session started, but its context could not be sent.」。两条文案的区分点是「会话是否存在」，用户据此判断要不要去新会话里手动补 prompt。
2. 未投递成功时不将失败会话当成成功结果展示，且失败分支不会继续调用其后的 RPC（create 失败不发 wait，wait 未就绪不发 send）。
3. 第 5 步两次请求携带同一个 `clientMutationId`，不产生第二个兄弟会话；仅在投递成功后释放该键。

## TC-007 桌面端「在新会话中继续」行为不变

- 关联需求：REQ-003
- 功能模块：桌面端 continuation
- 优先级：P0
- 测试类型：回归
- 前置条件：桌面端 Orca 运行中，存在一个 claude 或 codex 会话。
- 测试数据：与改动前同一会话。

### 操作步骤

1. 在桌面端触发「在新会话中继续」。
2. 切换两种上下文模式各生成一次。

### 预期结果

1. 入口位置、对话框结构与选项与改动前一致。
2. 两种模式生成的 prompt 与改动前逐字一致。
3. 不出现新增的移动端专有措辞或选项。

## TC-008 旧主机上不因新字段失败

- 关联需求：REQ-004
- 功能模块：续接投递编排
- 优先级：P0
- 测试类型：兼容性
- 前置条件：一台不认识 `cwd` 字段的旧版本主机。
- 测试数据：源 tab 带 `startupCwd`。

### 操作步骤

1. 在旧主机上执行 TC-005 的步骤 1–2。

### 预期结果

1. 不出现「未知 RPC 方法」或参数校验失败。
2. 新会话仍被创建，工作目录退化为主机默认工作目录。
3. prompt 正文不受影响。

## TC-009 新会话终端首屏实时渲染

- 关联需求：REQ-001
- 功能模块：续接投递编排 / 移动端终端视图
- 优先级：P1
- 测试类型：功能
- 前置条件：真实主机（非 mock），源会话为真实 claude 或 codex 进程——agent 启动时会发出 DECRQM（`CSI ? Ps $ p`）等模式查询，mock 终端不会。App 为冷启动，避免复用此前已创建的 WebView。
- 测试数据：无。

### 操作步骤

1. 从长按菜单触发续接，选择任一目标 agent。
2. 投递成功、自动切到新 tab 后，**不做任何 tab 切换**，持续观察该终端约 30 秒。
3. 检查客户端日志中的终端 WebView 引擎错误与流事件丢弃记录。

### 预期结果

1. 新 tab 的终端持续渲染新 agent 的输出，直至其给出回复；不会停在 shell 提示符或启动命令那一行。
2. 无需切换 tab 或重启 App 即可看到完整输出。
3. 客户端日志中 `[terminal-webview] engine error` 出现 0 次。
4. 客户端日志中 `scrollback DROPPED` / `data DROPPED` 出现 0 次。
