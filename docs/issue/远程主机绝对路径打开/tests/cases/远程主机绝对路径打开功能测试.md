# 远程主机绝对路径打开功能测试

## 2. 用例

单元用例实现位置：`src/main/remote-host-path-grant/host-path-grant-policy.test.ts`、`src/renderer/src/runtime-host-path/host-path-file-client.test.ts`、`src/renderer/src/components/tab-bar/tab-create-entry-action.test.ts`。

### TC-801 真机：配对客户端打开 worktree 外的主机路径

- 关联需求：REQ-801、REQ-803；优先级：P0；类型：端到端（真机 UI）；模块：全链路。
- 前置条件：真实 `orca serve` runtime 主机 + 真实第二个 Electron 桌面客户端配对；在主机临时目录（不属于任何 worktree）放一个带唯一标记的文本文件。
- 步骤：客户端「+」弹窗输入该绝对路径 → 回车 → Monaco 查找该标记。
- 预期：弹窗给出可点的 `Open file` 行且不出现「只能打开工作区内的文件」；编辑器打开且无 `File not found`；查找命中标记；标签页持有 grant。
- 反向对照：移除主机的 `files.grantHostPath` 后重新构建，同一条用例必须失败。

### TC-802 放开后保留的路径约束

- 关联需求：REQ-802；优先级：P0；类型：单元；模块：主机策略。
- 步骤：对绝对路径、相对路径、`~/`、空串、控制字符、非字符串分别调用 `hostGrantPathCandidate`。
- 预期：任意绝对路径（含 /etc、任意工作区外路径、Windows 盘符）通过；其余返回 null。

### TC-803 发放成功

- 关联需求：REQ-801；优先级：P0；类型：单元；模块：客户端。
- 预期：`requestHostPathGrant` 以 `files.grantHostPath` 请求并返回主机给的 `grantId` 与 `absolutePath`。

### TC-804 主机说没有

- 关联需求：REQ-801；优先级：P0；类型：单元；模块：客户端。
- 前置条件：主机返回 `exists: false`。
- 预期：抛出 `File not found on the host: <path>`，不返回不可用的 grant。

### TC-805 按 grant 读

- 关联需求：REQ-803；优先级：P0；类型：单元；模块：客户端。
- 预期：调用 `files.readTerminalArtifact` 且带 `grantId` 与 `absolutePath`。

### TC-806 按 grant 写

- 关联需求：REQ-804；优先级：P0；类型：单元；模块：客户端。
- 预期：调用 `files.writeTerminalArtifact` 且带 `grantId`、`absolutePath` 与内容。

### TC-807 识别可换发的失败

- 关联需求：REQ-805；优先级：P0；类型：单元；模块：客户端。
- 预期：`terminal_file_grant_expired`、`terminal_file_grant_mismatch` 判为可换发；`EACCES`、`socket died` 判为不可换发。

### TC-808 换发一次并回传新 grant

- 关联需求：REQ-805；优先级：P0；类型：单元；模块：客户端。
- 预期：第一次失败后换发并重试成功；返回值里的 grant 是新的那张（调用方要存回标签页）。

### TC-809 只换一次

- 关联需求：REQ-805；优先级：P0；类型：单元；模块：客户端。
- 预期：连续过期时抛出原错误，换发只发生一次。

### TC-811 授权路径返回截断内容时拒绝

- 关联需求：REQ-806；优先级：P0；类型：单元；模块：客户端。
- 前置条件：`files.readTerminalArtifact` 返回 `{ content: 'prefix', truncated: true, byteLength: 524288 }`。
- 步骤：调用 `readHostPathFile`。
- 预期：抛出 `Host file is too large to open in the editor (524288 bytes)`，不返回任何内容。
- 为什么必须有这条：授权路径没有 `files.readChunk` 的分块形式可补读，把前缀交给编辑器会让下一次保存抹掉主机文件的后半截。

### TC-810 弹窗对 worktree 外路径申请 grant

- 关联需求：REQ-801、REQ-803；优先级：P0；类型：单元；模块：弹窗执行链。
- 预期：调用 `requestHostPathGrant`；不调用 `statRuntimePath`；不调用本机 `authorizeExternalPath`；`openFile` 收到 `runtimeHostPathGrant`。主机拒绝时错误原样透出且不开 tab。

### TC-811 授权路径返回截断时拒绝

- 关联需求：REQ-806；优先级：P0；类型：单元；模块：客户端。
- 前置条件：主机 `files.readTerminalArtifact` 返回 `{ content: 'prefix', truncated: true, byteLength: 524288 }`。
- 步骤：调用 `readHostPathFile`。
- 预期：抛出 `Host file is too large to open in the editor (524288 bytes)`，**不返回任何内容**。
- 为什么必须有这条：授权路径没有 `files.readChunk` 那种分块补读形式，把前缀当成可编辑内容交出去，下一次保存就会抹掉主机文件的后半截。
