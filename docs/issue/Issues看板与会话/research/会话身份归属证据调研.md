# 会话身份归属证据调研（G0）

## 1. 结论先行

顶替**已在本机当场复现**（§3）：一个独立 `claude` 进程即可夺走 pane 的会话身份。这是标题漂移的根因，不是推断。

判据方面，两个候选**均被实验证伪或降级**：

- **`agent_id` 无效**：它只标记 Task 子代理，而子代理与父会话共用 `session_id`，本来就不顶替。真正的顶替源不带该字段（§4.1）。
- **`SessionStart.source` 不足**：内部调用与正规新开会话**同为 `startup`**（§5 对照实验）。

**现有可用信息是 pane 上下文**：顶替只发生在「该 pane 已有一个不同的活跃会话」时，而 `agent-hook-listener.ts:64` 已持有该信息。但「活跃」如何判定尚未闭合——`orca terminal close --tab` 未发出 `SessionEnd`，不能依赖它清除旧身份（§5）。

**结论：不具备立即实施的判据，G0 未闭合。** 需先解决"活跃"判定，或向 provider 侧争取显式标记。

## 2. 方法

在 `~/.claude/settings.json` 追加一条只读旁路 hook，把 Claude 交给 hook 的原始 stdin 抄一份落盘；不改 Orca、不改仓库、不重启 App，不向 stdout 输出（避免被当作注入上下文）。

覆盖事件：`SessionStart`、`SubagentStart`、`SubagentStop`、`UserPromptSubmit`、`Stop`、`PostCompact`、`SessionEnd`。

场景由本人用 `claude` CLI 直接构造，未要求用户操作：

| 场景 | 构造方式 |
| --- | --- |
| Task 子代理 | 在当前会话内启动一个 Explore 子代理 |
| 独立新会话 | `claude -p "…" --max-turns 1` |
| 恢复已有会话 | `claude --resume <id> -p "…"` |
| 压缩换 id | 运行期自然发生，被动捕获 |

采集 41 条，脱敏后存于 `.docs/会话身份归属-G0/2026-09-08/hook-events-redacted.jsonl`（prompt 正文、助手消息、工具入参已置换为 `<redacted>`；该目录被 git 忽略）。抓包 hook、脚本与原始记录已删除，`settings.json` 已核对还原。

## 3. 复现：一个 headless 进程顶替了 pane 身份

在 headless 会话启动的同时高频采样 `agent-hooks/last-status.json` 中本 pane（`0f3a87de…`）的身份：

```
1788873394485  d182cba2  PostToolUse    ← 用户真实会话
1788873397504  63faa6f6  SessionStart   ← headless 起来，身份立即被顶替
```

**一个独立 `claude` 进程即可夺走 pane 的会话身份。** 该进程继承了 pane 的 `ORCA_PANE_KEY`、`ORCA_TAB_ID`、`ORCA_AGENT_LAUNCH_TOKEN`，hook 照常上报。

现有 launch token 机制（`agent-status-live-reducer.ts:68-74`「Launch tokens authorize only the session they started」）**未能拦截**：它在 renderer store 层消费 token，而身份顶替发生在更早的 `agent-hook-listener` 归一化阶段。

## 4. 字段实测

### 4.1 `agent_id` 的真实覆盖面

| 事件 | `session_id` | `agent_id` | `agent_type` |
| --- | --- | --- | --- |
| SubagentStart | `d182cba2`（**与父相同**） | `ab0d8bc98e43ba080` | `Explore` |
| SubagentStop | `d182cba2`（**与父相同**） | `ab0d8bc98e43ba080` | `Explore` |
| UserPromptSubmit（主线） | `d182cba2` | 无 | 无 |
| 独立会话全部事件 | 全新 id | **无** | 无 |

与[官方文档](https://code.claude.com/docs/en/hooks)一致：`agent_id` "Present only when the hook fires inside a subagent call"。

**推论**：照搬 `agent-hook-listener.ts:42` 的 Codex 写法给 Claude 加分支**无效**——顶替源不带该字段。（此前一版方案曾如此设想，据本节撤回。）

### 4.2 `SessionStart.source` 完全区分三类

| 场景 | `session_id` | `source` |
| --- | --- | --- |
| 独立会话启动（顶替源） | 全新 | **`startup`** |
| `--resume` 恢复 | 已存在 | **`resume`** |
| Orca 恢复用户会话（`d182cba2`） | 已存在 | **`resume`** |
| Claude 压缩换 id（`e164dcf1`） | 换新 id | **`compact`** |

三类取值无重叠。文档另列 `clear`、`fork` 两值，本轮未捕获到样本。

`SessionStart` 的完整字段：`session_id`、`transcript_path`、`cwd`、`hook_event_name`、`source`。

### 4.3 Orca 丢弃了 `source`

`src/shared/agent-hook-listener.ts` 的 Claude 分支只读取 `prompt_id`（:46）与 compact 的 `trigger`（:49-54）。原始 payload 通过 `raw-json-v1` 完整送达主进程（`~/.orca/agent-hooks/claude-hook.sh` 以 `--data-binary @-` POST），**`source` 到了但没人读**。

## 5. 对照实验：`source` 不足以判定

用 `orca terminal create --worktree active --command "claude"` 开一个**正规的新 Claude 会话**（Orca 自己发起，等价于用户新开 tab）作对照：

| 场景 | `source` | paneKey | 该 pane 原有会话 |
| --- | --- | --- | --- |
| 内部调用（headless） | `startup` | `0f3a87de:c8b9d6a2`（**已存在**） | `d182cba2`，**活跃** |
| **正规新开（对照组）** | **`startup`** | `c1fc148d…`（**全新 tab**） | **无** |

**两者 `source` 相同。** 仅凭 `source` 无法区分——此前设想的主判据被本实验证伪。

### 真正的区别是 pane 上下文

顶替只在**该 pane 已有一个不同的活跃会话**时才发生；正规新开总是落在没有既有会话的新 pane 上。

`agent-hook-listener.ts:64` 已持有 `previousStatus = state.lastStatusByPaneKey.get(paneKey)`，即该 pane 上一条状态（含 providerSession），**判定所需信息在归一化阶段就已具备**，无需引入 launch token。

**候选判据**：`SessionStart` && `source === 'startup'` && 该 pane 已有**不同且活跃**的会话 → 不顶替身份。

### 该判据的未决问题

`orca terminal close --tab` 关闭会话时**未观察到 `SessionEnd`**（返回 `ptyKilled: false`，进程被运行时直接收走）。因此不能依赖 `SessionEnd` 来清除 pane 的既有身份。

后果：用户在**同一个 pane** 内先后跑两次 `claude`（前一次已退出）时，若旧身份未被清除，新会话会被误判为内部调用而拒绝顶替——这比现状更糟。

「活跃」的判定方式（进程存活、事件时效、PTY 实例代次等）**尚未确定，也未实测**，是实施前必须闭合的一项。

## 6. 未覆盖项

- `source` 为 `clear` / `fork` 的样本未捕获，行为未验证
- launch token 在 hook 归一化阶段是否可得、时序是否成立，未实测
- Codex 侧未做同等对照（其 `agent_id` 分支已在用，但是否也存在独立会话顶替未验）
- 本轮全部样本来自 local host；SSH / paired runtime 未覆盖
- 实测由本人构造的 headless 进程复现，与 Claude 自发的内部调用（如 `0d257c8f`）形态是否完全一致，未取得后者的原始 payload

## 7. 对既有结论的修正

- 撤回「照 Codex 那行给 Claude 加 `agent_id` 分支即可」——§4.1 证伪
- 撤回本人此前「89 条无快照会话中 88 条为 Orca 内部调用」——该结论由 prompt 文本分类得出，非身份证据，不作为依据
- 已提交的 `6ee315dc8`、`cabf7f675` 是异步竞态的局部改善（各带单测），**不是根因修复**；根因为本文所述身份顶替
