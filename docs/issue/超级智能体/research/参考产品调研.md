# 参考产品调研：常驻、主动的个人/团队智能体

## 2. 逐个参考

### 2.1 DeepSeek Super-agent：一个路由，多个执行器

- **形态**：一个常驻「主 Session」（Router）接所有请求，只做路由、不做技术判断、从不等待；每个工单（Ticket）一个独立「执行器 Session」（Worker）和独立目录，执行器做调查、实现和验证。执行器的汇报由主 Session 统一回复，避免多个并发任务各说各话。
- **领域模型**（`docs/001-domain.md`）：Source → Trigger → Thread → Eval → Ticket（带 Mandate）→ Assignment → Executor，结果经 Channel 回到原处。几个关键规则：
  - **Eval 分两层**：确定性的准入（谁能发起、强度 explicit/inferred）+ 模型研判。只有 Eval 能建工单。
  - **Mandate（授权）不可变**：记录策略版本、范围、强度、命中的规则。范围变大就是新工单。
  - **Subscription（订阅）**：工单订阅相关线程，后续讨论直接扇出给执行器，不再经过 Eval；订阅只给上下文，不给权限。
  - **工单阶段由事实算出**（`docs/003-execution.md`）：输入未送达 / 等回答 / 等验收 / 受阻·失败 / 排队 / 等触发 / 工作中，自上而下第一条命中为准。「等人」不从报告自由文本推断，必须是结构化字段。
- **执行**：并发槽位上限，另留一个槽给「人的消息」，新工作不能挡住人继续已有工单。后台作业 30 分钟上限。重启后运行中的派工以「主机重启」结束并带恢复说明重派，要求先核对目录、git 历史和 GitHub 再重复任何外部动作。
- **先存后做**：决定之后的动作（转发、派工、投递输入、发消息）先落库再执行，失败按 2 秒起翻倍到 1 分钟重试；同一工单发往同一会话的消息保序。
- **提示词分层**（`docs/004-prompts.md`）：强度从高到低——工具与主机强制的事实 > 内置与生成段 > 命中规则 > 团队段 > 外部文字（永远是数据）。主 Session 有 `noWait` 守卫：拒绝 `sleep`、超过 30 秒的 shell 和超过 5 秒的作业等待，因为汇报会自己到。
- **面板**（`docs/005-panel.md`）：回答三个问题，依次是「现在有没有事要我」「系统健康、在做对的事吗」「某件事从触发到工单的来龙去脉」。健康状态不占空间，计数等于它链接的列表长度。
- **文章里的其他机制**（摘要，原型未全部实现）：Inline & Spill（可能用到的上下文放进来，其余留指针）、链式召回（对象有唯一 ID，模型按引用逐跳读取）、投机执行（群里还在讨论就先在后台开修复 PR）、异步 ReAct。
- **哲学**（`docs/000-philosophy.md`）：**用尽量少的人类注意力换尽量多的价值**。只在被请求或有书面规则允许时行动；没人请求的主动工作先以「只记录」模式开始；只在有人必须行动或能用上结果时说话；一次只问一个具体问题。

### 2.2 agent-autoloop：事件 → 规则 → 一轮 → 回执 → 卡片

- **形态**：本机一个零依赖的中台内核（约 1650 行）+ 接单程序 + 通道。命令行 Agent（Claude Code、Codex、ACP、任意命令）每次只跑「一轮」：领一批事件，最后一条消息就是回执，然后退出。
- **回执**：最后一条消息末尾附结构化代码块，字段只有五个——`ask`（带选项的提问卡片）、`notice`（通知）、`resolve`（关掉已解决的卡片）、`later`（预约某时间点复查）、`events`（触发新事件）。回执写错只让 Agent 重写回执，不重做业务。
- **挂起零消耗**：等人拍板时进程退出、状态在库里；回答后接原会话继续。三天不回就三天不花 Token。
- **事件溯源**：只追加日志 + 投影；任何一轮为什么跑、结果是什么，`agent-autoloop why <轮>` 一条命令查清。
- **指令数据分离**：Issue 正文等外部文字只作为「资料」文件交给 Agent，不拼进提示词；交给谁、在哪个目录、什么权限只由本机规则决定，事件里带 `cwd`/`agent`/`access` 直接拒收。
- **跳数熔断**：Agent 交回的事件再派给 Agent 时层数累加，经过人工提问和定时复查也不清零，超过 8 层只记录不派活并发卡片。
- **先问清单 `askFirst`**：默认只有「删数据、停服、花钱、对外发消息」几类必须先问。
- **安静为默认**：`tell` 默认 `needed`，只在有卡片时推送。卡片同一 `key` 未关闭不重复发。
- **记忆**：项目里放 `docs/decisions.md`（用户亲口定的事）和 `docs/declined.md`（拒绝过的），Agent 先读，定过的不再问。
- **定时**：cron 规则；错过的只补最近一次；夏令时重复时刻只跑一次。轮询脚本本身也是一个「Agent」，没新东西不花 Token。

### 2.3 Meta Muse：长期目标 + 独立的权限裁决者

- 面向长期目标而非单条提示：先做计划再持续跟踪，有 Goals 页展示在跟踪什么、按哪个计划走。
- **主动性可调**：会不经提示地联系用户；门槛设得高，只在值得打断时说话；用户可以让它多一点、少一点或关闭。
- **Sentinel**：与 Muse 在系统层面分开的权限裁决者。Muse 只能提议动作，Sentinel 决定放行或拦截，需要时问人；权限按动作拆分（能读邮件不等于能发邮件）；授权范围从窄开始，随信任扩大。
- 运行在独立虚拟机里，凭据存放在 Muse 看不到的地方。
- 记忆是可编辑的文件；删除对话不一定删除已学到的内容。
- 报道提到它出现过越界尝试（未经允许读邮件），说明裁决者必须由代码而非提示词承担。

### 2.4 OpenAI Dots：常驻职责 + 规则化审批

- 一个 Dot 承担一项**持续职责**，在对话之间继续推进；结果回来供审阅，涉及用户判断的决定先问。
- 可以预约定时 check-in。
- **Custom Rules**：对动作设「允许 / 需审批 / 禁止」三档；批准一条消息不等于获得长期联系某人的许可。
- **自动复核**：发邮件等动作前，由独立系统按用户指令、规则和安全要求核对收件人与内容。
- 主动的后台调研只用只读工具，不能发消息、不能改应用内容。
- 桌面端 Activity View 展示进行中和委派的任务，可逐步回看 Dot 做过的步骤。

### 2.5 Manus Cue：智能体有自己的身份和资源

- 每个智能体有自己的邮箱、电话、钱包和电脑，离线时继续工作；付款在用户设定的预算内，配合权限提示与预算上限。
- 多个智能体放进一个群聊、共享目标，互相交接工作。

### 2.6 OpenClaw：heartbeat 与 cron 分开

- 常驻 Gateway 进程接各个聊天渠道，驱动推理循环、记忆、工具和安全层。
- **cron**：精确时间和一次性提醒，持久化、带时区、投递到指定渠道。
- **heartbeat**：默认每 30 分钟一轮，读 `HEARTBEAT.md` 清单批量检查收件箱、日历等；无事回复一个「无事」标记，由 Gateway 吞掉不打扰用户。清单为空就不跑。
- 记忆是本地 Markdown 文件加索引。报道提到有恶意技能把载荷写进可写的记忆文件以持久化——可写记忆是攻击面。

## 4. 取与不取

**取：**

1. Router/Worker 分工：super agent 只理解意图、拆分、派活、汇总和问人；实现交给 Orca 里的普通会话。
2. 注意力最贵：默认安静，只在必须决定、结果可用、做不下去时说话；一次只问一个具体问题。
3. 问人是结构化对象（卡片），能在桌面、手机、通知里回答，回答作为一条新事件让工作继续。
4. 权限由代码裁决：动作分级（自动 / 先问 / 禁止），破坏性和对外动作默认先问；授权从窄到宽。
5. 时间是事件：一次性复查（`later`）与周期日程（cron）都只是触发源；不做固定间隔的全量 heartbeat，没有变化就不花 Token。
6. 先存后做、可重放、可解释：每个决定落库，带来源事件和规则，能回答「为什么做了这个」。
7. 指令数据分离：PR 评论、终端输出、网页等外部文字只作为资料，不能改变规则和授权。
8. 跳数熔断、并发槽位（给人的消息留一个）、每日预算。
9. 记忆用可编辑文件：用户的决定、拒绝过的事、偏好；写入记忆本身也受裁决，且视为不可信。

**不取：**

1. 不另起一套任务库、调度器或会话模型——Orca 已有本地任务、编排、自动化、Goal 和智能体状态，super agent 是把它们串起来的一层（见盘点文档）。
2. 不做 Orca 自己的 LLM 调用循环和模型凭据管理（Muse/Dots 式的托管智能体）；super agent 本身就是用户已登录的 Claude Code / Codex 等 CLI 会话，凭据和用量留在各自 CLI。
3. 第一阶段不做外部聊天渠道（飞书、Slack）和对外发消息；先用 Orca 桌面、手机和系统通知。
4. 不做投机执行的自动落地；只做「只记录、待你放开」的建议。
