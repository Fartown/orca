Orca「以任务为主」原型

任务是入口和记录，对话是手段。打开 Orca 先看到任务首页；一句话派活，Orca 建任务、绑工作区、开会话；进展由智能体回写到任务上；完成由你验收。方案见本需求的 interaction/任务为主的工作流产品方案.md（§5～§8）。

1打开 Orca 先看到什么？

任务首页：顶部派活输入框，下面先是「需要你」，再是按状态分组的任务卡，每张卡有一行最新进展。d1 · m1

2一句话怎么变成在工作区里干活的会话？

「@工作区 + 一句话」直接派活，出一张「已派活」卡，10 秒内可以撤销；没有 @ 的交给调度会话，先提案再执行。d3 · d4 · d9

3不进会话，怎么知道做到哪了？

任务卡和详情上的进展卡：来自智能体回写，没有回写时显示它的最后一句话；要细看就用会话速览。d6 · d7 · d8

4完成由谁定？

智能体最多推进到「待验收」，你点「通过」或「打回」；打回的原因会发给会话。d10 · m7

深色主题，颜色、字号、阴影只用 assets/tokens.css 每屏顶部有屏幕切换器，地址里的 # 对应屏幕 id；带后缀的子屏（如 #d2-ask、#d13-shop12）也能直接打开 交互都能点：派活、只问、撤销倒计时、速览抽屉、提案卡、通过与打回、两屏新建、取消任务 桌面右上角「重置本屏」回到初始状态 桌面左侧栏顶部可以切换「工作区｜任务」：d1～d12 默认工作区模式，d13、d14 是任务模式；切换按屏记住 第二轮（BRIEF-2）：标题不再生成；任务模式里仍用速览抽屉看会话 第三轮（BRIEF-3）：看会话是同一个右侧浮层；概览页减信息：右栏取消、空块不显示、系统记录折叠、没有评审注释 第四轮（BRIEF-4 + 改口）：浮层两档宽度（速览 / 加宽）都完整可操作，再加全屏；没有「完成标准」这个东西——概览、新建任务、验收条、设置里都没有，验收看合入位置、改动、智能体的自检结论 第五轮：待验收的任务能看会话——需要你的待验收行有「速览」，验收条的自检来源能打开会话，浮层头部可在任务和子任务的会话间切换，验收中能在速览里追问；速览（窄）不再盖住内容，而是把主区推开，验收时能一边看会话一边点「通过」；首页的视图列收成图标，行里的主机和时间先隐藏；加宽仍盖在内容上 手机原型为方便评审用简体中文，真实 App 是英文 双击文件即可打开，不依赖网络
